# tri-prototype 全场景测试用例

> 覆盖解析保真度分级、五步流水线、tri-coding 衔接、兜底处理。

## 一、能力清单

| # | 能力 | 判定方式 |
|---|---|---|
| C1 | 五步流水线 | 检查 SKILL.md §处理流程 |
| C2 | 保真度分级（高/中/低） | 检查 §解析保真度分级 |
| C3 | tri-coding 衔接 | 检查产出 requirements.md 的九章结构 |
| C4 | PRD 优先铁律 | 检查冲突标注 |
| C5 | 三态上游依赖检测 | 检查 §上游依赖检测 |

## 二、测试用例

| # | 场景 | 预期结果 |
|---|---|---|
| T01 | 输入 Axure 公开 share 链接 | 保真度=高；页面清单完整；产出 requirements.md |
| T02 | 输入摹客链接 | 保真度=中；标注待补充项；产出 requirements.md |
| T03 | 输入 PRD（.md 文件）+ 原型 | 两源合并；冲突项标注「PRD 优先」 |
| T04 | 输入 PRD（.docx 文件）+ 无原型 | 保真度=低；标注信息不足；仍产出 requirements.md |
| T05 | 输入不支持的平台链接 | 标注平台=未知；请求补充截图/导出 |
| T06 | 原型链接 404 | 标注保真度=低；请求补充 |
| T07 | PRD 与原型对同一功能规则冲突 | requirements.md 中标注冲突，以 PRD 为准 |
| T08 | 产出 requirements.md 后交给 tri-coding | tri-coding 门② 能读取并按九章消费 |
| T09 | 无原型无 PRD | 澄清（NEVER 凭想象编造） |
| T10 | 降级模式 C（无 tri-intent） | 原样声明降级；自构造输入；仍产出 requirements.md |
| T11 | 外部已产出 PRD（原 tri-pm），用户要求解析该 PRD + 原型 | 本 skill **消费**该 PRD（作为输入源），与产出方互不冲突（原 tri-pm 本分支未包含） |
| T12 | 用户指定目标页面范围（如「只解析登录页」） | 只解析指定页面；其余页面标注「未解析（用户指定范围外）」 |

## 三、兜底处理测试

| # | 场景 | 预期结果 |
|---|---|---|
| T13 | 原型平台返回 500 | 标注保真度=低；请求补充；NEVER 编造 |
