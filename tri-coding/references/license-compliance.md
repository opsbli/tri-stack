# 代码版权与许可证合规（硬红线 · 完整参考）

> **原则**：tri-coding 生成的代码必须**原创、可合规使用与发布**。版权与许可证问题零容忍——任何疑似侵权或许可证冲突的代码，在解决前不得提交、发布或交付。
> 📌 提交/发布前速查：配套一页式 `代码合规自查小卡片.html`（skill 根目录）。
> 📌 本文件为 `SKILL.md` §代码版权与许可证合规（硬红线）的展开参考，两者冲突时以本文件为准。

## 一、四类风险与预防

| 风险 | 说明 | 预防措施 |
| :--- | :--- | :--- |
| 代码版权/署名 | 复制他人代码却不保留其 LICENSE/署名，或仿写闭源商业代码 | 只写原创代码；复用开源须完整保留其 LICENSE 与版权声明，不剥离头部 |
| 许可证冲突 | 在 GPL 项目引入不兼容许可代码导致"传染"，或反之 | 遵循目标仓库现有许可证；不引入与其不兼容的依赖 |
| 依赖/供应链 | 使用未授权、来源不明或私有付费包 | 仅用可商用、来源可信的依赖，记录版本与来源；不扒私有代码 |
| 标识/披露 | 平台/雇主/开源社区要求披露 AI 生成代码却未标注 | 提交/发布前确认相关方政策，按需标注"AI 生成" |

## 二、生成期：从源头杜绝

- **主体**：描述性实现需求，禁止把训练数据/网络片段当"已知答案"整段照搬。
- **依赖**：只用可商用的公共包，保留其许可证信息；不绕过付费/私有限制。
- **许可证**：生成代码落盘时，按目标仓库许可证写入 LICENSE 声明或头部注释。

## 三、提交/发布前：合规自检（硬性，不过则不出）

1. 是否复制了他人代码而未保留其许可证/署名？→ 是则补回或改原创。
2. 是否引入了与目标仓库许可证不兼容的依赖？→ 是则替换。
3. 是否使用了未授权/来源不明的依赖或私有包？→ 是则替换。
4. 代码是否与某闭源/商业代码高度雷同（疑似仿写）？→ 是则重写。
5. 是否按项目/平台/雇主要求标注了 AI 生成或 disclosures？→ 按需标注。
6. 生成代码的许可证（如本项目要求）是否已明确声明？→ 未声明则补。

## 四、平台/仓库条款速查（提交与发布前必读，以各平台最新规则为准）

- **代码托管（GitHub/GitLab/工蜂等）**：AI 生成代码通常可提交，但组织/雇主政策可能要求披露；商用以平台与雇主政策为准。
- **开源社区**：发布开源须自带兼容 LICENSE；不得把私有/闭源代码伪装为原创开源。
- ⚠️ 各平台与组织条款会更新，提交、发布与商用前务必查阅最新官方规则；本表仅为方向提示，**不构成法律意见**。

## 五、商用授权与原创存证

- **可商用确认**：接商单/用于公司产品前，确认目标仓库许可证与生成工具授权范围允许相应使用。
- **原创存证（建议）**：保留提示词、生成时间、关键会话记录作为原创证据；开源发布随附 LICENSE。

## 六、侵权应急

- 若收到 DMCA/下架/权属投诉：先撤回争议代码，核对权属；确属误用则凭存证申诉，确属侵权则替换并致歉。
- 全程保留生成日志与依赖来源记录，作为争议时的证据链。

## 七、合规底线（五条全过才可交付）

> **原创不照搬、许可证兼容、依赖已授权、披露到位、LICENSE 已声明**——五条全过，才可提交、发布与交付。

| 底线条目 | 判定 | 未过时的处置 |
|---|---|---|
| 原创不照搬 | 无整段照搬他人代码 | 改写为描述性原创实现 |
| 许可证兼容 | 依赖许可证与目标仓库不冲突 | 替换为兼容依赖 |
| 依赖已授权 | 依赖可商用、来源可信 | 替换为可信公共包 |
| 披露到位 | 按平台/雇主政策标注 AI 生成 | 补充标注 |
| LICENSE 已声明 | 落盘代码带许可证声明或头部注释 | 补写声明 |
