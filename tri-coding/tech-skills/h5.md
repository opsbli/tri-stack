# H5 移动端开发规范

> 本规范作为 tri-coding 技术栈体系的增强层，在 general.md 基底之上叠加 H5 移动端特定规范。

## 技术栈定义

H5 移动端指运行于移动端浏览器/WebView 的 Web 应用，基于 HTML5/CSS3/JavaScript（TypeScript），常配合 React/Vue 等前端框架。核心特性：移动端适配（viewport/rem/vw）、触摸事件交互、性能优化（加载与渲染）、跨浏览器/WebView 兼容性、响应式布局。

## 版本基线

- **HTML5 + CSS3 + ES2020+**：现代 H5 应用基线，支持 Flexbox/Grid 布局、CSS Variables、Optional Chaining、Nullish Coalescing
- **iOS WebView**：基于 WKWebView（iOS 14+），需注意 Safari 兼容性前缀与 Safe Area 适配
- **Android WebView**：基于 Chromium 内核（Android 8+），需处理低端设备性能与 WebView 版本碎片化
- **微信/支付宝 WebView**：需适配 X5/TBS 内核（Android）与 WKWebView（iOS），注意 JS-Bridge 差异

## 编码规范（技术特定）

### 移动端适配

- **viewport 配置**：正确设置 `<meta name="viewport">`，确保移动端视口适配
- **rem/vw 适配**：使用 `rem` 或 `vw/vh` 进行响应式尺寸单位适配，避免固定 `px`
- **响应式布局**：在各平台上实现一致的设计和响应式模式
- **触摸交互**：处理触摸事件（touch/tap），注意点击穿透与 300ms 延迟问题

### 代码风格与目录结构

- **代码风格**：符合官方 [React 代码风格指南](https://react.dev/learn/coding-style)、[Vue 风格指南](https://cn.vuejs.org/style-guide/) 及 [JavaScript/TypeScript 风格指南](https://github.com/airbnb/javascript)
- **目录结构**：遵循前端推荐的目录组织方式（如 components、pages、hooks、services、utils、store 等）
- **变量声明**：使用 `const` 或 `let`，不要使用 `var`

### 路由与异步

- **路由管理**：使用路由管理（如 React Router、Vue Router）进行页面导航
- **异步处理**：使用 async/await 处理异步操作，并进行适当的错误处理

### 错误处理与验证

- **日志输出**：优先使用 `console.info`/`console.warn`/`console.error`，并提供有价值的错误信息
- **提前返回**：对错误条件使用提前返回，实现守卫子句，尽早处理前置条件和无效状态
- **自定义错误类型**：使用自定义错误类型实现一致的错误处理
- **用户输入验证**：实施适当的用户输入验证和安全编码实践

### UI 与性能

- **现代 UI 框架**：使用现代 UI 框架（如 Tailwind CSS、Shadcn UI、Radix UI）进行样式设计
- **性能优化**：遵循性能优化技术，如减少加载时间和提高渲染效率

### 原有代码

- **谨慎修改**：在修复原有代码时，务必先阅读并理解原有代码，尽量不要修改原有代码逻辑

## 质量检查清单（技术特定）

- [ ] 是否正确配置 viewport meta 标签
- [ ] 是否使用 rem/vw 等响应式单位，避免固定 px
- [ ] 是否处理触摸事件交互与点击穿透问题
- [ ] 代码风格是否符合 React/Vue/JS 风格指南
- [ ] 目录结构是否清晰（components/pages/hooks/services/utils/store）
- [ ] 是否使用 `const`/`let` 而非 `var`
- [ ] 是否使用路由管理（React Router/Vue Router）进行导航
- [ ] 日志是否使用 `console.info`/`warn`/`error` 并提供有价值信息
- [ ] 是否使用提前返回/守卫子句处理错误条件
- [ ] 是否实施了用户输入验证
- [ ] 是否考虑了加载时间与渲染效率优化
