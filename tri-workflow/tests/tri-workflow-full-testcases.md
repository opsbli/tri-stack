# tri-workflow 全场景测试用例

> 基于 tri-workflow v1.2.2 全量扫描生成。覆盖 13 章骨架、7 阶段流水线、上游依赖检测三态、质量门禁与落盘规则。

## 零、能力清单

| 组 | 能力 | 关键定义 |
|---|---|---|
| A 触发与路由 | A1 意图识别 | I13 规划拆解（工作流设计）/ I14 操作执行（工作流编排）命中即路由本 skill |
| | A2 下游路由 | tri-intent 快照 `下游路由建议` 指向本 skill 时激活 |
| | A3 独立触发 | 用户直接要求设计工作流/流水线/审批流/自动化流程 |
| B 上游依赖检测 | B1 快照模式 A | 定位到可用快照 → 读取 §三 标准推进 |
| | B2 待识别 A0 | 有 tri-intent 无可用快照 → MUST 提示先意图识别 |
| | B3 降级模式 B | 无上游 → 跳过快照，对话提取需求，环境感知降级 |
| C 输入契约 | C1 模式 A 字段 | 读取快照 §三 六字段（L2/D1/D5/D4/任务要点/交付预期） |
| | C2 模式 B 必填 | 工作流类型/领域/触发/核心节点/交付形态/技术栈 |
| D 7 阶段流水线 | D1 环境感知 | 扫描 Skills/MCP/API/组织约束/技术栈 → env-profile |
| | D2 模板匹配 | 语义匹配 ≥70% 选用，<70% 给 Top3 或自定义 |
| | D3 对话补全 | 逐节点补全 action/role/inputs/sla/condition |
| | D4 编译优化 | 冗余消除/并行度/依赖最小化/节点合并/超时重试注入 |
| | D5 校验验证 | 依赖校验 + 死锁/可达/循环/数据流 + 可选 dry-run |
| | D6 多目标输出 | 按类型选 P0 主产物 + 统一 DSL |
| | D7 迭代反馈 | 反馈收集 / Webhook / 定时报告 / 自动重入 |

| | E2 统一 DSL | workflows/<name>.wf.yml 单一事实来源 |
| F 质量门禁 | F1 九维度 | 环境感知/模板/节点/依赖阻断/死锁/循环/多形态/最小化/渐进 |
| | F2 阻断=0 | 🔴 阻断项不为 0 不得进入阶段 6 |
| G 落盘规则 | G1 链路文档 | .tribro/workflows/<命名>/result.md 等 |
| | G2 产物分离 | 工作流产物落用户目录，非 tri 链路文档 |
| H 边界 | H1 MECE | 只设计不实现，不越界到 tri-coding/tri-fix |
| | H2 最小化 | 不擅自扩展节点或增加未要求交付形态 |

## 一、触发与路由（A 组）

- **A1-正**：快照 `intent.L2_核心意图=I13`，`任务要点` 含「设计一个发布流水线」→ 路由 tri-workflow。✅
- **A1-反**：快照 L2=I11（写代码）→ 不应激活，应路由 tri-coding。✅
- **A2-正**：快照 `下游路由建议=tri-workflow` → 激活并读取 §三。✅
- **A2-反**：下游路由建议=tri-review → 激活 tri-review 而非本 skill。✅
- **A3-正**：用户「帮我把 PR 合并到部署串成一条流水线」→ 独立触发，进入模式 B。✅
- **A-反-N**：未经路由且 L2 越界（I13 实为 I18 闲聊）→ 停止并回退 tri-intent 重新路由。✅

## 二、上游依赖检测三态（B 组）

- **B1-正**：`.tribro/LATEST.md` 指向 5 分钟前快照 → 模式 A，读取 §三 推进。✅
- **B1-反**：快照存在但 `intent.L2_核心意图=I11`（越界）→ 不满足 L2∈{I13,I14}，停止回退。✅
- **B2-正**：有 `tri-intent/` 目录但无可用快照（过期 >30min）→ 模式 A0，提示「本次请求尚未经意图识别」，引导先产出快照，绝不静默执行。✅
- **B2-反**：模式 A0 下直接按空上下文产出工作流 → 违规，MUST 阻断。✅
- **B3-正**：无 tri-intent 安装 → 模式 B，跳过快照，对话提取必填字段，阶段 1 仅扫描本地 Skills/MCP。✅
- **B3-反**：模式 B 声称做了「组织约束提取」→ 实际仅用默认值，标注降级限制。✅

## 三、输入契约（C 组）

- **C1-正**：模式 A 读取快照 §三，提取 D1 任务领域=研发、D4 格式约束=CI 配置。✅
- **C1-反**：模式 A 忽略 `任务要点` 中明确的「需飞书审批节点」→ 覆盖不全。✅
- **C2-正**：模式 B 用户只说「做一个审批流」→ 主动澄清缺失的触发方式/核心节点/技术栈。✅
- **C2-反**：模式 B 未澄清即假设技术栈为 GitHub Actions → 应澄清而非臆测。✅

## 四、阶段 1 环境感知（D1）

- **D1-正**：扫描出 skills[] 含 tri-coding v1.2、mcp_services[] 含 lark-im、tech_stack.ci_cd=GitHub Actions → env-profile 完整。✅
- **D1-反**：Skills 目录为空 → 标注 `skills: []`，阶段 5 依赖校验时提示，不静默。✅
- **D1-降级**：MCP 不可用 → `mcp_services: []`，跳过 MCP 相关节点并标注风险。✅

## 五、阶段 2 模板匹配（D2）

- **D2-正**：需求「代码提交后自动构建测试部署」匹配 `ci-cd-pipeline`（匹配度 92%）→ 直接选用。✅
- **D2-反**：匹配度 55% 未给 Top3 候选直接选用 → 违反匹配策略，应列候选或自定义。✅
- **D2-自定义**：高度定制需求 → 选「自定义」，跳至阶段 3 从零构建节点。✅

## 六、阶段 3 对话补全（D3）

- **D3-正**：初版某 auto 节点 `role` 未映射 → 提问「节点 X 由哪个 Skill 执行？」回填。✅
- **D3-反**：审批节点无 `sla` → 提问预期完成时间，不默认跳过时限。✅
- **D3-策略**：单轮 4 个问题 → 应压缩为 ≤3 个，按阻断>质量>体验排序。✅

## 七、阶段 4 编译优化（D4）

- **D4-正**：两个连续「通知」自动节点 → 冗余消除合并。✅
- **D4-反**：合并了人工节点与自动节点 → 违反约束，优化后不可改变业务语义。✅
- **D4-注入**：auto 节点无超时 → 注入默认 10min；无重试 → 注入默认 3 次。✅

## 八、阶段 5 校验验证（D5 / F 组）

- **D5-正**：某 auto 节点 `role.target=tri-review` 不在 env-profile.skills → 🔴 阻断，停止并给安装命令。✅
- **D5-反**：存在 🔴 阻断项仍进入阶段 6 产出 → 违反硬阻断契约。✅
- **D5-死锁**：无死锁（审批回退环合法）→ 通过。✅
- **F2-正**：阻断计数=0 → 允许进入阶段 6。✅
- **F2-反**：阻断=2 但用户「忽略」→ MUST 停止，不得忽略 🔴。✅

## 九、阶段 6 多目标输出（D6 / E 组）

- **E1-正**：协作流水线 → P0 产出 `.github/workflows/<name>.yml` + 统一 DSL。✅
- **E1-反**：所有工作流只出一种格式 → 违反多形态输出契约。✅
- **E2-正**：所有形态编译为 `workflows/<name>.wf.yml` 单一事实来源。✅
- **E-反-N**：用户未要求却额外产出 DAG 配置 → 违反最小化原则。✅

## 十、阶段 7 迭代反馈（D7）

- **D7-正**：Webhook 回调上报节点成功率 → 触发阶段 4 优化建议。✅
- **D7-反**：SLA 达标率 <80% 连续 7 天自动修改工作流 → 应为「建议模式」，需用户确认。✅

## 十一、落盘规则（G 组）

- **G1-正**：执行结果落盘 `.tribro/workflows/<命名>/result.md`（摘要+产物清单+校验结果）。✅
- **G2-正**：CI 配置落盘用户指定业务目录，非 `.tribro/` 链路目录。✅
- **G-反-N**：把工作流产物写进 `.tribro/workflows/` 与链路文档混淆 → 路径分离违规。✅

## 十二、边界与作答前声明（H 组 / 契约 7）

- **H1-正**：本 skill 产出工作流设计，节点内部业务代码交由 tri-coding。✅
- **H1-反**：本 skill 直接写出节点内部 Python 实现 → 越界。✅
- **H2-正**：仅实现快照 `任务要点` 明确要求范围。✅
- **声明-正**：作答前声明「本次意图=I13，已读取快照=是，模式=快照，当前阶段=3」。✅
- **声明-反**：声明写成「本次执行=tri-workflow，模式=下游」→ 旧格式，应使用标准化四元组。✅
