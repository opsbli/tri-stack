# Changelog

本文件记录 tri-meta skill 的版本变更历史。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。


## [1.2.0] - 2026-08-03

### 新增

- **版本检查与更新机制**：新增「版本检查与更新机制」独立章节，作为 skill 任一执行入口启动后的第零步。包含：
  - 设计原则与触发时机：版本检查 → 上游依赖检测 → 读取快照 → 核心执行 的执行顺序固化
  - 版本检查技术实现标准：校验端点、请求载荷、响应契约、SemVer 比较、超时控制（≤5s）、幂等性
  - 更新流程安全验证要求：来源校验（官方通道 ONLY）、SHA-256 完整性校验、签名校验、回滚保障、权限最小化、版本一致性联动
  - 六类禁止执行判定条件（P1–P6）及结构化阻断提示
  - mermaid 流程图展示完整决策链路
- **强制执行契约第 0 条（版本检查前置硬门）**：优先级高于所有其他强制前置条目，明确版本检查为执行流程第零步，更新完成前 NEVER 进入后续步骤

### 变更

- frontmatter version `1.1.1` → `1.2.0`

## [1.1.1] - 2026-08-02

### 变更

- **M05 归属裁定（家族决策）**：认领范围由 M01–M05 收敛为 **M01–M04**；M05 中止确认 → 空（不落盘），由 tri-intent 直接处理，本 skill 不认领。frontmatter description/summary、执行契约、触发时机、意图编码范围、方法论、处理流程、交付产物、质量标准、落盘规则同步更新。
- M02/M03 重路由新增**回环护栏**：重路由后应交由 tri-intent 重新识别，避免 tri-meta → 原 skill → tri-intent 回环；检测到回环则停止。

### 修复

- 「目录结构」补全 README.md / CHANGELOG.md / tests/，与实际文件树一致。

## [1.1.0] - 2026-07-26

### 新增

- 上游依赖检测两态逻辑（标准模式/引导安装），支持独立安装
- 独立使用时检测 tri-intent 是否可用，未检测到则引导安装

### 变更

- 明确不支持降级模式——引导安装为硬性阻断

## [1.0.0] - 2026-07-24

### 新增

- 初始版本：处理 M01–M05 元操作意图
- 5 子意图差异化响应策略（澄清追问/纠错反馈/追加细化/能力询问/中止确认）
- M02/M03 重路由机制（重路由到原 I 意图 skill 执行）
- 上一轮上下文强依赖，引用准确性要求
- M05 不落盘，与 tri-intent 的「不落盘」Flow 一致
- 轻量无审批门
