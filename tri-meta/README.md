# tri-meta

元操作下游执行 skill。处理 M01–M05（澄清追问/纠错反馈/追加细化/能力询问/中止确认）元操作意图，针对用户「关于对话本身」的控制动作做出响应。针对五个子意图采用差异化响应策略，其中 M02/M03 本质是「再次触发某个 I 意图」，通过重路由机制交接给原 I 意图 skill 执行，不在本 skill 内直接产出 I 意图成果物。强依赖上一轮对话上下文。

## 特性

- **5 子意图差异化响应**：M01 针对具体点澄清 / M02 接受纠错重做 / M03 追加细化 / M04 说明能力边界 / M05 即时叫停或放行
- **M02/M03 重路由机制**：纠错反馈/追加细化本质是再次触发原 I 意图，重路由到原 I 意图 skill 执行，不在本 skill 内产出成果物
- **上一轮上下文强依赖**：M01/M02/M03 必须准确定位上一轮回复对应内容，引用原话关键片段
- **M05 不落盘**：中止确认为即时控制信号，直接响应不产出文件，与 tri-intent 的「不落盘」Flow 一致
- **轻量无审批门**：按子意图选择响应策略后即时交付
- **可独立安装**：支持两态上游依赖检测（标准模式/引导安装），不支持降级模式

## 安装

将 `tri-meta/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-meta/ /path/to/your/skills/
```

> 本 skill 依赖 tri-intent 进行意图识别（M01–M05 判定）。独立使用时会检测上游依赖，未检测到 tri-intent 将引导安装。

## 使用

### 1. 核心流程

当 tri-intent 判定为 Meta 类（M01–M05）时激活，按以下步骤推进：

1. **接收判定与上下文定位**：接收 L2 判定，读取快照 §三 + 上一轮回复上下文，定位用户指向的具体内容
2. **按子意图选择响应策略**：M01 澄清 / M02 纠错重做 / M03 追加细化 / M04 能力说明 / M05 即时控制
3. **M02/M03 重路由**：从上一轮上下文识别原 I 意图，接住元操作信号后重路由到原 I 意图 skill 执行
4. **响应交付**：M01 输出澄清内容 / M02-M03 由原 skill 产出 / M04 输出能力边界 / M05 输出控制信号

### 2. 子意图响应策略

| 子意图 | 响应策略 | 核心动作 |
|---|---|---|
| M01 澄清追问 | 针对上一轮具体点澄清 | 引用上一轮对应内容 → 展开澄清/补充解释 |
| M02 纠错反馈 | 接受纠错，按纠正重做 | 接受纠错 → 定位原 I 意图 → 重路由重做 |
| M03 追加细化 | 基于上一轮追加细化 | 接住细化方向 → 定位原 I 意图 → 重路由追加 |
| M04 能力询问 | 说明能力边界 | 说明能力范围与边界，不夸大不隐瞒 |
| M05 中止确认 | 即时叫停或放行 | 「停/就这样」叫停 / 「可以了」放行 |

### 3. M02/M03 重路由映射

| 原 I 意图 | 重路由目标 |
|---|---|
| I01–I05 | （本分支未包含，原 tri-ask） |
| I11 / I12 | tri-coding / tri-fix |
| I15 | （本分支未包含，原 tri-mm） |
| I16 | （本分支未包含，原 tri-bs） |
| 其它 I 意图 | 对应下游 skill（本分支有下游者） |

### 4. 独立安装依赖检测

| 模式 | 触发条件 | 行为 |
|---|---|---|
| A · 标准模式 | `.tribro/snapshots/` 有快照 或 skills 目录有 `tri-intent/` | M01–M04 读取快照+上下文；M05 直接响应 |
| B · 引导安装 | 以上均不满足 | 提示依赖并引导安装 tri-intent |

## 设计原则

- **元操作是关于对话本身的控制动作**：M 类意图针对上一轮回复或 AI 本身发问，区别于新一轮独立提问
- **M02/M03 本质是再次触发 I 意图**：重路由到原 I 意图 skill 执行，不在本 skill 内产出 I 意图成果物
- **上一轮上下文强依赖**：M01/M02/M03 必须准确定位上一轮回复对应内容，脱离上下文凭空响应视为失败
