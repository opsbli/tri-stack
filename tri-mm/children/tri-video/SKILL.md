# 视频生成（tri-mm 子SKILL · 视频）

> 本 skill 是 tri-mm 在 I15 多媒体生成下的**视频类子 SKILL**，依据 tri-mm 转交的媒体任务（快照 `snapshot.md` §三 + 媒体类型=视频）做多维度详细设计，先产出**分镜头设计方案**交用户确认，再生成视频产物。
>
> 用户心智：把 AI 当"懂分镜、懂运镜的短片导演"，期望先把每个镜头的时长、画面、运镜、转场、字幕、节奏定清楚，再一键生成，避免"生成出来节奏不对、字幕错位再从头改"。

## 强制执行契约（Execution Contract · 最高优先级）

0. **版本检查前置硬门（第零步）**：MUST 先通过 §版本检查与更新机制（连接 skillhub 校验版本，非最新版 MUST 自动执行 `skillhub upgrade <slug>` 升级；升级成功后继续，升级通道不可用则标注 D 态降级继续）——此为执行流程第零步，优先于后续所有步骤。版本检查完成前 NEVER 进入后续步骤。本条目优先级高于所有其他强制前置条目。

1. **强制前置**：收到 tri-mm 转交任务 MUST 先读取快照 §三，校验 `intent.L2_核心意图 = I15` 且媒体类型 ∈ {视频}；NEVER 跳过校验直接生成。独立使用 MUST 先走 §上游依赖检测。
2. **多维设计先于生成**：MUST 先完成 §视频设计方法论 的全部维度分析，产出分镜头 `design.md` 设计方案，NEVER 在未经用户确认前调用生成工具或开始渲染。
3. **确认门不可跳**：分镜头 `design.md` MUST 呈现用户确认；未确认 NEVER 进入生成。修改 → 修订回确认；取消 → 终止。
4. **子任务协同**：若需旁白/配音，MUST 通过 tri-mm 协同 `tri-audio` 子SKILL 生成（不在本子SKILL 内自行编造音频工具指令）；音乐 BGM 由 tri-music 提供。
5. **产物落盘**：生成视频 MUST 落盘 `.tribro/multimedia/video/<命名>/` 并返回可访问路径，NEVER 仅对话内联。
6. **参数可复现**：MUST 记录分镜头参数与生成参数。
7. **自检句**：作答前声明「本次意图=I15·视频，已读取快照，制作路线=<AI生成/代码渲染>，镜头数=<N>，设计方案已交付确认=<是/否>」；与快照冲突 MUST 停止纠正。
8. **双路线判定先于设计**：收到视频任务 MUST 先按 §制作路线判定 确定制作路线并记录判定依据；代码渲染路线 MUST 按 §知识包装配顺序 读取对应 references 知识包执行，NEVER 跳过审美准则自检与独立终检。

## 职责边界

- **负责**：视频类（含分镜头设计、画面生成、剪辑参数构造）的多维设计 + 生成；代码渲染路线下还包括制作流水线执行、程序化渲染工程产出、审美准则自检与独立终检
- **不负责**：音乐创作（tri-music）、图片（tri-image）、PPT（tri-ppt）、纯文本（tri-content）、编码（tri-coding）
- 与 tri-audio：旁白/配音由 tri-audio 协同生成；本子SKILL 不自行生成音频
- 与 tri-music：BGM/歌曲由 tri-music 提供；代码渲染路线下 BGM 的**节奏分析与卡点编排、SFX 选型与钉帧、音画对齐验收**归本子SKILL（设计与方法论职责，不是音频生成）

## 制作路线判定（先于多维设计）

| 信号 | 路线 |
|---|---|
| 输入为主题/脚本/创意描述，无页面素材依赖，接受 AI 生成工具的节奏与质感 | **AI 生成工具路线**（默认） |
| 输入为前端项目/网页/录屏，要求产品宣传片、真实页面运镜、卡点节奏、逐帧精确控制 | **代码渲染路线** |
| 用户点名渲染引擎/程序化制作/代码动画，或要复刻某支已验收宣传片的镜头结构 | 代码渲染路线 |
| 两条路线都可行 | 先出双路线对比（成本/可控性/周期）交用户选择，不默认代替决策 |

判定结果写入 design.md 首行并进入自检句。**两条路线共用 10 维设计方法论与确认门**；代码渲染路线额外加载 §知识包装配顺序 中的 references 知识包（八阶段流水线/审美准则/镜头卡体系/采集与相机/卡点与声音）。

## 视频设计方法论（核心能力 · 可扩展）

> 先设计、再生成。每个维度 MUST 在 design.md 分镜头表中显式填充。两条路线通用。

### 多维设计维度

| # | 维度 | 说明 | 常见取值 |
|---|------|------|----------|
| 1 | 时长与时长结构 | 总时长、段落划分 | 15s/60s/3min；开场-发展-高潮-结尾 |
| 2 | 分镜头脚本 | 每个镜头的画面内容、景别、时长 | 镜头1/2/3… |
| 3 | 运镜 | 镜头运动方式 | 固定/推/拉/摇/移/跟/升降/手持/无人机 |
| 4 | 转场 | 镜头衔接方式 | 硬切/淡入淡出/溶解/遮罩/匹配转场 |
| 5 | 画面与视觉 | 色调/滤镜/主体/场景/特效 | 暖调/赛博/胶片感 |
| 6 | 旁白与配音 | 文案、音色（协同 tri-audio） | 有/无；由 tri-audio 生成 |
| 7 | 字幕 | 语言、样式、位置、关键帧 | 中文/双语；底部/顶部 |
| 8 | 节奏与 BGM | 卡点、情绪曲线（BGM 由 tri-music） | 快节奏/舒缓 |
| 9 | 画幅与参数 | 比例、分辨率、帧率、格式 | 横 16:9/竖 9:16；1080p/4K；MP4 |
| 10 | 平台适配 | 发布平台规格 | 抖音竖屏/YouTube 横屏/B站 |

## 处理流程

> 执行顺序固定：§版本检查与更新机制（第零步）→ 上游依赖检测 → 读取快照 §三 → §制作路线判定 → 核心执行。版本检查未通过前 NEVER 进入以下任一执行步骤。

> 含**分镜头设计方案确认门**。

### 步骤 1：任务接收与校验

1. 读取 tri-mm 转交任务，校验 `L2=I15` 且媒体类型=视频
2. 按 §制作路线判定 确定路线并记录依据
3. 声明自检句

### 步骤 2：多维设计 → 产出分镜头 design.md

1. 逐维度填充 §视频设计方法论，生成分镜头表
2. 如需旁白 → 标记由 tri-audio 协同；如需 BGM → 标记由 tri-music 提供
3. 代码渲染路线：路线判定后立即按装配顺序读 `production-pipeline.md`，阶段 0–3（产品理解/视觉方向与 styleframe/功能镜头映射/分镜放行）在此步完成，分镜表含帧级时间轴与 hold/rest 帧预算；用户已指定 BGM → 先跑 `scripts/beat_grid_fit.py` 做节奏分析，网格验收（残差 ≤±15ms）通过前不分镜
4. 落盘 `.tribro/multimedia/video/<命名>/design.md`

### 步骤 3：确认门（不可跳）

1. 呈现分镜头 design.md，明确「请确认或提出修改」
2. 确认 → 步骤 4；修改 → 修订回本步；取消 → 终止
3. 共创意愿强的用户可按 `references/production-pipeline.md` §1 模式 3 在产品简报/需求决策/视觉方向/镜头映射/最终分镜五处逐级确认；确认后不重跑

### 步骤 4：协同与生成

- **AI 生成工具路线**：据 design.md 调用 tri-audio（旁白）/ tri-music（BGM）协同产出；生成各镜头画面并按转场参数剪辑
- **代码渲染路线**：按流水线阶段 4–6 连续执行——素材采集三件套（`capture-and-camera.md`）→ 逐镜头实现（读卡三读 + 静帧验收写死 2 帧号 + 整片重渲 + 确定性渲染铁律）→ 声音设计（`beat-sync-sound.md` §5，画面锁定后才做，from 全用相对表达式）
- 产物落盘 `.tribro/multimedia/video/<命名>/`，记录参数

### 步骤 5：核对与交付

1. 逐项核对 `任务要点` 覆盖（时长/画幅/字幕/平台）
2. 代码渲染路线：**独立终检必做**——派干净上下文 subagent 按 `references/aesthetic-rules.md` 26 条 + 方案一致性逐条出带帧号证据的报告；卡点片渲后回测全部切点误差 ≤3f；配 BGM 片终渲交付带 BGM/无 BGM 两版；修复项回对应阶段小循环直到通过
3. 落盘 `result.md`
4. 返回 tri-mm 汇总

## 质量标准

| 维度 | 标准 | 验证方式 |
|---|---|---|
| 方案完整 | 10 维度 + 分镜头表填充；路线判定有依据 | design.md 无空维度 |
| 确认到位 | 用户确认后生成 | 确认记录存在 |
| 协同正确 | 旁白→tri-audio / BGM→tri-music | 不越界生成音频 |
| 产物可访问 | 文件落盘 | 路径可开 |
| 参数可复现 | 分镜头+生成参数完整 | 可重生成 |
| 任务要点覆盖 | 满足全部条目 | 逐项核对 |
| 准则自检（代码渲染） | 26 条审美准则逐条过检 | 终检报告编号 ✓/✗(帧号) |
| 独立终检（代码渲染） | 干净上下文 subagent 第三方审查，不带辩解 | 终检报告存在且非制作方自述 |
| 确定性渲染（代码渲染） | 禁 Date.now/Math.random，伪随机固定种子 | 代码扫描 + 重渲帧一致 |
| 卡点精度（卡点片） | 全部切点误差 ≤3f | 渲后抽音轨回测 |
| 音画对齐（带音频） | 输出偏移+峰值滞后两项实测补偿 | 对帧回放无错位 |

## 版本检查与更新机制（强制技术约束 · 硬红线）

> 家族级强制技术约束，优先级与「强制执行契约」同级。skill 任一执行入口启动后的**第零步**，先于核心执行阶段。
> **细则唯一真源**：`references/version-check-spec.md`。本节为可独立执行的最小声明，NEVER 在此内联展开细则；修订规则只改真源一处。

**执行要点**

0. **确定性入口（可执行实现）**：`python scripts/check_update.py --slug tri-video --json`（脚本与家族同源，位于本 skill `scripts/`）。解析 JSON `state`：`A`/`B`/`C`/`D` 一律放行并标注降级口径；`BLOCK` 绝对禁止执行。退出码 `< 20` 放行，`>= 20` 阻断。细则见本 skill `references/version-check-spec.md`（瘦指针，真源随 tri-mm 包分发）。
1. **端点取自配置**：API 主机 MUST 读自 `~/.skillhub/metadata.json`，NEVER 硬编码域名。营销官网 `skillhub.cn` 与 API 主机 `api.skillhub.cn` 是两个站点——官网对任意路径都返回 `200 + HTML` 兜底页，绝不可作校验端点。读不到配置即判通道不可用。
2. **校验请求**：`GET {api_host}/api/v1/skills/{slug}`，超时 ≤ 5s，失败重试 1 次，会话内仅校验一次。
3. **最新版取值**：`latestVersion.version`，缺失时回退 `skill.tags.latest`。平台**不提供** `min_compatible` / `deprecated` / `checksum_sha256` / `signature`，NEVER 依赖这些字段。
4. **响应有效性**（三条件同时成立）：HTTP 200 **且** `Content-Type` 含 `application/json` **且** 能解析出版本字段。仅看状态码会被 SPA 兜底页击穿。
5. **版本比较**：按 [SemVer](https://semver.org/lang/zh-CN/) 逐段整数比较，NEVER 字符串比较。
6. **四态判定**：
   - **A 校验通过**（响应有效且 `current >= latest`）→ 放行。
   - **B 离线降级**（网络不可达）→ 标注「版本校验未完成（离线）」后以当前版本继续。
   - **C 通道降级**（可达但响应无效 / 404 / 405 / 读不到配置）→ 标注「版本校验未完成（通道不可用）」+ 输出通道异常告警后继续。
   - **D 升级降级**（陈旧且已真实尝试自动升级但未完成）→ 标注「版本陈旧·自动升级失败」+ 输出手动升级指引后继续。
   - 四态 NEVER 用于绕过「已检出陈旧却不尝试升级」——MUST 先真实执行一次自动升级，失败方可落 D 态。
7. **更新通道（自动执行）**：检出陈旧 MUST 自动执行 `skillhub upgrade <slug>` → `skillhub verify <slug>`，升级前备份、签名明确不一致则回滚。CLI 不在 PATH 时回退 `python ~/.skillhub/skills_store_cli.py upgrade <slug>`；CLI 缺失或升级失败 → 落 D 态降级继续，NEVER 阻断。以 junction 指向源码树的 `source: local` skill 跳过自动更新，改为提示维护者手动同步。命令细则、CLI 定位顺序与已知陷阱见真源。
8. **阻断条件 P1–P4** 与四处版本同步点见真源；发布前 MUST 通过家族版本同步校验。
