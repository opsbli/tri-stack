# production-pipeline — 程序化渲染路线 · 八阶段制作流水线

> 本文件是 tri-video「代码渲染精确路线」的核心方法论：用程序化渲染引擎（如 Remotion）
> 从真实页面素材逐帧制作产品宣传片/演示视频。当路线判定为「代码渲染」时按本流水线执行；
> AI 生成工具路线不使用本文件（走 SKILL.md §视频设计方法论 的 10 维设计 + 生成提示词）。

## 装配层级

常驻层（代码渲染路线激活时常驻）。覆盖优先级：用户明确指令 > 本文 > SKILL.md 通用流程。
grep 定位模式：`阶段`、`styleframe`、`分镜`、`素材采集`、`终检`。

## 0. 双路线判定

| 信号 | 路线 |
|---|---|
| 输入为前端项目/网页/录屏，要求产品宣传片、真实页面运镜、卡点节奏、逐帧精确控制 | **代码渲染路线**（本文件） |
| 输入为主题/脚本/创意描述，无页面素材依赖，接受 AI 生成视频工具的节奏与质感 | AI 生成工具路线（默认） |
| 用户点名渲染引擎/程序化制作/代码动画，或要复刻某支已验收宣传片的镜头结构 | 代码渲染路线 |
| 两条路线都可行时 | 先出双路线对比（成本/可控性/周期）交用户选择，不默认代替决策 |

代码渲染路线的工程前提：Node.js 环境 + Remotion（React 视频渲染框架，30fps、1920×1080
起步；**独立许可**——个人与小团队免费，公司商用须自行确认许可条款）。

## 1. 三种推进模式（互不合并，选定不回问）

1. **模板复现**：已有已验收宣传片模板/往期成片 → 保持其镜头结构，只替换素材、文案与品牌信息。
2. **自主推进**：授权 agent 自主决策 → 阶段 0–7 连续执行，不逐阶段等确认；用户既有要求（用途/受众/功能/画幅/音频/数据口径）是硬约束，不得被默认选择覆盖。
3. **共创确认**：用户参与决策 → 在产品简报、需求决策、视觉方向、镜头映射、最终分镜五处逐级确认；确认后从阶段 4 继续，不重跑不重问。用户说「你全权决定」时切换为自主推进并记录。

模式未定时：先做**最小只读产品检查**（定位/主要功能/页面状态/视觉 tokens/数据风险），
给出三模式适配性判断与推荐，明确询问后停住等待，不默认替用户选择。

## 2. 八阶段流水线

执行总原则：**方向性问题不进昂贵的逐镜头阶段**；**验收贯穿全程，不是最后一个阶段**。

### 阶段 0：产品理解与执行约束
只读检查项目定位、主要功能、页面状态、视觉 tokens、启动方式、数据风险。产出：产品简报、
需求到执行决策表、数据与音频约束。敏感数据（客户/个人/内部/密钥/实时）一律先虚构、脱敏
或冻结；公开演示数据须确认公开属性后使用。用户已指定 BGM → 先做节奏分析（见
beat-sync-sound.md），网格未验收前不设计分镜。

### 阶段 1：视觉方向与 styleframe
用最便宜的产物锁定色板/字体/光感/运镜气质：写纯 HTML/CSS styleframe 页（2–3 张 1920×1080
静态关键画面），截图验证后再写第一行视频代码。**品牌→动效参数推导**（不凭手感挑缓动）：
按能量轴（低=沉稳 premium ↔ 高=运动 startup）× 调性轴（严肃 ↔ 活泼）两轴定位，从最近预设起步：

| 预设（品类） | 主时长@30fps | 入场缓动 | 过冲 | squash |
|---|---|---|---|---|
| 专业信赖（fintech/enterprise/B2B） | ~21f | bezier(0,0,0.2,1) | 1.0 不弹 | 0 |
| 精致高端（奢侈品/时尚） | ~48f | bezier(0.4,0,0.6,1) | ≤1.02 | 0 |
| 活力大胆（体育/游戏/startup） | ~18f | bezier(0.16,1,0.3,1) | 1.12 | 0.25 |
| 活泼愉悦（消费/社交） | ~27f | bezier(0.34,1.56,0.64,1) | 1.08 | 0.18 |
| 平静关怀（健康/教育） | ~42f | ease-in-out 对称 | 1.0 | ≤0.04 |
| 亲和友好（小微/社区） | ~26f | bezier(0.25,0.46,0.45,0.94) | 1.04 | 0.08 |

自检：①用三个词描述成片动效，与品牌词对得上吗；②同一套 tokens 必须同时管入场/转场/hold
节奏——一个品牌一种动效嗓音。注意：落地要弹的场合 bezier y1 必须 >1（预设「不弹」仅指无
落地隐喻的淡入/推移类动作）。有参考片 → 先抽帧做 motion breakdown（每个动画/转场/特效的
实现方式清单，三列表：手法｜参考实现｜取舍），选择性适配不强行套用。

### 阶段 2：功能到镜头映射
先列产品功能清单逐一对应镜头（核心功能漏拍=返工）；扫描配方卡库（shot-card-system.md）
按用途/能量/时长/所需页面状态为每项功能选首选与备选；一种动画手法全片只当一次主角。

### 阶段 3：分镜与制作放行
查段位模板（shot-card-system.md §能量弧）分配段位与帧预算；有指定 BGM 时镜头边界全锚
拍号，最强 hit 分给全片 2–3 个大 slam。写完整分镜表：镜头顺序/时长/功能信息/页面状态/
镜头卡与变体/主动作/素材来源/字幕/转场/SFX；**预留 hold/rest 帧预算**（品牌字标落定
hold ≥1s、批量动效收尾 0.5s 静止、开场主体动作 ≥3s——节奏返工是单向的：过快必返工，
放慢从未被否）。分镜转帧级时间轴 `| shot | from | duration | 内容 |`（卡点片 from/to 全用
beatF(n) 表达）。

### 阶段 4：最终素材采集
**画面分镜放行后才做**（素材方向错误拖到逐镜头阶段才暴露=整套场景报废）。按
capture-and-camera.md 产出三件套：全页 2x 截图 + per-element cutout + layout.json 坐标表；
活数据源先按阶段 0 口径冻结/虚构/脱敏。

### 阶段 5：逐镜头实现
每镜头「先解析再三读」（校验卡名→读配方卡全文→定位并读参考实现源码全文→copy 组件进
工程）；**静帧验收**：每镜头在计划里写死 2 个验收帧号，完成即渲染单帧肉眼检查构图/穿帮/
文字锐度，产物按版本归档 `out/qa/`；每轮修改后整片重渲 + ffmpeg 抽关键帧回看；对照
aesthetic-rules.md 边做边自检。**确定性渲染铁律**：禁 `Date.now()`/`Math.random()`/无参
`new Date()`，一切伪随机用固定种子（mulberry32/哈希，seed 从 index 派生），逐帧可复现。

### 阶段 6：声音设计
**画面时间线锁定后才开始**（画面每动一次，钉帧表全体重对——最贵的顺序教训）。按
beat-sync-sound.md §声音设计执行；配 BGM 的片子预留布尔 inputProp，终渲从同一时间线出
带 BGM/无 BGM 两版。

### 阶段 7：独立终检与交付
全片渲最新版，ffmpeg 抽全部关键帧（每镜头至少：入场中/动作峰值/落定后三帧）。**派一个
干净上下文的 subagent 做第三方终检**——不给制作过程中的辩解、修改历史或「应该通过」的
暗示，只给：成片、关键帧、产品简报、决策表、视觉方向/分镜、镜头卡与变体、参考样片、
aesthetic-rules.md 与 final-review 检查单；逐条出带帧号证据的报告（如「Q2 ✗（第 615 帧
文字发糊）」）。修复项回对应阶段小循环，checklist 通过后终渲出片（配 BGM 片双版本）。

## 3. 逐镜头实现常见坑（实证沉淀）

- 首检交给用户：交付前必须自己抽帧看片。
- 跳过参考实现直接新写：参数是多轮真实裁决调校出来的，新写几乎必回踩已知坑。
- 产品宣传片默认不加手持 shake（Q3）。
- 装饰性光效群发：批量元素入场靠运动本身，群发即廉价（Q4）。
- 3D 推进文字发糊：先查纹理链路（2x 纹理 + CSS zoom + 关键元素 4x），别先动相机和景深（Q2）。
- 飞入动画终点悬空：元素必须落进页面布局的真实槽位，悬浮其上显得假（Q9）。
- 改错立即整 commit revert 重来，不在错误版本上打补丁；每个改动独立 commit。

## 4. 无头/CI 渲染三坑（已实证）

1. 低核机器渲染并发上限报错 → 显式 `--concurrency=1`。
2. 新版 Chrome 移除旧 headless 模式，指系统 chromium 启动失败 → 改用 chrome-headless-shell。
3. 渲染引擎自动下载浏览器被 CDN 阻断 → `--browser-executable=<本地 headless-shell 路径>`。
