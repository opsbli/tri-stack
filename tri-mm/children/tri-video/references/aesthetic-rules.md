# aesthetic-rules — 判例式审美准则（代码渲染路线 · 26 条）

> 每条 = 规则（一句可执行的话）+ 判例要点（实战返工沉淀）+ 自检问题，三要素缺一不可。
> 代码渲染路线阶段 5 起边做边自检，阶段 7 独立终检**逐条过一遍**，输出格式：
> `编号 ✓` 或 `编号 ✗(镜头名/帧号)`。准则可以有意识违反（风格需要），但每次违反必须写进
> 该项目说明文档（违反哪条、为什么）。

## 节奏（R）

### R1. 关键信息落定后必须呼吸，品牌字标 hold 满 1 秒
承载信息的元素（字卡/数字/网格全貌）落定后静止 ≥1s 再切镜；呼吸停顿优先给品牌记忆点，
不给普通内容卡片。
自检：每个「想让观众记住的画面」有完整静止时刻吗？停顿给的是品牌/关键信息还是随手给了普通元素？

### R2. 速度感来自加速度：群体运动挂物理隐喻，收尾留 0.5s 停顿
飞入/滚动一律非线性缓动 + 非均匀错峰，匀速运动读作廉价 PPT；大量同类元素入场用「越来越快」
的硬加速节拍，最好绑一个物理隐喻（如发牌/堆积），满板后静止 0.5s 再切下一拍。抽象泛化式
群运动多轮不收敛时，换具体物理隐喻往往一轮通过。
自检：有没有元素在做匀速直线运动？批量入场是否越来越快、末尾有无静止呼吸？

### R3. 节奏宁慢勿快：主体动作弧 ≥3s，交互演示按真人操作速度
开场主体动作（聚焦→悬浮→归位完整弧线）至少 3 秒；模拟真实交互（打字/筛选/点击）按真人
速度走；排时间线预留 hold/rest 帧预算——第一版几乎总是偏快。实战判例：全部反馈指向
「放慢/停留」，从未有「太慢了」的反向反馈。
自检：把每个镜头当第一次看：哪里没看清？交互段自己能跟着操作一遍吗？

### R4. 卡点约束时机不放大幅度：全画面级冲击全片 ≤3 处
强节奏 BGM 片「切点落拍」≠「逐拍打画面」——作用于整画面/相机层的冲击（整画面 scale 泵/
震屏/闪帧/负片帧）视同大 slam 管理：全片 ≤3 处、钉最强 hit 清单、相邻间隔 ≥16 拍；其余
拍点动效只作用主角元素层；节拍泵类连打单次 ≤4 拍、全片 ≤1 次。计数单位是一次手法使用，
不按内部子事件数。根因判例：把 kick→冲击映射执行成逐拍全画面泵，强鼓点曲 kick 几乎每拍
都有，逐拍「被砸」叠加相机层即节拍频率的画面抖动。
自检：高能段任取连续 8 拍逐帧回放：整画面在逐拍脉冲吗？全画面冲击超 3 处了吗？

## 质感·运镜·构图（Q）

### Q1. 复刻既有页面必须真实截图；手搓 UI 限非复刻场景且质量/表达双硬门槛
表现产品既有页面的镜头，第一步就用无头浏览器截真实页面（整页纹理+元素级抠图+坐标 json）；
非复刻场景（抽象开场/品牌段/独立展示组件）允许手搓，但出版级质感 + 观众一眼看懂是硬门槛，
达不到回截图路线。数据按风险口径处理（见 capture-and-camera.md）。
自检：每块 UI 素材在复刻既有页面吗？手搓件的质感和表达能过 Q10 级审视吗？

### Q2. 3D 纹理按原生尺寸栅格化后向下采样；文字发糊先查栅格化链路
3D 场景里的 UI 纹理按显示尺寸 2–4 倍原生栅格化、在 3D 里向下采样；放大走布局级 CSS `zoom`
而非 `transform: scale`。文字模糊先查栅格化路径，**别先动相机/DoF——DoF 只做氛围，永远
不是清晰度的解法**。详见 capture-and-camera.md §高清栅格化。
自检：放大/透视镜头逐帧截图看文字边缘：有像素方块吗？纹理源分辨率 ≥ 显示尺寸 2 倍吗？

### Q3. 镜头要稳：产品宣传片默认禁手持抖动
亮场 UI 宣传片禁 handheld shake；相机噪声只在暗场氛围片明确追求纪实感时用极小值，且渲染帧
自查确认无意外抖动。
自检：逐镜头看渲染帧：有非叙事意图的相机抖动吗？

### Q4. 高光/扫光宁缺毋滥：不群发、主角一次、裁进圆角
glint/泛光划过类特效不做群发——批量元素入场靠运动本身；保留的光效必须被承载元素的
border-radius/overflow 裁剪，光溢出圆角是廉价感典型来源。技术路径本身不封杀：单点、给主角、
质量过硬的 sheen 可做，做完对渲染帧自问「好看吗」再交。
自检：全片 glint/sweep 超「主角一次」了吗？每处光效被圆角裁剪了吗？

### Q5. 开场只给一个主角：单主体 + 完整动作弧
开场信息宁少而聚焦——一个主角元素、一条完整弧线（聚光→推近→悬浮→描边光→归位），多元素
并舞撑不起第一印象。
自检：开场镜头有几个「想让观众看」的东西？主角动作弧完整（起-承-落）吗？

### Q6. 机位服务可读性：信息密集镜头正视，文字特写侧向水平
风格化机位逐镜头决定——叙事/情绪镜头可倾斜，列表/堆叠等信息密集镜头保持正视；含文字的
卡片特写用侧向水平机位，避免大角度仰俯拍破坏可读性；**禁止全局一刀切**套用某种机位风格。
自检：每个倾斜机位镜头：斜的理由是什么？文字在这个角度读得清吗？

### Q7. 物件特写四件套：侧面倾斜角 + 可感知高度 + orbit 环绕 + 反差深色材质
物件/资产特写做足环境戏：侧面倾斜机位、堆叠出体积高度、镜头绕主体环绕、背景用与主场景
反差的深色材质（如拉丝金属），拉远同步过渡回主场景。四件套缺一不可。
自检：特写主体有体积感和环境反差吗？相机是死机位还是有环绕/拉远？

### Q8. 结尾做成「发布会合影」：全片元素围住字标，能量推到全片峰值
多功能产品收尾用「全家福」结构——每个已展示功能抽一个代表元素多方向飞入定格；规格匹配
全片能量峰值（crane 运镜 + 舞台光 + 粒子）；初版收尾几乎总偏保守，默认加码一档。
自检：结尾是全片能量最高点吗？每个已展示功能都有代表元素吗？

### Q9. 飞入的终点必须是页面布局里的真实槽位
元素飞入后要「嵌入」页面（归位真实格位、扩展滚动流），不落地悬浮其上显得假。
自检：每个飞入元素落定后在布局里有真实坐标吗？有元素永久浮在页面之上吗？

### Q10. 文档类镜头的 mock 内容要出版级
观众会读清屏幕上每个字——mock 文档必须用产品原生排版灌满真实密度的假内容，侧栏/评论栏等
版式元素完整入镜；「贴图+标语」级别的假文档整镜头返工。
自检：暂停在文档镜头任意一帧：内容读起来像真的吗？版式完整吗？

### Q11. 要被读的文字有最低有效字高：字幕 ≥5% 帧高、辅助 ≥3%，按渲染帧实测像素
1080p 成片按手机/内嵌小窗播放校准：叙事字幕有效字高 ≥56px（推荐 60px 档），辅助文字
≥32px；有效字高 = fontSize × 全部祖先 scale × 透视压缩（3D 按 cos(rotY) 估算），**验收量
渲染帧实际像素，不看代码 fontSize**。文字只有两态：「纹理」（装饰小字，明显虚化/降亮度让
观众不去读）或「要读」（达标字号+足够对比度）；「重排了但仍读不清」是非法中间态，读不到
宁可删。收尾 URL/行动号召是全片最不该小的一行。
自检：抽每个含字幕镜头一帧缩到 480px 宽：读得清吗？逐帧量「要读」文字实际像素达标吗？

## 声音（S）

### S1. 按片种选音不按事件选：电影系 SFX 词汇，禁游戏音包音色（禁音色不禁动作）
SFX 词汇表 = whoosh(运镜)/impact(落地)/riser(铺垫)/sparkle(光效)/transition(转场)；BGM 选
强鼓点强节奏电子底，判据是「典型产品宣传片气质」不是「好听」。**禁的是音色不是动作**：
画面真有点击/开关/碎裂就该配拟音（那是 S4）。判别问句：这个音像真实世界里那个物件发出的
声音，还是像游戏引擎里的反馈提示音？前者用后者弃。合成 UI 反馈音（tone/bleep/notification
类）除非刻意要「系统提示」叙事，一律排除。
自检：闭眼只听音轨：像产品发布会预告还是像手机游戏？BGM 是垫进成片试听后选定的吗？

### S2. SFX 逐拍钉帧集中管理；连发防机枪三招
SFX 用「帧号+音源+音量」声明式表管理，逐条注释对应画面动作，杜绝凭感觉铺；连发防机枪感
三招——双样本交替、音量阶梯递减（如 0.40→0.25 六级）、间隔跟随动画曲线加速；密到糊成
一片时让声音淡出成 swoosh，不逐个配音。
自检：每条 SFX 钉在具体帧号并注释动作了吗？连发段是「数得出来的节奏」还是机械复读？

### S3. 声音在画面锁定后做；时间线一动全表重钉
BGM/SFX 排在画面结构基本锁定之后；任何改变镜头时长/顺序的修改，收尾动作固定包含「全表
SFX 帧号重对」——音画错位是交付前必查项。实战教训：钉完 11 小时后画面大改导致全表重钉，
三次重钉中两次纯属画面返工连带成本。
自检：本轮有镜头时长/顺序变化吗？SFX 表逐条重对过了吗？

### S4. 拟音优先于装饰音：画面动作配真实声音，音频裁到与动作严格等长
打字配键盘声、逐条落入配逐个 pop——泛用 swoosh 盖不住有辨识度的动作；长样本按画面段落
截断（显式 durationInFrames，靠 Sequence 截断不剪文件），带长尾混响的 impact 例外；峰值
偏低的轻音素材首选换素材或预归一化，`volume` 是乘法系数，给到 1.0 也救不回 -12dB 以下的
素材，必要时 >1 增益并以渲染产物验峰防削波。
自检：每个有辨识度的动作有自己的拟音吗？音效有拖到动作结束还在响吗？每条音效在成片里
真的听得见吗？

### S5. 音画对齐补两项偏移：输出音轨偏移逐渲染管线实测统一扣，音源峰值滞后逐文件量
渲出成片的整条音轨相对视频有固定滞后（AAC encoder priming，48kHz 典型 2048 samples
≈1.28f@30fps），按渲染管线（引擎版本+codec+采样率+容器）实测记档——渲出成片抽音轨，拿
2–3 个尖锐 SFX 原文件做归一化交叉相关，残差一致才算量准；补偿在渲染层 from 计算式统一扣，
不逐条改帧号。音源自身峰值滞后（峰值不在文件头）逐文件量。统一公式：
`from = 目标峰值帧 − 峰值滞后 − 输出偏移`。**偏移常数不可跨渲染管线搬运**；不补时最重
一击可晚 0.27s，明显读作音画不同步；卡点片差 2–3 帧即让合理卡点动效读作无端抖动。
自检：本管线的输出偏移实测过吗？补偿统一扣还是散落各条帧号里？带攻击峰的音源峰值滞后量过吗？

## 文案（C）

### C1. 文案在画面锁定后按最终镜头重写一遍，纯动画段落也配解说
初稿文案只是占位——画面定稿后对照成片逐镜头重写；纯动画镜头配短解说 caption，不留
「哑巴段落」（品牌收尾镜头除外）。
自检：每句文案和它所在画面匹配吗？有超过 3 秒的无解说动画段落吗？

### C2. 标语写「团队 + 产品功能名 + 具体收益」，抽象隐喻词一律具体化
标语要具体、带功能名，避免泛化口号；重要功能出场前加引导字卡。
自检：每句标语有具体功能名/收益词吗？有只靠隐喻撑着的句子吗？

### C3. 3D 镜头里的注记文字活在同一 3D 空间
给 3D 场景主体配画内注记：文字进同一 3D 空间（页面坐标系、同一相机透视、translateZ 悬浮 +
落影），平面叠字与场景脱节；样式用大字 + 马克笔 highlight 关键词。
自检：3D 镜头里每块文字跟着场景相机动吗，还是贴在屏幕玻璃上？

## 流程（P）

### P1. 交付前必须自己渲染截帧逐一检查，不把首检交给用户
每轮修改后先自行渲染关键帧截图逐一检查（构图/抖动/文字锐度/穿帮），必要时像素级工具
（裁剪放大/两帧 diff）自证，再交用户；静帧产物按版本归档供双方基于帧评审。
自检：这版交出去前我自己看过哪些帧？关键镜头有截图证据吗？

### P2. 参考素材先逐帧拆解成手法清单，再逐镜头判断适配性，不全局套用
有参考片先抽帧做 motion breakdown 写进 spec，按项目适配性取舍；图片参考描述的是「某一类
镜头」的感觉而非全片风格令——落地前逐镜头判断，改完自查再交。
自检：参考素材的每个手法有「采用/弃用」显式决定吗？有把一张参考图当成全片风格令吗？

### P3. 指代含糊的反馈先确认对象；改错整 commit 干净 revert
「第一个标题」式模糊反馈先确认所指再动手；落错对象立即整 commit revert 重来；每个改动
独立 commit 以便干净回滚。
自检：这条反馈的指代对象确定吗？当前 commit 粒度出错能一键回滚吗？

### P4. 先列功能清单逐一对应镜头；一种动画手法全片只当一次主角，重复即删
开拍前列功能清单逐一映射镜头，核心功能漏拍=返工；一种手法（飞入/堆叠/翻页）全片只当一次
主角；剪辑自查按「这个镜头给了什么新信息」过滤，同一素材/信息全片只出现一次。
自检：功能清单每项有对应镜头吗？有两个镜头用同一手法当主角或讲同一件事吗？
