# 参考图处理与身份保持（公共层）

> 参考图是**高优先级输入**。本文合并了原分散在多处的输入探测、落目录存、深度分析、人物处理与身份保持话术。

## 输入探测

| 输入形态 | 处置 |
|---|---|
| 用户给了图片文件路径 | 复制到 `refs/ref-NN-{slug}.{ext}`（NN 从 01 起），可直传参考图参数 |
| 对话里有图但无路径 | **MUST 按 `user-input-rules.md` 向用户索取文件路径** |
| 用户无法提供路径 | 口述提取风格/配色 → 追加进提示词正文，**NEVER 写入 frontmatter 的 references** |

**硬要求**：只有当文件**真实存进 `refs/`** 后，才允许出现在提示词 frontmatter 的 `references` 列表里；落文件前 MUST 校验文件存在。

## usage 三档

| usage | 语义 | 何时用 |
|---|---|---|
| `direct` | 模型直接看到参考图；**人物必须出现在成果中时 MUST 用这一档** | 需要保持本人/本物身份 |
| `style` | 只抽视觉风格 | 不要人物出现时 |
| `palette` | 只抽配色 | 只要色彩方案 |

## 描述文件（仅当后端不支持参考图时）

后端不支持参考图入参（如部分国产模型早期版本）时，MUST 额外生成 `refs/ref-NN-{slug}.md`，把描述以 MUST/REQUIRED 指令形式嵌进提示词正文：

```yaml
---
ref_id: NN
filename: refs/ref-NN-{slug}.png
usage: direct | style | palette
---
[嵌入提示词的特征描述]
```

## 深度分析 ⚠️

参考图 MUST 提取**具体、可复现**的要素，NEVER 写「干净风格」这类空话：

| 维度 | 好 | 坏 |
|---|---|---|
| 品牌元素 | 「Logo 用三条竖向平行线构成首字母」 | 「有个 logo」 |
| 特征纹样 | 「交织曲线形成菱形网格」 | 「有纹理」 |
| 配色 | 「#2D4A3E 墨绿 + #F5F0E0 米白」 | 「深浅配色」 |
| 版式结构 | 「底部 30% 深色横条承载品牌信息」 | 「有 banner」 |
| 字体 | 「全大写、宽字距」 | 「有文字」 |

输出格式：每条写成**可直接粘进提示词的强制指令**（用 MUST / REQUIRED 起句）。

### 含人物的参考图

除 `usage: direct` 外，按角色补：**外貌 / 姿态 / 服装 / 转换规则（如何贴合渲染风格）**。

## 身份保持话术（核心）

> 想保住真人/实物的身份时，NEVER 用长段外貌描述替代参考图——模型会「按描述合成一个新的人」。

推荐话术（短而硬）：

- 「把参考图中的人物/物体作为**同一身份**使用，NEVER 重新设计或生成一个相似的新主体。」
- 「只允许改变场景、服装、姿态、光照、渲染风格与构图；人脸特征、比例、发型、关键配饰与整体身份 MUST 与参考图一致。」
- 多张参考图时：「这些参考图是同一主体，共同定义身份。」

其它约束：

- 参考图**优选 2–4 张**精选图；数量过多或单图数 MB 会拖垮部分流式后端。
- **NEVER 把本次生成物当作下一轮的参考图**（除非用户显式要求）——会累积漂移。
- 成果过度精致时，追加抗美化约束：不做瘦脸、大眼、浓妆、商业写真式过度磨皮。
- 需要呈现年龄变化时，用服装/姿态/场景表达，NEVER 要求模型改变面部身份。

## 优先级

- **参考图压过默认偏好**：参考图与偏好中的调色板/渲染冲突时，MUST 以参考图为准。
- **具体 > 抽象**；**可见性核验**：出图后 MUST 核对参考要素是否出现，没出现就加强提示词重出。

## 失败降档

参考图传不动 → 压缩（JPEG 质量 65–80）后重试 → 仍失败 → 丢弃参考图、把提取特征写进提示词正文。
