# 用户输入工具约定（公共层 · 全场景共用）

> 本文件是「如何向用户提问」的唯一约定。任何需要用户做选择的环节都 MUST 遵循，不允许各场景自行发明提问方式。

## 核心规则

1. **MUST 优先使用当前运行环境内置的提问能力**——例如 `AskUserQuestion`、`request_user_input`、`clarify`、`ask_user` 或等价物。
2. **降级**：若运行环境无上述能力，MUST 输出**编号纯文本**消息，请用户回复编号作答。
3. **批量**：若该能力支持一次多问，MUST 把本次全部待确认问题合并为**一次调用**；若只支持单问，按优先级逐条提问。
4. **NEVER** 用「要不要继续？」这类无信息量的问题占用户注意力；每个问题 MUST 给出推荐项 + 理由 + 备选。

## 提问格式约定

| 位置 | 要求 |
|---|---|
| 首选项 | 推荐项 MUST 排第一，并在 label 后标注「(推荐)」与一句理由 |
| 备选项 | 2–4 个互斥选项；超出用自由文本兜底，不再追问 |
| 默认推荐 | 来自扩展偏好（见 `preferences-schema.md`）或场景 §Auto-Selection 结论 |

## 与三轨的关系

| 轨 | 何时必须提问 |
|---|---|
| Track-V（矢量确定性） | 图类型无法从请求判定时；无需询问后端 |
| Track-R · T1（原生光栅） | 仅需按场景确认门提问，不询问后端可用性 |
| Track-R · T2（引擎光栅） | 多 provider 且无 pin 时按 `image-backend-rules.md` 第 3 步询问一次 |

> 推荐方式 —— per levels：运行时原生能力 > 编号纯文本。NEVER 静默假设用户选择后直接开跑。
