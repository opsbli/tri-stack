# 生图后端选择规则（公共层 · Track-R 唯一入口）

> 本文件是**光栅生图（Track-R）**选择后端/落盘方式的唯一规则集。
> ⚠️ **作用域声明**：本文全部条款**仅约束 Track-R（光栅生图）**，NEVER 用于约束 Track-V（矢量确定性轨）。结构图类产品由 `../scenes/diagram/README.md` 独立产出 SVG，不受本文「禁止用 SVG 顶替」条款限制。

## 路由总表（先看这里）

| 场景 | 默认轨 | 依据 |
|---|---|---|
| 结构图 / 架构图 / 流程图 / 时序图 / ER / 脑图 / 时间线 / 状态机 / 数据流 | **Track-V**（SVG 矢量，确定性，零额度） | 输出须可编辑、须精确、不依赖模型 |
| 封面图 / 信息图 / 文章配图 / 社媒卡片 / 幻灯片 / 漫画 | **Track-R**（光栅位图） | 输出须是位图资产 |

> 判定不确定时，MUST 按 `../scenes/*/README.md` 的场景关键词确认，**NEVER** 用图代办位图，也 NEVER 用位图代办可编辑矢量图。

## Track-R 后端解析顺序（第 3 步规则）

按序判定，命中即停：

1. **当前请求显式指定** —— 用户在本次消息点名后端 → 用它。
2. **扩展偏好 pin** —— 偏好文件 `preferred_image_backend` 指向某后端且当前可用 → 用它。
3. **自动选择**（偏好为 `auto`/未设置/被 pin 的后端不可用）：
   - **T1 · 运行时原生生图工具**（如 `ImageGen`）——运行环境若提供原生生图能力， MUST 优先使用，优先级高于任何非原生脚本。注意两点硬约束：(a) 它没有「宽高比」参数——MUST 用 `scripts/aspect.py` 把比例换算成像素尺寸写进提示参数；(b) 部分实现会把产物落到工具托管目录——生成后 MUST 移动/复制到本 skill 的约定输出路径。参考图通过对应的图片入参传入（最多 3 张）。
   - **T2 · 引擎脚本**（`scripts/engine/main.ts`）——当且仅当以下任一成立时使用：① 运行时无原生生图能力；② 用户需要 T1 不具备的能力（指定 provider / 模型、批处理并行、2.35:1 等精确比例、4K 尺寸、--n 多张）。执行方式见 `../engine/README.md`，需 Bun 与对应 API Key。
   - **其它运行时原生工具** —— 同理 docstring 优先。
   - 若以上皆不可用且有唯一非原生后端 → 用它；多个非原生且无原生工具 → 询问用户**一次**（与其它初始问题合并一次调用）。
4. **全不可用** —— MUST 明确告知用户并询问如何继续。

**T1 与 T2 的能力差（决定何时必须升轨）**

| 能力 | T1 原生 | T2 引擎 |
|---|---|---|
| 文本生图 | 支持 | 支持 |
| 参考图（图生图） | 支持（≤3 张） | 支持（因 provider 而异，见 `../engine/README.md`） |
| 像素尺寸 | 支持固定档 | 支持任意 W×H 与比例 |
| 宽高比参数 | 不支持（须由 `scripts/aspect.py` 换算） | 支持 `1:1/16:9/9:16/4:3/3:4/2.35:1` |
| 质量档 | low/medium/high | `normal`/`2k`，可 4K |
| 批处理并行 | 不支持 | 支持（`--batchfile` + `--jobs`） |
| 指定 provider/模型 | 不支持 | 支持 12 个 provider |
| 水印 | `footnote`（≤16 字符） | 提示词注入（见 `watermark-guide.md`） |

## ⛔ 两条硬红线（Track-R 内）

1. **NEVER 用 SVG / HTML / canvas / CSS 绘图顶替光栅生图。** 走 Track-R 的场景已经判定「需要位图」；若后端无法解析到第 3 步之外，MUST 落到第 4 步问用户，NEVER 静默产出 SVG 或内联 `<svg>` 交差。
2. **NEVER 用程序修补已生成位图上的文字。** 若标题/标签错讹，MUST 走「改提示词 → 新提示词文件 → 新输出文件名」重出；NEVER 用图像处理、OCR 覆盖、遮罩重绘等方式改写图上文字。允许的后处理仅限：裁剪、缩放、压缩、格式转换（不改文字与主构图）。

## 提示词文件先行（硬）

无论 T1/T2，**每张图的完整终稿提示词 MUST 先落盘**为 `prompts/NN-{scene}-{slug}.md`，再调用后端。详见 `prompt-file-rules.md`。

## coderef 调用契约

> T2 走 Codex 订阅时的专用路径是无 Key 场景的常见解法（不需要 API Key，用已登录的 Codex CLI）。

- 首选：通过引擎的 `codex-cli` provider 调用（自带重试 / 缓存 / 批处理语义，与其它 provider 一致）。
- 直接调用兜底：`scripts/engine/coderef/main.ts --image <out.png> --prompt-file prompts/01-xxx.md --aspect 16:9`。
- **n=1 约束**：该包装器每次调用**只产出 1 张图**。批量场景（幻灯片分页 / 卡片 / 漫画分页）MUST 为每张图单独发起一次调用，NEVER 指望一次出多张；因此分批策略按 `batch-policy.md` 执行，不要试图合并为单次请求。
- 该包装器**不支持 session**：跨图一致性 MUST 靠参考图链（见下）而非会话 ID。
- stdout 单行 JSON：`{"status":"ok","path":...,"bytes":N}` / `{"status":"error","error_kind":...}`。

## 跨图一致性：首图锚链

> 多图序列（卡片 / 幻灯片 / 漫画 / 配图）最容易翻车的是风格漂移。这是 authoritative 解法：

1. **图 1 不带任何参考图**生成，作为锚点。
2. **图 2 及以后 MUST 把图 1 作为参考图传入**（后续图可接力上一张，也可始终指向图 1）。
3. 后端支持会话/种子时叠加使用，但 NEVER 因为支持会话就跳过锚链。
4. 漫画另有角色表机制（`../scenes/comic/character-template.md`），与锚链叠加使用。

## 参考图身份保持话术

参见 `reference-images.md`。核心：**用短而硬的身份保持句**，NEVER 用大段外貌描述替代参考图。

## 失败降档顺序

1. 参考图过大/失败 → 压缩后重试 → 仍失败则丢弃参考图、把提取到的特征写进提示词正文。
2. 后端无参考图能力 → 同上（描述内联）。
3. 后端不可用 → 换下一可用后端 → 全部不可用则入第 4 步询问用户。
4. 文字错讹 → 只重出，NEVER 补绘。
