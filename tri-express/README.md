# tri-express

表达陪伴下游执行 skill。处理 I17–I20（角色扮演/情感陪伴/闲聊娱乐/观点表达）表达陪伴类意图，针对四个子意图采用差异化回应基调，并以安全边界检查作为统一前置（安全边界优先于人设维持）。直接即时自然回应，不落盘不产出成果物，与 tri-intent 的「不落盘」Flow 一致。

## 特性

- **4 子意图差异化回应基调**：I17 角色扮演维持人设一致性 / I18 情感陪伴共情倾听 / I19 闲聊娱乐轻松兜底 / I20 观点表达接住观点给温度
- **安全边界优先于人设维持**：涉及未成年人、自伤、暴力、违法犯罪等有害内容时，按全局安全规则拒绝/转介，不为维持人设妥协安全底线
- **不落盘不产出文件**：即时对话回应即全部交付，不生成快照、不产出文件
- **无自检句要求**：保持对话自然度，不作答前声明（内部须确认子意图与回应基调匹配）
- **轻量无审批门**：按子意图选择回应基调后即时回应，单轮交付
- **可独立安装**：支持两态上游依赖检测（标准模式/引导安装），不支持降级模式

## 安装

将 `tri-express/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-express/ /path/to/your/skills/
```

> 本 skill 依赖 tri-intent 进行意图识别（I17–I20 判定）。独立使用时会检测上游依赖，未检测到 tri-intent 将引导安装。

## 使用

### 1. 核心流程

当 tri-intent 判定为 Expressing 类（I17–I20）时激活，按以下步骤推进：

1. **接收判定与基调选择**：接收 tri-intent 的 L2 判定，按子意图选择对应回应基调
2. **安全边界检查**：在生成回应前对内容做安全过滤，安全边界优先于人设维持
3. **即时自然回应**：按选定基调生成回应，不产出文件、不落盘
4. **对话延续**：回应后保持对话开放，用户切换意图时由 tri-intent 重新路由

### 2. 子意图回应基调

| 子意图 | 回应基调 | 核心策略 |
|---|---|---|
| I17 角色扮演 | 进入人设，维持角色一致性 | 按用户指定人设回应，全程不出戏 |
| I18 情感陪伴 | 共情倾听，情感支持 | 先接住情绪再回应，不急于给建议 |
| I19 闲聊娱乐 | 轻松娱乐，兜底所有无法归类项 | 接住话题自然延展，不强行输出知识 |
| I20 观点表达 | 接住观点，给有温度的回应 | 先确认接住观点，可补充视角但不否定 |

### 3. 独立安装依赖检测

| 模式 | 触发条件 | 行为 |
|---|---|---|
| A · 标准模式 | skills 目录有 `tri-intent/` | 接收 tri-intent 的 L2 判定，按子意图差异化回应 |
| B · 引导安装 | 以上均不满足 | 提示依赖并引导安装 tri-intent |

## 设计原则

- **不同子意图需要不同回应基调**：角色扮演、情感陪伴、闲聊娱乐、观点表达四种形态差异大，统一基调无法兼顾
- **安全边界是统一底线**：无论何种子意图，安全边界检查作为统一前置，优先于人设维持
- **即时对话回应不破坏自然度**：不落盘、不产出文件、不作答前声明，保持对话流畅自然
