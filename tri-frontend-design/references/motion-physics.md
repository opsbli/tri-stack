# 流体交互物理层（motion-physics.md）

> 界面"活起来"的物理学：响应、直接操控、可中断性、弹簧、速度交接、动量投射、橡皮筋、材质深度、排版光学。

## 贯穿主线

> 当动效**从当前屏幕值起步、继承用户速度、向前投射动量、且随时可被抓住并反向**时，界面就活了。

弹簧是让这一切自然的工具，因为它天生可中断且感知速度。

---

## 1. 响应——消灭延迟

延迟一旦出现，直接感"断崖式下跌"。响应是其余一切的基础。

- **在 pointer-down 时响应，而非释放时。** 按钮在按下的**瞬间**就要高亮。等 `click`/touch-up 才给反馈，感觉是死的。
- **对每一处延迟保持警惕。** 审计 debounce、人为定时器、过渡等待、~300ms 点击延迟。输入路径上任何非必需的东西都是 regression。
- **反馈 MUST 贯穿交互过程，而非只在结束时。** 拖拽、滑块、抽屉 MUST 全程 1:1 跟随指针，NEVER 只在手势完成时动画。

```css
.button:active {
  transform: scale(0.97);
  transition: transform 100ms ease-out;
}
```

## 2. 直接操控——1:1 跟踪

> "触摸与内容应当一起移动。"

用户拖东西时，它 MUST 粘在手指上，并**尊重他们抓取处的偏移**。抓取时吸附到元素中心会立刻破坏错觉。

- 用 Pointer Events 配 `setPointerCapture`，指针离开元素边界后继续跟踪。
- 维护一小段**速度/位置历史**（最近几次 `pointermove`），而不只是当前点——释放时需要速度。

```js
el.addEventListener('pointerdown', (e) => {
  el.setPointerCapture(e.pointerId);
  const grabOffset = e.clientY - el.getBoundingClientRect().top; // 尊重抓取位置
  // ...记录位置 + 时间戳历史以计算速度
});
```

## 3. 可中断性——最重要的一条原则

> "思维与手势是并行发生的。"

每个动画 MUST 在任意时刻可中断、可重定向。用户 MUST 能抓住正在飞行的元素并反向，而不必等动画播完。一个正在关闭的模态框被用户再次抓住时，应当跟随手指——而不是先关完再打开。

- **NEVER 在过渡期间锁死输入。**
- **永远从"呈现值"（当前屏幕值）起算，NEVER 从目标值起算。** 中断时读取元素的实时屏幕 transform，从那里起新动画。从逻辑/目标值起步会产生可见跳变。
- **手势驱动的东西避免用 CSS transition 与 `@keyframes`**——它们无法被平滑地中途抓住并反向。Spring 默认从当前值起步，正是中断所需。
- **手势反向时融合速度，NEVER 硬切。** 用另一个动画替换一个动画会造成速度不连续——一堵"砖墙"。能带着速度重定向的 spring 库可以避免它。
- **把 2D 运动分解为独立的 X 与 Y 弹簧。** 单一弹簧驱动 2D 距离，在 X/Y 速度不同时会失步。

## 4. 行为优于动画——用弹簧

> "把动画看成你与对象之间的对话，而不是界面预先规定的脚本。"

预编排的固定时长动画无法响应新输入。弹簧可以——新输入只是改变目标，运动保持连续。凡是用户能碰到的东西，都用弹簧。

### 两个设计师友好的参数（Apple 刻意用它们取代 mass/stiffness/damping 三元组）

- **Damping ratio（阻尼比）** —— 控制过冲。`1.0` = 临界阻尼，无回弹，平滑收敛。`< 1.0` = 过冲并振荡。越低越弹。
- **Response（响应）** —— 值抵达目标的速度，单位秒。越低越利落。**这不是"时长"**——弹簧没有固定时长，收敛时间由参数涌现。

**默认：**
- 大多数 UI 从 **damping `1.0`**（临界阻尼）起步——从容且不分散注意力。
- **仅当手势本身携带了动量时**（轻扫、抛掷、拖拽释放）才加回弹（**damping ~`0.8`**）。一个刚淡入的菜单过冲是错的；一张被你甩出去的卡片过冲是对的。

**Apple 实际出厂值：**

| 交互 | Damping | Response |
| --- | --- | --- |
| 移动 / 重定位（如画中画） | `1.0` | `0.4` |
| 旋转 | `0.8` | `0.4` |
| 抽屉 / 面板 | `0.8` | `0.3` |

```js
import { animate } from 'motion';

// 临界阻尼默认（无过冲）
animate(el, { y: 0 }, { type: 'spring', bounce: 0, duration: 0.4 });

// 动量交互——一点回弹，只因为前面有一次轻扫
animate(el, { y: target }, { type: 'spring', bounce: 0.2, duration: 0.4 });
```

## 5. 速度交接——拖拽与动画之间的接缝

手势结束时，动画 MUST **以手指的确切速度继续**，使拖拽与动画之间没有可见接缝。正是这个细节区分了"流体"与"还行"。

把指针释放速度作为弹簧的初速度传入。有些弹簧 API 要的是**相对**速度——按到目标的剩余距离归一化：

```
relativeVelocity = gestureVelocity / (targetValue − currentValue)
```

例：元素在 `y=50`，目标 `y=150`（还剩 100px），手指以 50px/s 移动 → 弹簧初速度 = `50 / 100 = 0.5`。Framer Motion / Motion 直接接受绝对 px/s 速度（`velocity` 选项），通常传原始值即可。

## 6. 动量投射——动画到手势"正要去的地方"

> "小输入，大输出。"

NEVER 从**释放点**吸附到最近边界。用速度**投射静止位置**——与滚动减速完全同理——然后吸附到距该投射点最近的目标。这才让一次轻扫感觉像把元素"扔"了出去。

Apple 的确切投射函数（出自《Designing Fluid Interfaces》示例代码）：

```js
// decelerationRate ≈ 0.998 为常规滚动手感；0.99 更利落
function project(initialVelocity /* px/s */, decelerationRate = 0.998) {
  return (initialVelocity / 1000) * decelerationRate / (1 - decelerationRate);
}

const projectedEndpoint = currentPosition + project(releaseVelocity);
const target = nearestSnapPoint(projectedEndpoint);       // 由投射点选目标
animateSpringTo(target, { velocity: releaseVelocity });  // 然后交接速度（§5）
```

> **注意：物理教科书里的 `v²/(2·decel)` 不是 Apple 的做法**——MUST 用上面的指数衰减形式。这是优质 bottom-sheet 与 carousel（Vaul、Embla）的标准行为。

## 7. 空间一致性——对称路径、锚定原点

> "如果某物是这样消失的，我们预期它会从原处出现。"

- **进出走同一条路径。** 从右侧滑入的面板 MUST 向右侧消失。右进/下出让人感到断裂与困惑。
- **把交互锚定到其来源。** 菜单、popover、面板应源自触发它的元素——把 `transform-origin` 设为触发器，让按钮与内容之间的空间关系显而易见。
- **可逆过渡上镜像缓动**，让去程与回程一致（两个方向用互为反向的 cubic-bézier 控制点）。

## 8. 朝手势方向给提示

人会从轨迹预测最终状态。中间帧 MUST 预告事物要去哪——控制中心模块"朝着你的手指长大并展开"。让中间帧指向结果，而不只是盲目插值到结果。

## 9. 橡皮筋——软边界

在边缘处**渐进地抵抗**，而非硬停。硬停读作"卡死"；连续抵抗读作"响应着，但到头了"。施加随越界距离递增的阻尼。

```js
// 越界越远，元素跟随得越少——真实物体在停下前会减速
function rubberband(overshoot, dimension, constant = 0.55) {
  return (overshoot * dimension * constant) / (dimension + constant * Math.abs(overshoot));
}
```

## 10. 手势设计细节（手感检查单）

- **点按**：在 touch-**down** 时高亮（即时），在 touch-**up** 时提交。目标周围加约 **10px** 迟滞/命中内边距，并允许"拖离取消、拖回恢复"。
- **拖拽/滑动**：提交方向前需要一个小位移阈值（迟滞，约 **10px**），之后 1:1 跟踪。
- **从第一次移动起并行检测所有可能手势**，意图清晰后再果断取消落败者。避免只报**最终状态**的识别器（`swipeleft` 类事件）——它们丢掉了反馈所需的连续跟踪。
- **最小化消歧延迟。** 双击检测不可避免地会延迟单击；只在确实存在双击的地方付这个代价。

## 11. 帧级平滑

平滑关乎**帧里有什么**，而不仅是帧率。

- 保持每帧位置变化低于感知阈值，避免频闪。
- 极快运动时，轻微的**运动模糊/拉伸**能编码速度，比一道生硬锐利的残影读起来更好。
- `requestAnimationFrame` 是 Web 的显示同步时钟（Apple 用 `CADisplayLink`）。只动画合成器友好的属性——`transform` 与 `opacity`——并在动效临近处用 `will-change` 提示。

## 12. 材质与深度——半透明传达层级

Web 上用 `backdrop-filter` 近似 Apple 的半透明材质层。

- **把导航/工具栏/面板做成半透明层**（`backdrop-filter: blur()` + 半透明背景），内容在其下滚动——而非占据固定条带的实色栏。
- **材质重量编码层级**：更暗/更重的材质分隔结构区域（侧边栏）；更轻的材质把注意力引向交互元素（按钮）。**NEVER 在一个半透明表面上再叠一个**——可读性会崩塌。
- **更大的表面应当读起来更厚**：比小 chip 更强的模糊 + 更深的阴影。考虑上下文感知阴影——在繁忙/文字内容上方更重以分隔，在纯色背景上方更轻。
- **用变暗聚焦，用分隔保持流畅。** 模态任务配变暗遮罩并把背景推后/下沉；并行的非阻塞面板用半透明与偏移，**不加遮罩**，以免打断流转。堆叠面板时逐层递增变暗与后推。
- **Vibrancy 让文字在变化背景上保持可读。** 在模糊/半透明表面上，NEVER 用平板灰文字——用更高对比、略重字重、以及一点点字距增量。颜色放在实色层上，不要放在半透明前景上。
- **用滚动边缘效果，而非硬性分隔线。** 在内容触及浮动 chrome 处淡出一个小的模糊/渐变遮罩，替代 sticky header 下的 1px 边框——且只在浮动 UI 真正与内容重叠处使用。
- **让它"物化"，而非只是淡入。** 玻璃/模糊表面进出时，同时动画模糊半径与缩放，让表面读起来是一块真实材质抵达，而非一次平淡的 opacity 淡入。

```css
.toolbar {
  background: rgba(255, 255, 255, 0.6);
  backdrop-filter: blur(20px) saturate(180%);
  border-top: 1px solid rgba(255, 255, 255, 0.4); /* 亮顶边 = 光打在材质上 */
}
```

## 13. 多模态反馈——动效 + 声音 + 触感

组合感官的三条规则：

1. **因果性** —— MUST 显而易见是什么造成了反馈。在实际的因果事件上触发（开关翻转、元素吸附归位），并让反馈的**性质**匹配动作的物理性。
2. **和谐** —— 视觉、声音、触感 MUST 在**同一帧**触发。它们之间的延迟会摧毁错觉。不要让 CSS 过渡滞后于音频/触感（Vibration API）。
3. **效用** —— 只在赚到位置的地方加反馈。触感/声音留给有意义的时刻（成功、错误、提交、吸附）。过度反馈会训练用户无视全部反馈。

## 14. 减弱动效与无障碍（三个独立信号）

减弱动效**不是没有反馈**，而是更温和、不致前庭不适的等价物。MUST 响应三个信号并把它们内建进组件：

- **`prefers-reduced-motion: reduce`** —— 用短促的 opacity **交叉淡入或静态过渡**替换滑动/弹簧/视差。去掉弹性/过冲。保留有助理解的 opacity/颜色变化。
- **`prefers-reduced-transparency: reduce`** —— 让半透明表面更实/更"霜"：提高背景不透明度，去掉模糊。
- **`prefers-contrast: more`** —— 近乎实色的背景 + 明确的高对比边框。

另外：避免全视口移动背景、缓慢循环振荡（接近 0.2 Hz / 每 5 秒一周期）、以及突兀的亮度跳变（深浅色主题切换要缓动）。大的移动对象在行进中做成半透明；大幅重定位期间淡出大表面，落定后再淡入。

```css
@media (prefers-reduced-motion: reduce) {
  .sheet { transition: opacity 200ms ease; transform: none !important; }
}
@media (prefers-reduced-transparency: reduce) {
  .toolbar { background: white; backdrop-filter: none; }
}
```

## 15. 排版——光学尺寸、字距、行距

Apple 让字形随尺寸改变形状；同样的纪律适用于 Web。

- **字距（letter-spacing）随字号而变——NEVER 一个值打天下。** 大号展示字要**负**字距（字号变大时字母看起来会分得太开）；小字要略微**正**字距以保证可读。固定的 `letter-spacing` 总会在某处是错的。标题收紧，正文接近 `0`。
- **行距（line-height）与字号反向联动。** 大标题紧，正文松。升降部较高的文字体系要加大；信息密集的 UI 要收紧。
- **层级由字重 + 字号 + 行距成套构建**，而非仅靠字号。用字重强调——它增加存在感却不占更多空间。
- **尊重用户的字号设置**（Dynamic Type）。布局随文字缩放——间距用 `rem`/`em`，而非固定 px。
- **默认用平台系统字体**，其次才是自定义字体——系统字体已自带光学尺寸、字距表与可读性调优。只在有理由时覆盖。

```css
:root { font: 100%/1.5 system-ui, sans-serif; } /* 正文：系统字体，舒适行距 */

.display {
  font-size: clamp(2rem, 5vw, 4rem);
  line-height: 1.05;        /* 大字号用紧行距 */
  letter-spacing: -0.02em;  /* 变大时负字距 */
  font-optical-sizing: auto;
}
```

## 16. 八条设计原则

| # | 原则 | 要点 |
|---|---|---|
| 1 | **目的 Purpose** | 有意图地做；决定**不**做什么。每个功能都在索要用户的时间、注意力与信任——只把这份预算花在能回本的地方 |
| 2 | **自主 Agency** | 让人保持掌控：给选择，NEVER 只留一条路。以"可原谅"兜底——失误易撤销；确认对话框只留给真正破坏性、不可逆的动作（慎用；滥用会训练人无脑点过） |
| 3 | **责任 Responsibility** | 按用户利益行事。隐私：在对的时刻、只为所需、透明地索取。安全：预判误用与伤害——尤其在 AI 场景（一个知悉过敏的食谱 App 绝不能建议有害食材）。加预览、确认、免责声明；风险大于价值时砍掉功能 |
| 4 | **熟悉 Familiarity** | 建基于人已知的东西。用既不太直白也不太抽象的隐喻（垃圾桶意味着删除），并尊重其物理性。保持一致：看起来一样的东西 MUST 行为一样、位置一样，人才能预测下一步。只有在能证明更好时才打破熟悉模式——然后去测，NEVER 假定 |
| 5 | **灵活 Flexibility** | 为不同情境、设备与全部能力范围而设计。适配平台与场景，包容性设计（年龄、语言、熟练度、无障碍）。没有单一布局适合所有人时，让人个性化——重排控件、隐藏不用的 |
| 6 | **简洁 Simplicity（非极简）** | 剥掉不必要的，让核心目的发光；把一切埋在一处看起来极简，但并不简洁。要简练（平实语言、无术语、更少步骤）且清晰（用层级——顺序、间距、对比——让最重要的最显眼）。每个元素都要赚到自己的位置；有时**增加**上下文反而简化（显示剩余时间的视频拖拽条）。先展示常规路径，高级选项深一层 |
| 7 | **工艺 Craft** | 不妥协的细节建立信任。优美的排版、随明暗自适应的颜色、清晰的图标语言、给出即时自然反馈的响应动效。没有什么是随机的——每个间距、时序、对齐值都是可辩护的刻意选择。抖动滚动、图标错位、旋转就崩的布局读作"不用心"。工艺需要迭代与长期性——随功能与硬件变化持续演进设计 |
| 8 | **愉悦 Delight** | 是把前七条做对之后的**结果**，而非撒上去的彩带。决定你想让人感受到什么情绪（平静、自信、兴奋），并在每一个决定中强化它 |

**服务于上述原则的战术规则：**

- **反馈有四种**：状态、完成、警告、错误。确认有意义的动作，暴露进行中的状态，问题发生前警告，内联校验（而非提交时才校验）。
- **寻路（Wayfinding）**：每个屏幕都该回答——我在哪？我能去哪？那里有什么？我怎么出去？NEVER 困住用户。
- **分组与映射**：邻近意味着关系；把控件放在它所影响的东西旁边，并让控件排布镜像它改变的东西。若需要一个标签来解释某个控件，说明映射太弱。
- **直接、具体的标签胜过安全的泛称。** 用内容命名导航项（"进度""资料库"），而非含糊的伞形词（"首页"）。具体性创造可预测性。

## 17. 流程

- **交互式地做原型——一个可交互的 demo 值"一百万张静态设计稿"。** 你是靠做出来玩着发现界面的；能跑的原型也树立了一条具体的标尺，防止最终实现沦为平庸。
- **交互与视觉一起设计。** "你不该能分清哪个先结束、哪个后开始。"动效不是像素之后加的一层。
- **在真实情境中与真实的人测试**，并用新鲜眼睛复核动效——慢放/逐帧播放，捕捉全速下看不见的东西。

## 速查表

| 需要 | 技法 | 具体值 |

| 默认 UI 弹簧 | 临界阻尼，无过冲 | `damping 1.0`，`response 0.3–0.4` |
| 动量 / 轻扫弹簧 | 欠阻尼，轻回弹 | `damping ~0.8`，`response 0.3–0.4` |
| 手势 → 弹簧速度 | 交接释放速度 | `gestureVelocity / (target − current)`（若要归一化） |
| 轻扫落点 | 投射动量 | `current + (v/1000)·d/(1−d)`，`d ≈ 0.998` |
| 干净地中断 | 从呈现值（实时值）起步 | 读取屏幕上的 transform |
| 避免反向"砖墙" | 重定向时带着速度 | 能融合速度的 spring |
| 可逆过渡 | 镜像缓动曲线 | 互为反向的 cubic-bézier |
| 判定反向 vs 提交 | 用速度的**符号**，而非位置 | 在释放时刻 |
| 1:1 拖拽 | Pointer Events + 捕获 | 尊重抓取偏移 |
| 反馈 | 在 pointer-down，且连续 | NEVER 只在结束时给 |
| 边界 | 橡皮筋，而非硬停 | 渐进阻力 |
| 半透明 chrome | `backdrop-filter` 层 | 内容在其下滚动 |
| 字体字距 | 随字号而变，NEVER 固定 | 大字号收紧（`-0.02em`），正文接近 `0` |
| 减弱动效 | 交叉淡入，而非滑动/弹簧 | `@media (prefers-reduced-motion)` |
