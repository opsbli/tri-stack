# tri-frontend-design 全场景测试用例

> 版本强一致：本文件 frontmatter `version` MUST == SKILL.md `version`（当前均为 1.1.1）。
> 每个用例含：输入 / 预期 / 判定点。判定点对应 SKILL.md 的契约条款。

## TC-01 锚点选择 · 出人意料（§1 步骤2）

- **输入**："帮我做一个工业风花店首页"
- **预期**：锚点=工业风（Industrial）；差异化点=如"等宽体价格标签随库存跳动"；理由陈述偏向出人意料而非稳妥。
- **判定点**：② 偏向出人意料；拒绝"稳妥默认"（如所有简报都导向工业风）。

## TC-02 单锚点铁律 · 拒绝杂交（§1 末段 / §5 抗杂交）

- **输入**："瑞士风但带点粗野主义的硬阴影"
- **预期**：MUST 拒绝杂交，提示"带粗野主义边缘的瑞士风是范畴错误"，要求二选一。
- **判定点**：单锚点铁律；§5 抗杂交项不过则回炉。

## TC-03 令牌保真 · 瑞士风（§3 / §4 / references/anchors.md）

- **输入**：锚点=瑞士风格
- **预期**：渲染 CSS 含纯白/中性灰、无衬线、可见网格；无暖纸、无 Fraunces、无颗粒。
- **判定点**：§4 Token fidelity；§5 令牌保真项。对照 `references/anchors.md` Swiss 段。

## TC-04 令牌保真 · 工业风（references/anchors.md）

- **输入**：锚点=工业风
- **预期**：纯黑/暖黑底、声明字体全为等宽体、1px 边框无阴影、tabular-nums；无圆角、无衬线比例字体。
- **判定点**：§4 Token fidelity；对照 Industrial 段。

## TC-05 令牌保真 · 粗野主义

- **输入**：锚点=粗野主义
- **预期**：纯原色 2–3 种、系统字体、硬偏移阴影 `8px 8px 0 #000`、原生控件；无网络字体、无软阴影、无居中。
- **判定点**：对照 Brutalist 段 Breaks if。

## TC-06 令牌保真 · 极光极繁

- **输入**：锚点=极光极繁主义
- **预期**：暗色高饱和渐变、Inter/PP Neue Machina 超大字、网格渐变、霓虹 text-shadow 辉光；无纯色背景、无发丝线主结构。
- **判定点**：对照 Aurora Maximalism 段。

## TC-07 令牌保真 · 混沌极繁

- **输入**：锚点=混沌极繁主义
- **预期**：冲突粉彩+霓虹、3+ 混排字体、满屏图案、超大展示字；无协调色板、无单一字族、无 60/30/10。
- **判定点**：对照 Chaotic Maximalism 段。

## TC-08 令牌保真 · 复古未来

- **输入**：锚点=复古未来主义
- **预期**：纯黑、年代字体、CRT 扫描线/色差、霓虹双色；无现代无衬线（Inter/Söhne）、无纸质表面。
- **判定点**：对照 Retro-Futuristic 段。

## TC-09 令牌保真 · 有机风

- **输入**：锚点=有机风
- **预期**：大地色系、人文衬线/暖几何无衬线、圆角 16–32px、1–3% 颗粒；无奶油色 `#F0+`、无冷灰、无硬矩形。
- **判定点**：对照 Organic 段（注意 Fraunces 仅限本锚点）。

## TC-10 令牌保真 · 低保真

- **输入**：锚点=低保真
- **预期**：纸黄、混排系统字体、2–8° 旋转、半调网点、Risograph 套印错位；无精确感、无平滑动效、无奶油色。
- **判定点**：对照 Lo-Fi 段。

## TC-11 内容纪律 · 禁止编造（§2）

- **输入**：屏幕需展示"用户会话列表"，但用户未提供真实数据
- **预期**：MUST 留空或请求真实数据，NEVER 编造 `a.chen@grid.co`、`GRID.FREQ 59.998 Hz`、`BUILD 8.2.0-rc3`。
- **判定点**：§2 五项禁止第一项；§5 内容节制项。

## TC-12 内容纪律 · 禁止填充/主题化/字形/套话（§2）

- **输入**：登录页
- **预期**：不用 `SECURE OPERATOR AUTHENTICATION` 等填充大写、不用 `// INTELLIGENCE LAYER` 伪注释、按钮用 `Next` 而非 `Authenticate Session`、不用 `▣` 当图标、不写 `Ask the grid.` 等 AI 套话。
- **判定点**：§2 五项禁止第 2–5 项；§5 内容节制项。

## TC-13 交付物完整性（§4）

- **输入**：完整一次前端设计请求
- **预期**：交付含①明确导向（锚点+理由+差异化点+关键令牌）②令牌保真说明 ③内容节制核对 ④差异化点可见证据。
- **判定点**：§4 四项全过。

## TC-14 发布前自检（§5）

- **输入**：渲染产物
- **预期**：五项（出人意料搭配 / 令牌保真 / 内容节制 / 差异化点可见 / 抗杂交）逐条判定，任一不过回炉。
- **判定点**：§5 全过。

## TC-15 版本检查门（第零步）

- **输入**：任一执行入口启动
- **预期**：先运行 `scripts/check_update.py --slug tri-frontend-design --json`；state∈{A,B,C,D} 放行，BLOCK 阻断。
- **判定点**：强制执行契约第 0 条；脚本退出码 `<20` 放行。

## TC-16 上游依赖检测三态（§上游依赖检测）

- **输入**：不同上游环境
- **预期**：有可用快照→A 快照模式；无 tri-intent 且用户愿装→B 引导；拒绝安装→C 降级声明。
- **判定点**：三态逻辑匹配。

## TC-17 频率硬门 · 键盘触发动作禁止动画（契约⑦ / §6 步骤1）

- **输入**："给命令面板开合加个入场动画"
- **预期**：MUST 判定为键盘触发 + 100+ 次/天，NEVER 添加开合动画；给出"Raycast 无开合动画即正确"的类比说明。
- **判定点**：契约⑦；`motion-standards.md §1` 频率闸门；频率未过门不得进入曲线选择。

## TC-18 动效令牌真源 · 数值不近似（契约⑧ / §6 步骤5）

- **输入**："给瑞士风按钮加点击反馈动效"
- **预期**：曲线 MUST 取自 `motion-standards.md`（`ease-out` `cubic-bezier(0.23, 1, 0.32, 1)`、150–200ms、纯 opacity/transform）；`scale(0)` 弹出 MUST NOT 用；`scale(0.97)` 作按压反馈。
- **判定点**：契约⑧；`cubic-bezier(0.23, 1, 0.32, 1)` 写 `0.25` 视为缺陷。

## TC-19 锚点↔动效基线映射（§7 / anchors.md Motion baseline）

- **输入**：锚点=工业风，请求"按钮hover 弹个弹性动效"
- **预期**：动效基线=近乎无动效；MUST 拒绝弹性，仅给 100–160ms 按压反馈；不得违背工业风 Motion baseline。
- **判定点**：§7 映射表；`anchors.md` 工业风 Motion baseline 段；与 SKILL.md §7 一致。

## TC-20 a11y 随动效同交（契约⑨ / §6 步骤7）

- **输入**："给模态框加淡入淡出"
- **预期**：交付 MUST 含 `prefers-reduced-motion` 降级（退化为瞬时显隐）+ hover/focus 等价态；缺任一即视为未交付。
- **判定点**：契约⑨；`motion-standards.md §8`。

## TC-21 动效评审 · Block/Approve 裁决（motion.review / motion-review.md）

- **输入**：既有界面，动效入场用 `ease-in` + 从 `scale(0)` 弹出
- **预期**：对照十条标准，判定违反"入场用 ease-out、禁止 scale(0) 弹出"，输出 Before-After-Why 表，裁决 Block 并给修复。
- **判定点**：`motion-review.md` 十条不可协商标准；Before-After-Why 格式；Block/Approve 明确。

## TC-22 机会发现 · 强制输出被否决清单（motion.find / §6 子动作）

- **输入**："我的 dashboard 哪些地方该加动效"
- **预期**：输出"该动"清单 + **强制输出被否决候选及理由**（克制机制，"这里已经对了"是合法结论）。
- **判定点**：§6 子动作 `find`；强制否决清单不得缺失。

## TC-23 全库审计 · 自包含 plan（motion.audit / motion-plan-template.md）

- **输入**："把整个站点的动效审计一遍，深度 standard"
- **预期**：四阶段（侦察→并行审计→复核定级→自包含 plan），产出分级发现表 + `plans/NNN-*.md`（假设执行者零上下文零品味）。
- **判定点**：`motion-plan-template.md` 自包含要求；`plans/` 落盘路径。

## TC-24 多变体 · 锚点内分歧、不跨锚点（variants / §8）

- **输入**："出 3 个瑞士风 dashboard 变体"
- **预期**：3 个变体在瑞士锚点内沿布局/密度/交互模型/动效叙事分歧；NEVER 混搭其他锚点令牌；产出 picker harness + 权衡表。
- **判定点**：§8 分歧轴；单锚点铁律（硬约束）不破；变体真正分歧非微调。

## TC-25 三模式七处同步（硬约束 26 · 收口核验）

- **输入**：核对 SKILL.md 三模式（design/motion/variants）
- **预期**：触发时机 / 强制契约 / 输入契约 / 职责边界 / 落盘规则 / 产物清单 / 自检句 七处均覆盖三模式，无遗漏。
- **判定点**：硬约束 26；七处 × 三模式 = 21 检查点全命中。

## TC-26 知识装配顺序完备（硬约束 25 / §知识装配顺序）

- **输入**：核对 `§知识装配顺序` 表
- **预期**：8 个 references 全部列出，且每行有 grep 模式；数值仅存于 `motion-standards.md`（单一真源）。
- **判定点**：硬约束 25；去重规则（recipes 引用而非重定义、review 指针回 L1）。
