# tri-humanize

去 AI 化改写方法论 skill（横向 · 5 原则速查 + 35 模式精判 + 人味注入）。为 tri-xxx 家族提供「去 AI 化改写」能力——先按 5 条速查原则粗筛，再对照 35 种 AI 写作模式（内容 / 语言语法 / 风格 / 聊天机器人 / 填充对冲与结构套路 五类）精判；删 AI 腔并注入人味，让文本读起来像真人书写，同时不改变原意、不虚构事实。

![version](https://img.shields.io/badge/version-1.1.0-blue) ![license](https://img.shields.io/badge/license-MIT-green)

## 特性

- **速查 + 精判双层识别**：顶层 5 条核心规则速查（删填充 / 破公式 / 变节奏 / 信读者 / 删金句）粗筛，下层 35 种模式精判——覆盖内容模式（夸大/炫耀/浅层分析/销售语言/模糊来源/公式化展望）、语言语法模式（AI 词/避免 is-are/Not X but Y/强行三连/改名重复/虚假范围/被动语态）、风格模式（破折号/加粗/标题/表情/引号）、聊天机器人模式（残留文本/截止声明/顺从语气）、填充对冲与结构套路（填充短语/限定词/正面结尾/连字符/假真相/宣布/标题重复/旧版本/笑点/谚语/假坦诚/无人异议/虚假替代）
- **中英文双触发词**：35 种模式各给出英文识别信号与中文触发词，中文文本直接对照中文词表，英文技术文本对照英文词表；对中文天然不适用的模式（标题大写、弯引号）显式标注不适用与替代信号
- **人味注入（加法层）**：删掉 AI 腔只是减法，本节补上人的观点、节奏与具体感受；内置启用判据（有样本按样本 / 个人写作启用 / 参考技术法律文本不注入）与刹车条款（只注入观点与感受，NEVER 注入事实）
- **三种输出形态**：粘贴文本（草稿 + 模式清单 + 终稿 + 质量自评）/ 文件（只写终稿，保留代码与元数据）/ 嵌入（仅终稿，供下游消费）
- **写作样本匹配**：用户提供 2-3 段本人写作时，样本优先于默认风格规则（含破折号按样本频率保留）
- **误报检查**：What not to flag 清单 + Human details to keep，避免误伤正常写作
- **三问六检自检**：问 AI 腔 / 问事实增删 / 问人味，外加交付前六项清单（句长 / 结尾 / 破折号 / 解释隐喻 / 连接词 / 三段列举）
- **事实保真**：不增删任何事实/名称/数字/日期/引用/引文/排名
- **质量自评（非门禁）**：粘贴模式输出直接性 / 节奏 / 信任度 / 真实性 / 精炼度 5 维评分（总分 50），仅作参考，不覆盖事实保真与误报检查
- **横向方法论型**：不认领 L2 意图编码，由用户显式调用或 tri-article 等下游委派激活
- **四态上游依赖检测**：独立使用时检测上游 tri-intent，据结果选择模式 A 快照 / A0 待识别 / B 引导安装 / C 降级

## 安装

将 `tri-humanize/` 目录放入你的 skills 目录，或通过 skillhub 安装：

```bash
skillhub install tri-humanize
```

本 skill 可独立安装，但依赖上游 tri-intent 产出的快照以获得完整效果。激活时检测上游 tri-intent 是否可用，据检测结果选择执行模式；未安装时建议先安装依赖：

```bash
skillhub install tri-intent
```

## 使用

### 核心流程

收到去 AI 化改写请求后，按以下链路推进：

```
版本检查（第零步）→ 上游依赖检测（四态）→ 读取输入（文本/文件/样本）
        │
        ▼
速查 5 原则粗筛 → 35 模式精判（对照 references/ai-patterns.md）
        │
        ▼
匹配语气（有样本则样本优先）+ 判定是否启用人味注入
        │
        ▼
写草稿 → 三问自检（还像 AI？增删事实？缺人的判断？）+ 六检 → 写终稿
        │
        ▼
误报检查（What not to flag / Human details to keep）
        │
        ▼
按输出形态返回（粘贴含自评 / 文件终稿 / 嵌入终稿）
```

### 调用示例

**粘贴文本（默认）**：

```
去 AI 化这段文本：[paste your text here]
```

**文件模式**：

```
改写 docs/launch-post.md 的散文
```

**写作样本匹配**：

```
这是我的写作风格样本：
[paste 2-3 paragraphs of your own writing]

现在去 AI 化这段文本：
[paste AI text to humanize]
```

**嵌入模式（下游委派）**：tri-article 等下游 skill 调用本 skill 作为去 AI 化引擎，仅返回终稿。

## 设计原则

- **先粗后细**：顶层 5 条速查原则负责快速定位，35 模式决策表负责精确判定与处置，避免一上来就扫 35 条规则
- **决策规则显性化**：35 种模式提炼为 IF-THEN 决策规则（识别信号 → 处置动作 → 原因），每种模式配 Before-After 示例可回溯
- **判定与处置分层**：判定是否 AI 腔要多个模式同现（防误伤），处置是终稿硬性要求（如破折号），两者互不覆盖、各自有例外清单
- **单一事实源**：模式决策规则集中在 `references/ai-patterns.md`，SKILL.md 只保留框架与概览，控制上下文体积
- **误报优先**：宁可漏改也不误伤——单个模式出现不判定 AI 腔，多个模式同现才处置
- **减法 + 加法**：删掉 AI 腔之外还要按需注入人味，注入受事实保真铁律硬约束
- **事实保真铁律**：改写不增删事实，缺细节时询问而非编造
- **可独立可集成**：既能独立安装运行（四态依赖检测），也能作为 tri-article 等下游的去 AI 化引擎无缝集成
