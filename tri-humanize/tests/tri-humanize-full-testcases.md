## 一、测试用例

### 1. 元数据与家族一致性（A1–A3）

| 用例 | 输入 | 预期 |
|------|------|------|
| TC-01 | 检查 SKILL.md frontmatter | 8 字段齐全；name=slug=tri-humanize；version=1.1.1；license=MIT |
| TC-02 | 检查 description | 含「支持独立安装，含上游依赖检测四态逻辑」 |
| TC-03 | 检查版本一致性 | SKILL.md version == README 徽章 == CHANGELOG.md 最新版本号 == _meta.json == tests frontmatter 版本（五处一致） |

### 2. 强制执行契约（B1–B10）

| 用例 | 输入 | 预期 |
|------|------|------|
| TC-04 | 检查契约置顶 | 「强制执行契约（Execution Contract · 最高优先级）」章节存在且含激活语义 |
| TC-05 | 检查 MUST/NEVER | 契约条目用 MUST/NEVER 大写祈使 |
| TC-06 | 版本检查第零步 | 执行 `python scripts/check_update.py --slug tri-humanize --json` 返回 state 字段 |
| TC-07 | 保留每个主张 | 输入含事实的 AI 腔文本，改写后事实数量不变 |
| TC-08 | 不虚构事实 | 输入缺细节的文本，改写不添加来源未提供的细节 |
| TC-09 | 匹配作者语气 | 提供写作样本，改写匹配样本习惯 |
| TC-10 | 硬性规则（处置层） | 输入含 em dash / en dash / 中文全角破折号文本，终稿不含 —、–、——（命中三条例外之一除外） |
| TC-11 | 误报检查（判定层） | 输入含单个 em dash 的正常文本，不误判为 AI 腔；且终稿仍按处置层移除该破折号——判定层与处置层互不覆盖 |
| TC-12 | 最小化原则 | 文件模式只改散文，代码块/YAML/链接目标不变 |
| TC-13 | 自检句 | 操作前声明「本次操作=HUMANIZE，触发源=…，已读取…」 |

### 5. 误报检查（D5–D6）

| 用例 | 输入 | 预期 |
|------|------|------|
| TC-53 | 完美语法文本 | 不误判为 AI 腔 |
| TC-54 | 单个 em dash 文本 | 不误判（仅与公式化节奏同现才判定） |
| TC-55 | 单个强调短句 | 不误判（连续多个才处理） |
| TC-56 | 弯引号单独出现 | 不误判（与其它信号堆叠才计数） |
| TC-57 | 有用限制与免责声明 | 保留 |
| TC-58 | 真实替代方案 | 保留 |
| TC-59 | 第二手文本（引号/标题/专有名词） | 不改写受监控短语 |
| TC-60 | 保留人类细节 | 保留具体不寻常细节/混合感受/时代引用/句长变化/真实题外话 |

### 8. 质量标准与落盘（H1–H3）

|------|------|------|

### 9. 诱饵压力测试（关键）

> 构造「看似该用实则不适用」场景，验证 skill 不越界误用。

| 用例 | 诱饵输入 | 预期（不误触发） |
|------|----------|------------------|
| TC-73 | 用户要求「写一篇新文章」而非改写已有文本 | 不激活改写流程（归 tri-article） |
| TC-74 | 用户要求「翻译成英文」 | 不激活改写流程（归 tri-translate） |
| TC-75 | 用户要求「核查这段的事实真伪」 | 不激活改写流程（归 tri-true） |
| TC-76 | 输入为代码而非散文 | 不改写代码（文件模式只改散文） |
| TC-77 | 输入为引号内的第二手文本 | 不改写受监控短语 |
| TC-78 | 单个模式出现的正常写作 | 不判定为 AI 腔，不误改写 |
| TC-79 | 用户提供写作样本但未要求改写 | 不擅自改写（无改写请求） |
| TC-80 | 无输入文本 | 不静默改写（MUST 先读取输入） |

### 10. 1.1.0 新增能力（D8–D11）

| 用例 | 输入 | 预期 |
|------|------|------|
| TC-81 | 速查 5 原则 | 先过 5 条速查粗筛再进 35 模式精判；速查结论与精判结论冲突时以精判（references 决策表）为准 |
| TC-82 | 人味注入与刹车 | 个人写作文本：改写后含人的观点/节奏变化/具体感受，且事实项数量不变；技术文档文本：不启用注入，不出现第一人称观点句 |
| TC-83 | 破折号判定/处置双层 | 单个破折号的正常文本：判定层不判为 AI 腔，处置层终稿移除；样本使用破折号 / 第二手文本 / 代码块三类例外命中时保留 |
| TC-84 | 质量自评 | 粘贴模式输出 5 维评分与总分（/50）；文件模式与嵌入模式不输出自评；评分不覆盖事实保真与误报检查 |
