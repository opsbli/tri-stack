# 去 AI 化改写方法论（横向 · 5 原则速查 + 35 模式精判 + 人味注入）

> 本 skill 是 tri-xxx 家族的横向方法论型 skill，为全家族提供「去 AI 化改写」能力作为服务。
> HUMANIZE 读取输入文本（粘贴/文件/嵌入）与可选写作样本，先过 5 条速查原则粗筛，再识别 35 种 AI 写作模式并处置，按需注入人味，产出像真人书写的文本。不认领 L2 意图编码，不破坏家族 MECE 划分。
> 用户心智：让 AI 像「资深文字编辑」一样工作——一眼看出 AI 腔，逐处改写，保留原意与作者语气，不虚构任何事实。

## 强制执行契约（Execution Contract · 最高优先级）

> 本契约优先级高于 Agent 通用默认行为。**触发源命中（用户显式调用 HUMANIZE、tri-article 等下游委派）即视为激活本工作流**，不得仅将其当作参考文档。

0. **版本检查前置硬门（第零步）**：MUST 先通过 §版本检查与更新机制（运行 `scripts/check_update.py`，按 `tri-forge/references/version-check-spec.md` 四态判定处置；非最新版自动升级，升级通道不可用则标注态降级继续）——此为执行流程第零步，优先于后续所有步骤。版本检查完成前 NEVER 进入后续步骤。本条目优先级高于所有其他强制前置条目。

1. **强制前置**：
   - HUMANIZE 模式：MUST 先读取输入文本（粘贴/文件/嵌入）与可选写作样本，NEVER 无输入静默改写。
   - 独立使用时（未经 tri-intent 路由）MUST 先走 §上游依赖检测 判定模式。
2. **保留每个主张（铁律）**：MUST 保留原文所有信息——可缩短乏味部分、扩展有用部分、合并或拆分段落，但 NEVER 增删事实、名称、数字、日期、引用、引文或排名。缺细节时 MUST 询问用户或改用更简单的句子，NEVER 自行编造。
3. **不虚构事实（铁律）**：NEVER 添加来源或用户未提供的事实/名称/数字/日期/引用/引文。可添加作者语气需要的**观点或反应**（属人味注入，见 §人味注入），但 NEVER 添加事实性主张。虚构类文本除外（虚构细节属任务本身）。**注入裁决**：是否启用人味注入由文本类型与写作样本决定——有样本时样本优先；无样本时博客/散文/观点/个人写作启用，参考/技术/法律/事实文本**不注入**，只保留既有的人类细节。
4. **匹配作者语气（铁律）**：有写作样本时 MUST 先分析样本（句长/用词/段落开头/标点/重复短语/过渡）再改写，样本优先于默认风格规则；无样本时按文本类型选择语气（博客/散文/个人写作保留个性，参考/技术/法律/事实文本保持中性）。NEVER 用正式词替换随意词，NEVER 删除刻意怪癖。
5. **硬性规则（铁律）**：终稿 MUST 不含 em dash（—）、en dash（–）与中文全角破折号（——）。**判定与处置分层**：单个破折号 NEVER 作为「判定 AI 腔」的证据（见 §误报检查），但处置层不看判定结果——终稿一律移除，除非命中以下三条例外之一：①写作样本使用该标点（按样本频率保留）；②第二手文本内部（引号/标题/专有名词/讨论该短语本身的示例）；③代码块、YAML 元数据、数据、链接目标内部。
6. **误报检查（铁律）**：MUST 按 §误报检查 核对——单个模式出现 NEVER 视为 AI 证据，须多个模式同现才判定；NEVER 把完美语法、正式词、单个过渡词、单个 em dash、单个强调短句等当 AI 腔。保留真实细节（具体不寻常细节/混合感受/时代引用/句长变化/真实题外话）。**注意**：误报检查只裁定「是否判定为 AI 腔」，不豁免模式 N14 的终稿处置要求。
7. **最小化原则**：MUST 只改写本次输入范围内的文本，NEVER 越界改写无关内容；文件模式只改散文，保留代码块、YAML 元数据、数据与链接目标不变。
8. **自检句**：每次操作前 MUST 声明「本次操作=HUMANIZE，触发源=<显式|委派>，已读取<输入文本|写作样本>，输入形态=<粘贴|文件|嵌入>」；与输入冲突时 MUST 停止并纠正，NEVER 擅自继续。

## 职责边界

- **本 skill 负责**：识别并处置 35 种 AI 写作模式；改写 AI 腔文本使其像真人书写；匹配作者语气（有样本时）；误报检查（避免误伤正常写作）；按输入形态返回结果。
- **不负责**：意图识别（由 tri-intent）；产出任何业务作答（由各下游执行 skill）；从零生成文章（由 tri-article / tri-content）；翻译（由 tri-translate）。
- **与 tri-article 的边界**：tri-article 是「去 AI 化技术文章生成器」（从 profile 生成文章）；本 skill 是「去 AI 化改写引擎」（对已有文本改写）。tri-article 可委派本 skill 作为其去 AI 化引擎。
- **与 tri-translate 的边界**：tri-translate 处理跨语言转换；本 skill 处理同语言内的 AI 腔消除。改写不改变语言。
- **与 tri-true 的边界**：tri-true 消除幻觉（事实核查）；本 skill 不核查事实真伪，只保证「不增删事实」（改写不引入/删除来源已有的事实）。
- **MECE 边界**：本 skill 不认领任何 L2 意图编码，不破坏家族下游 skill 的 MECE 划分；属横切关注点，同 tri-cache / tri-evolve / tri-translate / tri-true / tri-cost 同属横向层。
- **不触发场景（Not-Trigger）**：本 skill 不接手「从零创作/内容生成」原文撰写（属 tri-article / tri-content，本 skill 只改写既有草稿）；不接手「事实真伪核查纠错」（属 tri-true，本 skill 只保证不增删事实）；不接手「翻译转换本身」（属 tri-content / tri-translate，本 skill 只做语感改写）；不接手「识别用户意图」（由 tri-intent / 自身 profile 驱动）。

## 去 AI 化改写方法论（核心能力 · 可扩展）

> 去 AI 化改写方法论是 tri-humanize 的核心能力。通过「5 原则速查 → 35 模式精判 → 决策规则处置 → 人味注入 → 三问六检 → 误报检查」六件套，确保 AI 腔文本被改写为真人书写，且不增删事实。

### 核心理念

> **AI 腔不是「写得不好」，而是「太平均」——LLM 用统计算法猜下一个词，结果趋向最可能、最通用的表达。去 AI 化就是打破这种平均，让文本有人的判断与节奏。**

### 核心规则速查（5 条 · 粗筛层）

> 改写前先过这 5 条粗筛，再进 35 模式精判。**粗筛层只负责快速定位，不替代精判**：具体识别信号、IF-THEN 与示例一律以 `references/ai-patterns.md` 为准；本层与 §强制执行契约 冲突时，契约优先。

1. **删除填充短语**——开场白、强调性拐杖词、套娃式修饰，全部删掉。
2. **打破公式结构**——二元对比、戏剧性分段、修辞性设置，改为直陈（关联 N9 / N31 / N34）。
3. **变化节奏**——长短句交错；**两项优于三项**；段落结尾方式多样化（关联 N10）。
4. **信任读者**——直接陈述事实，跳过软化、辩解与手把手引导；不解释隐喻（关联 N23 / N24）。
5. **删除金句**——读起来像可被引用的句子，重写它（关联 N27 / N32）。

### 35 种 AI 写作模式（五类分组）

> 完整决策规则表（每种模式的英文识别信号 / 中文触发词 / IF-THEN 规则 / Before-After 示例 / 误报注意）见 `references/ai-patterns.md`（单一事实源，grep 模式：模式 N1–N35）。概览：

| 类别 | 模式编号 | 一句话识别信号 |
|------|----------|----------------|
| 内容模式 | 1–6 | 夸大重要性 / 点名炫耀 / 浅层 -ing 分析 / 销售语言 / 模糊来源 / 公式化挑战展望 |
| 语言语法模式 | 7–13 | 过度使用 AI 词 / 避免 is-are / Not X but Y / 强行三连 / 改名与重复句首 / 虚假 from-X-to-Y / 被动与缺失主语 |
| 风格模式 | 14–19 | em-en 破折号（硬性）/ 过多加粗 / 加粗小标题列表 / 标题大写 / 表情符号 / 弯引号 |
| 聊天机器人模式 | 20–22 | 残留聊天文本 / 知识截止声明与猜测 / 过度顺从语气 |
| 填充、对冲与结构套路 | 23–35 | 填充短语 / 过多限定词 / 泛泛正面结尾 / 过多连字符 / 假装揭示真相 / 宣布下一点 / 标题重复 / 写旧版本 / 强行笑点 / 公式化谚语 / 假坦诚开场 / 回答无人异议 / 拒绝虚假替代 |

### 决策规则提炼（IF-THEN）

> 每种模式提炼为可执行的 IF-THEN 决策规则（完整 35 条见 `references/ai-patterns.md`）。示例：

| 模式 | IF 观察到 | THEN 处置 | 因为 |
|------|-----------|-----------|------|
| 模式 1 夸大重要性 | 普通细节被描述为「重大变化/遗产/广泛趋势」（pivotal moment, testament, evolving landscape） | 删除夸大，保留事实 | AI 常把普通细节拔高 |
| 模式 4 销售语言 | 广告式词汇描述地点/产品（nestled, breathtaking, vibrant, must-visit） | 删除销售腔，保留事实 | AI 写作常像广告 |
| 模式 14 em dash（硬性） | 文本含 — 或 – | 用句号/逗号/冒号/括号替换或重写 | 终稿硬性规则 |
| 模式 21 知识截止声明 | 出现「as of [date]」「Up to my last training update」或猜测性补全 | 陈述来源未显示的内容或删除句子 | 不把猜测当事实 |

### 优先级排序

1. **硬性规则优先**：模式 14（em dash）为强制，终稿 MUST 不含。
2. **内容模式优先于风格模式**：先处理事实层面的问题（夸大/虚构/模糊来源），再处理表达层面的问题（词汇/标点/格式）。
3. **误报检查兜底**：改写完成后 MUST 按 §误报检查 核对，避免误伤正常写作。

### 权衡取舍

| 对立目标 | 取舍判据 |
|----------|----------|
| 保留信息 vs 精简结构 | 信息优先——可缩短乏味部分、合并段落，但 NEVER 丢失事实 |
| 匹配语气 vs 保持中性 | 有样本时样本优先；无样本时按文本类型（个人写作保留个性，参考/技术/法律保持中性） |
| 主动改写 vs 避免误伤 | 多个模式同现才判定 AI 腔；单个模式出现不判定；保留真实细节 |

### 误报检查（What not to flag）

> 完整清单见 `references/ai-patterns.md` §误报检查。核心：单个模式出现 NEVER 视为 AI 证据，须多个模式同现才判定。以下情况不标记：

- **完美语法与一致风格**：专业人士或被编辑过 ≠ AI。
- **正式/学术词**：模式 7 只针对特定过度使用的词，不简化所有正式词。
- **单个过渡词**：一个 *however* 不是 AI 信号（*Additionally* 等成堆出现才是）。
- **单个 em dash**：编辑与记者常用，只有与公式化销售节奏同现才是**判定**证据。不判为 AI 腔 ≠ 可保留——终稿仍按契约第 5 条处置（例外三条见该条）。
- **单个强调短句**：只有连续多个短片段才是戏剧化。
- **弯引号单独出现**：macOS/Word/Google Docs 默认自动弯引号。
- **有用的限制与免责声明**：范围声明、法律/安全提示、真实更正、具名异议、FAQ 回答。
- **真实替代方案**：设计文档/教程/论证中读者可能考虑的选项。
- **第二手文本**：引号、标题、专有名词、讨论该短语本身的示例中不改写。

### 保留的人类细节（Human details to keep）

> 这些细节常承载作者语气，除非伤害含义否则保留：具体不寻常细节（真实地址/奇怪引语）、混合感受与未解决张力、时代性引用（俚语/梗）、刻意第一人称选择、句长变化、真实题外话/括号/自我纠正。

> **时间锚点**：2022-11-30（ChatGPT 公开上线）之前的编辑内容几乎不可能是 AI 生成的，遇到该日期前的文本时降低判定强度，优先保留原貌。

### 人味注入（加法层 · Voice Injection）

> 删掉 AI 腔只做完一半。无菌、没有声音的写作和机器生成的内容一样明显。本节是**加法**：在确认不增删事实的前提下，补回人的判断、节奏与温度。与上一节互补——保留是防守（已有的别删），注入是进攻（按文本类型按需补）。

**启用判据（与契约第 3 条注入裁决一致）**

| 条件 | 是否启用注入 |
|------|--------------|
| 有写作样本 | **启用**，且严格按样本习惯注入（样本优先于本节默认做法） |
| 无样本 + 博客 / 散文 / 观点 / 个人写作 | **启用** |
| 无样本 + 参考 / 技术 / 法律 / 事实文本 | **不注入**，只保留文本既有的人类细节 |

**注入 6 法**

1. **有观点**——不只是报道事实，对事实做出反应。「我真的不知道该怎么看待这件事」比中立罗列利弊更像人。
2. **变化节奏**——短促有力的句子，接着需要时间展开的长句，混合使用。
3. **承认复杂性**——真实的人有复杂的感受。「这令人印象深刻，但也有点不安」胜过「这令人印象深刻」。
4. **适当用「我」**——第一人称不是不专业，是诚实。「我一直在想……」「让我困扰的是……」表明有真实的人在思考。
5. **允许一些混乱**——完美结构像算法输出。跑题、题外话、半成型的想法是人性的体现。
6. **对感受要具体**——不写「这令人担忧」，写「凌晨三点没人看着的时候，智能体还在不停运转，这让人不安」。

**需要注入的信号（无灵魂迹象）**：句长与结构整齐划一 / 只有中立报道，没有反应 / 不承认不确定性与复杂感受 / 该用第一人称时不用 / 无幽默、无锋芒、无个性 / 读起来像百科条目或新闻稿。

**刹车（硬约束）**

- 只注入**观点、感受、节奏、句式与衔接**；NEVER 注入事实、名称、数字、日期、引用、引文、排名或任何事实性主张。
- 注入后 MUST 重新过一遍处理流程第三问（是否增删事实），任何无来源的事实性添加视为错误并回退。
- 注入 NEVER 覆盖写作样本：样本中刻意保留的怪癖、怪词、不均匀节奏一律不动。

**示例（中文）**

- Before（干净但无灵魂）：实验产生了有趣的结果。智能体生成了 300 万行代码。一些开发者印象深刻，另一些则持怀疑态度。影响尚不明确。
- After（注入后）：我真的不知道该怎么看待这件事。300 万行代码，就那么生成出来了。一些开发者觉得不可思议，另一些在解释为什么这不算数。真相大概落在无聊的中间地带——但我一直在想那些通宵运转的智能体。
- 事实核对：300 万行 ✓、开发者反应分歧 ✓、影响尚不明确 ✓ —— 零增删（新增的只是观点与感受）。

## 处理流程

> 执行顺序固定：§版本检查与更新机制（第零步）→ 上游依赖检测 → 读取输入 → 核心执行。版本检查未通过前 NEVER 进入以下任一执行步骤。

> 轻量工作流，无审批门；按输入形态分三支执行，核心改写流程一致。

### 核心改写流程（HUMANIZE 通用）

1. **接收**：输入文本 + 可选写作样本 + 输出形态
2. **声明自检句**：「本次操作=HUMANIZE，触发源=<显式|委派>，已读取<输入文本|写作样本>，输入形态=<粘贴|文件|嵌入>」
3. **匹配语气**：有样本时先分析样本（句长/用词/段落开头/标点/重复短语/过渡），样本优先于默认风格规则；同时按 §人味注入 启用判据决定是否启用注入
4. **识别模式**：先过 §核心规则速查 5 条粗筛，再对照 35 种模式逐段标记（见 `references/ai-patterns.md`）
5. **写草稿**：朗读检查节奏、细节、简单动词（is/has）、正式度
6. **三问自检（强制）**：
   - **问一（AI 腔）**：还有哪里像 AI 写的？
   - **问二（事实）**：改写是否增删了任何事实 / 名称 / 数字 / 日期 / 引用 / 引文 / 排名 / 其他主张？——任何无来源的添加或丢失的主张都视为错误，MUST 修正
   - **问三（人味）**：启用人味注入时，是否补上了人的判断（观点 / 节奏变化 / 具体感受）？未启用注入时本问不适用
7. **六检（交付前清单，逐条勾选）**：
   - 连续三个句子长度相同？→ 打断其中一个
   - 段落以简洁的单行结尾？→ 变换结尾方式
   - 揭示内容前有破折号？→ 删除（模式 N14 处置层）
   - 在解释隐喻或比喻？→ 相信读者能理解
   - 用了「此外」「然而」等冗余连接词？→ 考虑删除
   - 三段式列举？→ 改为两项或四项
8. **写终稿**：自然陈述每个要点而非逐个修补标记短语；句子别扭时围绕其主要观点重写段落；应用模式 N14 处置层规则（搜索 —、–、—— 并移除，除非命中契约第 5 条三条例外）
9. **误报检查**：按 §误报检查 核对，确认未误伤正常写作、保留真实细节

### 输出形态分流

| 形态 | 返回内容 |
|------|----------|
| **粘贴文本（默认）** | 草稿 + 剩余 AI 模式短清单 + 终稿 + 质量自评（见 §质量自评） |
| **文件模式** | 只写终稿到文件（只改散文，保留代码块/YAML 元数据/数据/链接目标不变），给简短摘要 |
| **嵌入模式** | 只返回终稿（供下游 skill 直接消费） |

### 质量自评（可选输出 · 非门禁）

> 仅在**粘贴模式**输出，文件模式与嵌入模式不输出。自评是给用户感知改写幅度的参考，**不是放行门禁**——评分再低，也 NEVER 反过来放宽事实保真、误报检查与硬性规则；评分再高，也不豁免三问自检。

| 维度 | 评估标准 | 得分 |
|------|----------|------|
| **直接性** | 直接陈述事实还是绕圈宣告？10 分：直截了当；1 分：充满铺垫 | /10 |
| **节奏** | 句子长度是否变化？10 分：长短交错；1 分：机械重复 | /10 |
| **信任度** | 是否尊重读者智慧？10 分：简洁明了；1 分：过度解释 | /10 |
| **真实性** | 听起来像真人说话吗？10 分：自然流畅；1 分：机械生硬 | /10 |
| **精炼度** | 还有可删减的内容吗？10 分：无冗余；1 分：大量废话 | /10 |
| **总分** |  | **/50** |

**档位**：45–50 优秀（AI 痕迹已去除且有人味）/ 35–44 良好（仍有改进空间）/ 低于 35 需重新修订（先查三问自检与误报检查，再重做改写）。

### 完整示例（中文 · 端到端）

**Before（AI 腔）**：

> 新的软件更新作为公司致力于创新的证明。此外，它提供了无缝、直观和强大的用户体验——确保用户能够高效地完成目标。这不仅仅是一次更新，而是我们思考生产力方式的革命。行业专家认为这将对整个行业产生持久影响，彰显了公司在不断演变的技术格局中的关键作用。

**After（去 AI 化 + 人味注入）**：

> 这次更新加了批处理、键盘快捷键和离线模式。我试了一周，批处理是最有用的那个。测试用户反馈偏正面，多数人报告任务完成更快。至于会不会影响整个行业，现在说还太早。

**更改说明（逐条）**：

- 「作为……的证明」→ 删除（N1 夸大重要性）
- 「此外」→ 删除（N7 AI 词）
- 「无缝、直观和强大」→ 删除（N10 强行三连 + N4 销售语言）
- 破折号与「确保……」→ 删除，拆为独立句（N14 处置层 + N3 浅层 -ing）
- 「这不仅仅是……而是……」→ 删除（N9 否定式排比）
- 「行业专家认为」→ 改为「现在说还太早」，不虚构来源（N5 模糊来源 + 问二核对）
- 「关键作用」「不断演变的格局」→ 删除（N7 AI 词）
- 补回具体功能与人的判断（批量处理/快捷键/离线模式 + 「我试了一周」），属人味注入，不含事实性添加

**事实核对**：更新内容三项 ✓、用户反馈正面 ✓、任务完成更快 ✓ —— 零增删；破折号终稿为 0 ✓。
