01心智模型：三句话

① 意图只识别一次

所有提问先过 tri-intent，产出快照交给下游。下游 skill 绝不重新识别意图，只读快照 §三。

② 一切落盘

链路文档进 .tribro/；真实成果物（源码、CHANGELOG）进你的工作区。

③ 闸门优先于速度

「要动手」的 skill 都有审批门。门没过，代码一行不写。想快，就在门上及时回「通过」。

用不好这套 skill 的症状也只有三种：提问太泛（动作无法映射 → 被降级到咨询）、门上一言不发（skill 卡在等你确认）、跳轨（小需求用了重装轨）。后面每条都有对治。

03核心契约：快照 + LATEST 指针（本版未变）

tri-intent 的唯一交付产物是一份快照，快照 §三 是下游 skill 的唯一输入源。

# .tribro/snapshots/I11_20260923_181207_6a5c037d.md

一、用户原始提问（原文，不加工）
二、意图分析过程（L1/L2/D1–D5 逐步判定推导）   ← 溯源用
三、结构化结论（下游 skill 直接读取执行区）   ← 机器消费用

§三 是 YAML 块，核心字段：一句话复述 / intent{L1,L2,L3_子意图,置信度,置信度档位} / dimensions{D1–D5} / 任务要点 / 澄清门状态 / 交付预期 / 下游路由建议 / 下游 slug。

下游按四级优先级定位快照

优先级定位方式说明
①.tribro/LATEST.md 的 snapshot_path推荐路径，最稳
②会话 ID 匹配的最新快照同会话多次提问时用
③全局最新且修改时间 ≤ 30 分钟超时即过期，不得使用
④校验 intent.L2 属于本 skill 认领范围越界即停止并回退重路由
三个直接后果
  • 快照有时效：超过 30 分钟未使用，下游会要求重新识别。别隔夜再喊「继续」。
  • 下游会拒绝越界：快照 L2 与 skill 认领范围不符时它会停下来回退重路由，不会将就。
  • 低置信度不放行：置信度档位=低（<0.60）时下游直接拒绝执行，强制回 clarify-gate。把需求说清楚是省时间的唯一办法。

04版本门：现状与走向（本版重大变化）

每个 skill 启动后的**第零步**都会跑 scripts/check_update.py。本版这一机制有两处结构变化：

变化 1 · 真源改为「每 skill 自带」

上游把版本门细则真源放在 tri-forge/references/version-check-spec.md，而 tri-forge 被上游私有化（.gitignore 显式排除，平台亦未发布）。本仓库为自维护 fork，已自行重建 tri-forge 并改为：

文件角色
<skill>/references/version-check-spec.md该 skill 自带的执行规范（42 份，内容 SHA-256 完全一致）→ 满足「支持独立安装」
tri-intent/references/version-gate.md家族设计总纲（设计原则 / 端点配置真源 / 四处同步点 / junction 例外 / P1–P4）
scripts/check_update.py可执行真源——规范与脚本冲突时以脚本实际行为为准

自带的 spec 已按脚本实际行为校正过上游的 4 处失真：--platform 参数（脚本里没有）、退出码 20/21/22（实际只有 20，P2/P3/P4 靠 block_code）、缓存路径、端点解析条款。

变化 2 · 远端比对已停用（自维护 fork）

四态语义与处置（当前）
态退出码含义
A0校验通过（current ≥ latest）
B10离线降级（网络不可达）
C11通道降级（响应无效 / 读不到配置）
D12升级降级（陈旧且升级未完成）
BLOCK20阻断（block_code = P2 签名不一致 / P3 回滚失败 / P4 通道已证实正常却 5xx）

退出码 <20 一律放行（含 A/B/C/D）；≥20 绝对禁止执行。脚本自身异常兜底降级放行。节流 24h。

已落地：43 份 check_update.py 内置 SELF_MAINTAINED = True，完全跳过远端请求，改为校验本 skill 自身 5 处版本声明是否一致（P1–P5），返回 A（一致，exit 0）/ D（漂移，exit 12）。排障逃生舱：TRI_ALLOW_REMOTE=1 可临时恢复远端比对。

轨道选择决策表

你的需求长相走哪条判据
「写个 XX 功能 / 改一下这个模块」轻轨 tri-coding目标代码不存在，单功能/模块
「PM 给了原型链接，帮我解析后开始编码」tri-prototype → tri-coding有原型链接或 PRD，需先解析成 requirements.md 再进 tri-coding 门②
「先出个方案 / 排个期 / 拆下任务」规划轨 tri-plan只要文档，不要动手
「按完整流程做个项目 / 从零到上线」重装轨 tri-sdlc交付对象是一个真实项目
「设计 CI 流水线 / 审批流 / DAG」tri-workflow交付物是流程定义，交付即结束
「建知识库 loop / 定期跑的循环」tri-loop交付物是长期循环体，无明确终点
「这个报错查一下」tri-fix有可复现故障
「帮我 review / 审一下这次改动」tri-review只看不改
「生成审计清单 / commit 前清单」tri-checklist要可勾选 checklist
「分析项目架构 / 画架构图」tri-html架构可视化
「把某人的方法论做成 skill」tri-god产物是一个可独立调用的 skill
「长期学某门课 / 长期求职辅导」tri-learn / tri-jobhunt领域单入口，不按单次意图
优先级冲突 sdlc 子类最高

三个子类（sdlc / workflow / loop）可能同时命中：sdlc > workflow > loop，最终以「交付对象是一个真实项目 / 一份流程定义 / 一个长期循环体」三者择一。且 sdlc 子类靠任务要点语义触发，不是表层动词。

Step 1 · 把需求说出来（决定命中率）

意图识别的主键是核心动词。动词能映射到具体 I 编码就能精准分派；太泛（「搞定」「搞一下」）会降级为 I03 建议咨询并强制先澄清。

优化一下优化一下这段 SQL 的查询性能（附代码）动作明确但对象缺失 → 不降级，但会先澄清对象
把这份 PDF 转成 MD把这份合同 PDF 提取成 Markdown（附文件）已补装 tri-pdf2md，该子类路由现可正常落地（不会停在安装门）

补充维度能显著提升质量：说明任务领域、是否有素材、要多细、期望什么形态。这些写进快照 D1–D5，下游按它调整策略。

Step 2 · 被澄清时

反问模式: G1 苏格拉底式(引导) 或 G2 批判式(挑刺)
初步理解: 你想做数据看板，但没说给谁看、看哪些指标

回复方式: 逐条补充 | 回「按默认」全采纳 | 「继续」表示无需澄清

Step 3 · 识别与落盘

每个 skill 作答前会打一行自检句，这是判断「它有没有跑对」的窗口：

Step 4 · 选轨道并确认

门的三种结果
  • 通过 → 阶段置「已通过」，进入下一阶段
  • 打回 + 说清哪里不对 → 携修订意见回炉该阶段，轮次+1
  • 回退 说「回退到 Pn」→ 级联重置：Pn 之后全部置「未开始」，已产出物标 stale

反规避规则（对你有保护）：门禁不因「用户着急」下调标准；也不由编排器代笔补全交付物——补全必须回炉给对应子 SKILL。所以门上说「快点过」无效，真正快的方式是把需求一次说清，减少回炉轮次。

Step 6 · 执行后加装验证

想加什么在哪加怎么加
代码审查门③「执行前确认」被问到①是否调其它 skill 协同 → 答「调 tri-review」

成本审计对话过长 / 关心开销时tri-cost 统计全过程 token 开销，可设预算闸门
skill 安全审计安装任何 skill 前tri-guard 委派 skillspector 确定性扫描
去 AI 化改写成稿后tri-humanize：5 条速查 + 35 种模式 tri-article 已内置委派

tri-fix 值得单独记住：第一性规则是「没有能变红的反馈循环，就没有假设阶段」。在一条你真实跑过、且在这个 bug 上失败的命令出现之前，它只允许做一件事：构造这条命令，不会凭代码阅读跳到根因。构造不出循环时它会停下来向你要三样之一：环境访问权 / 抓取产物（HAR、日志转储、core dump、带时间戳录屏）/ 临时生产插桩许可。

tri-review v1.6.0 也变强了：除 Phase 0/1/2 与 Fowler 12 坏味外，新增覆盖度账本（双源分离 + gaps）、反证据关闭门、严重度校准 rubric，以及审查执行纪律八则（确定性验证 / 非对称复核 / 证据锚降级 / 分桶 / 预分析 / 注入防线 / 覆盖收尾 / 超限恢复）。

Step 7 · 沉淀（可选，复利最高）

  • tri-cache v2.1.1 提供四层缓存（滑动窗口 / 结构化存储 / 轻量摘要 / 向量检索）+ 上下文压缩。I11/I12/I17–I20/M01–M04 不缓存（代码和故障会变）。
  • tri-evolve 从外部信号归因学习。改 skill 核心契约属高风险须人工审批；经验沉淀过 A/B 验证门（lift ≥5%，p<0.05）。
  • tri-god：说「把这套流程做成 skill」→ 识别蒸馏对象类型 → 加载方法论 → 双门 → 产出 skill。
