# tri-ask

咨询作答下游执行 skill。读取 tri-intent 快照 §三 结构化结论，处理 I01–I05（信息查询 / 概念解释 / 建议咨询 / 决策辅助 / 推理计算）咨询求解类意图，产出知识、建议、判断或推理结果。当 tri-intent 快照下游路由建议指向本 skill 时激活。

本 skill **仅负责依据快照作答**，不重新识别意图（由 tri-intent）、不产出 Doing 类文本成果物（由 tri-content）、不产出编码/调试结果（由 tri-coding）。核心理念：**不同子意图需要不同的作答结构，但来源诚实是统一底线。** 作答内容即时对话回应，不落盘。

## 特性

- **5 子意图差异化作答策略**：I01 给事实性回答 / I02 分层讲解 / I03 给可执行建议+依据 / I04 列利弊+倾向性结论 / I05 展示推导过程，按 L2 路由到对应策略，NEVER 用统一模板套用
- **事实性主张来源标注**：涉及数据、引文、版本号、法规条款、API 签名等事实性主张 MUST 标注来源；无法核实的显式标注「未核实」，NEVER 编造来源
- **任务要点全覆盖核对**：作答 MUST 覆盖快照 `任务要点` 的全部条目，信息不足的条目显式标注「该条信息不足」+ 缺失信息说明
- **格式合规（D4 约束）**：作答 MUST 遵守快照 `D4_输出期望`（简答/长文/分步指引）与 `D4_格式约束`（表格/分点/字数限制），NEVER 自行变更格式
- **轻量无审批门**：单轮作答即交付，无审批门、无链路文档，作答内容即交付物
- **独立安装两态依赖检测**：支持快照模式 / 引导安装，不支持降级模式（模式 B 为硬性阻断）

## 安装

将 `tri-ask/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-ask/ /path/to/your/skills/
```

本 skill 可独立安装。激活时检测上游 tri-intent skill 是否可用，据检测结果选择执行模式：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| A · 快照模式 | `.tribro/snapshots/` 有快照 或 skills 目录有 `tri-intent/` | 读取快照 §三，按工作流推进（标准模式） |
| B · 引导安装 | 以上均不满足 | 向用户提示依赖并引导安装 `skillhub install tri-intent` |

> 本 skill 不支持降级模式——模式 B 为硬性阻断，MUST 安装 tri-intent 后方可使用。

## 使用

### 核心流程

收到 tri-intent 快照且 `下游路由建议` 指向本 skill 后，按以下链路推进：

```
读取快照 §三 (L2 ∈ I01–I05)
        │
        ▼
  按子意图选择作答策略
  · I01 事实性回答 / I02 分层讲解
  · I03 可执行建议+依据 / I04 利弊+倾向结论 / I05 推导过程
        │
        ▼
  组织输出
  · D4_输出期望 → 简答/长文/分步指引
  · D4_格式约束 → 表格/分点/字数限制
  · 事实性主张标注来源
        │
        ▼
  任务要点覆盖核对
  · 逐项核对清单，信息不足显式标注
        │
        ▼
  交付（即时对话回应，不落盘）
```

### 子意图作答策略表

| 子意图 | 作答策略 | 结构要求 | 来源标注 |
|---|---|---|---|
| I01 信息查询 | 检索/调用知识，给事实性回答 | 直接结论 + 关键事实 +（可选）背景 | 事实性主张 MUST 标注来源 |
| I02 概念解释 | 分层讲解，由浅入深 | 一句话定义 → 核心要点 → 进阶展开 →（可选）类比 | 概念出处可标注 |
| I03 建议咨询 | 给可执行建议，说明依据 | 建议清单（动作 + 依据 + 适用前提） | 依据 MUST 标注来源 |
| I04 决策辅助 | 列利弊/风险，给倾向性结论 | 选项表（利/弊/风险）+ 倾向结论 + 理由 | 事实性论据 MUST 标注来源 |
| I05 推理计算 | 展示推导/计算过程 | 已知条件 → 推导步骤 → 中间结果 → 结论 | 公式/算法出处可标注 |

### 落盘规则

- 快照由 tri-intent 已落盘于 `.tribro/snapshots/`
- 本 skill 为轻量咨询作答，作答内容**不落盘**（即时对话回应）
- 若用户明确要求保存作答内容 → 按用户指定路径落盘（非 .tribro/）

## 测试

完整测试用例见 `tests/tri-ask-full-testcases.md`，覆盖 5 子意图作答策略、事实性主张来源标注、任务要点全覆盖核对、格式合规（D4 约束）、轻量无审批门、上游依赖检测两态逻辑等全部能力点。

## 设计原则

- **子意图差异化**：5 个子意图各有独立作答策略与结构要求，NEVER 用统一模板套用所有子意图
- **来源诚实**：事实性主张 MUST 标注来源，无法核实显式标注「未核实」，NEVER 编造来源
- **覆盖完整**：`任务要点` 全部条目 MUST 有对应作答，信息不足显式标注而非跳过
- **职责边界**：仅依据快照作答咨询求解类意图，不越界产出 Doing 类文本成果物
