# tri-plan

规划拆解下游执行 skill。读取 tri-intent 快照 §三 结构化结论，处理 I13（规划拆解）意图，自主管理「规划纲要 → 完整规划 → 任务清单」完整规划工作流。融合 WBS 分解与 SMART 目标校准方法论，含三门审批机制（规划方向确认 + 规划审计 + 交付前确认）。当 tri-intent 快照下游路由建议指向本 skill 时激活。

## 特性

- **三门审批机制**：门①规划方向确认 → 门②规划审计 → 门③交付前确认，三道关卡严格串行，禁止跳门直接给计划
- **WBS 任务分解（MECE 原则）**：目标 → 阶段 → 任务 → 子任务逐层分解，同层任务之和 = 父项全部范围，无遗漏无重叠
- **SMART 目标校准**：5 维度校准（明确/可度量/可达/相关/有时限），目标含糊时 MUST 在门①澄清
- **依赖图无环校验**：4 种依赖类型标注（FS/SS/FF/外部），判定由 `scripts/dep_lint.py` 实跑拓扑排序完成，检出环/自环/悬引用时退出码 1 并给出环路径
- **风险登记**：每个风险 MUST 有缓解措施，高可能性+高影响风险 MUST 有应对策略
- **两态依赖检测**：独立安装时支持快照模式 / 引导安装，不支持降级模式（硬阻断）

## 安装

将 `tri-plan/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-plan/ /path/to/your/skills/
```

> 本 skill 依赖 tri-intent 进行意图识别与输入校验。若未安装 tri-intent，激活时为硬性阻断，必须安装后方可使用（不支持降级模式）。

## 使用

### 1. 规划工作流（核心流程）

收到 tri-intent 快照（L2 = I13）后，按以下链路串行推进：

```
快照 §三 → plan-brief.md → 门①确认 → plan.md → 门②审计 → task-checklist.md → 门③交付前确认 → 交付
```

> **核心铁律**：没有明确的目标与验收标准，就没有任务拆解——目标含糊时拆得越细越偏离。

| 阶段 | 产出物 | 审批门 | 关键动作 | 回炉规则 |
|---|---|---|---|---|
| 1 | `plan-brief.md` | 门① | 从快照 §三 提取目标/范围/约束；SMART 校准 + 验收标准骨架 + 里程碑草案 | — |
| 2 | `plan.md` | 门② | WBS 分解（目标→阶段→任务）+ 依赖图 + 里程碑 + 风险登记 + 验收标准 | 门①未过则回炉 plan-brief |
| 3 | `task-checklist.md` | 门③ | 据 plan.md 产出可执行任务清单 + 逐项验收标准 + 依赖标注 | 门②未过则回炉 plan.md |
| 4 | 规划成果物 | — | 交付 plan.md + task-checklist.md，复选框标记交付确认 | 用户补充约束则回炉 task-checklist |

### 2. 目标拆解方法论

基于 WBS + SMART 方法论，形成「目标 → 阶段 → 任务 → 验收标准 → 风险」的结构化拆解：

- **SMART 校准**：Specific / Measurable / Achievable / Relevant / Time-bound
- **WBS 分解原则**：可独立执行 / 粒度适中 / 100% 覆盖（MECE）/ 验收可判
- **依赖关系标注**：FS（→）/ SS（⇒）/ FF（⇐）/ 外部依赖（⇢），填完跑 `python scripts/dep_lint.py <plan.md>` 做无环校验
- **风险登记**：每个风险有缓解措施，高可能性+高影响风险有应对策略

### 3. 交付产物

链路文档落盘于 `.tribro/plans/<命名>/`，命名沿用 tri-intent 快照：

```
.tribro/plans/I13_20250211_143022_6a5c037d/
├── plan-brief.md
├── plan.md
└── task-checklist.md
```

## 设计原则

- **目标先行**：没有明确的目标与验收标准就没有任务拆解，目标含糊时 MUST 在门①澄清
- **只出方案不动手**：本 skill 只产出计划/方案/任务清单，不写代码不执行操作；编码实现归 tri-coding，操作执行归 tri-action
- **MECE 分解**：同层任务互斥穷尽，无遗漏无重叠，依赖关系无环
- **可扩展方法论**：新增拆解维度/依赖类型/风险维度无需修改核心工作流，模板自动对齐
