# 信息架构方法论对比与选型（ia-methods）

> tri-wiki 门A（信息架构设计）的唯一事实源。新增方法论时追加一节 + `organize.py` 的 `METHOD_PRESETS` 追加预设。
> grep 检索模式：`PARA` / `JD` / `MOC` / `主题` / `选型`。

## 一、方法论总览对比

| 维度 | 主题树+MOC（默认） | MOC-only | PARA | Johnny Decimal |
|---|---|---|---|---|
| 核心逻辑 | 目录按主题分层 + 每主题 MOC 索引页 | 无目录语义，全靠 MOC 索引 | Projects/Areas/Resources/Archives 四类 | 两级编号 10 大类×10 子类 |
| 结构刚性 | 中 | 低（涌现式） | 中（四类固定） | 高（严格编号） |
| AI 自动化友好度 | 高 | 高 | 高（分类规则明确） | 高（编号可规则化） |
| 适合场景 | 通用（可浏览+可发现） | 研究型/链接密集 | 项目驱动型 | 文件量大、快速定位 |
| 学习曲线 | 低 | 中 | 低 | 中 |
| tri-wiki 预设名 | `topic-moc` | `moc-only` | `para` | `jd` |

## 二、各方法论目录骨架（organize.py METHOD_PRESETS）

### 2.1 topic-moc（默认）

```
<库名>/
├── index.md                # 库总览（说明/统计/MOC 入口）
├── tags.md                 # 标签聚合页
├── 00-Inbox/               # 未分类/低置信度/近重复待仲裁
├── <主题1>/                # 主题目录（名由门A 主题词表确认）
│   ├── <主题1>-MOC.md      # 主题内容地图（条目+简介+相关链接）
│   └── <标题>.md           # 入库笔记
├── <主题2>/…
├── 90-attachments/         # 图片等附件
└── .wiki-meta/             # 构建清单（源→产物映射）
```

### 2.2 moc-only

无主题目录——全部笔记平铺 `notes/`，导航完全由 `index.md` + 各 MOC 承担。适合笔记间链接密度高的研究型库。

### 2.3 para

```
<库名>/
├── index.md
├── 10-Projects/   # 有截止日期的短期目标
├── 20-Areas/      # 持续维护的标准领域
├── 30-Resources/  # 主题素材库
├── 40-Archive/    # 已完成/不活跃
└── 90-attachments/
```

### 2.4 jd（Johnny Decimal）

```
<库名>/
├── index.md
├── 10-19_<大类1>/    # 大类语义名
│   ├── 11.01-<条目>.md
│   └── 11-<子类说明>.md
├── 20-29_<大类2>/…
└── 90-99_Meta/
```

两级编号最大深度 2 层；编号不表语义，语义放子类说明页。

## 三、选型决策（门A 澄清依据）

| 用户信号 | 推荐方法论 |
|---|---|
| 「文档资料库/团队文档/说明书集合」 | topic-moc |
| 「研究笔记/读书笔记/想建知识网络」 | moc-only 或 topic-moc |
| 「按项目组织/项目完成后归档」 | para |
| 「文件特别多/要快速编号定位」 | jd |
| 未表达偏好 | topic-moc（默认） |

## 四、命名规范（全方法论通用）

| 对象 | 规则 | 示例 |
|---|---|---|
| 笔记文件 | `<主题>-<标题>.md`（topic-moc）；中文标题保留 | `后端-Koa中间件机制.md` |
| 拆分子页 | `<标题>-<序号两位>-<H2标题>.md` + 父页 `<标题>.md` | `Koa指南-03-错误处理.md` |
| 主题目录 | 中文语义名（topic-moc）；保留位 `00-`/`90-`/`99-` | `00-Inbox`、`90-attachments` |
| 日期 | ISO 8601（`YYYY-MM-DD`） | `2026-08-24` |
| 禁止 | 空格开头/结尾、`\/:*?"<>|`、超过 80 字符 | — |

## 五、标签体系（门A 确认）

- 标签 = 主题词表（一级，与目录对齐）+ 内容标签（二级，自由扩展，建议 ≤5 个/笔记）。
- 主题词表 + 别名表在 build-plan.md 锁定；门D/E 分类与链接匹配 MUST 对齐词表（同主题多称谓经别名表归一）。
- 状态标签：`seedling`（萌芽）/`budding`（成长）/`evergreen`（常青）——数字花园三级状态，写入 frontmatter `status`。
