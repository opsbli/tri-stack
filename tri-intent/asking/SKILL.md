# Asking 咨询求解（二级路由 I01–I05）

用户心智：**「我不知道/不确定，请你告诉我」**。产出是知识与判断，非成果物。

## 二级判定

| 意图 | 一句话信号 | skill |
| --- | --- | --- |
| I01 信息查询 | 要客观事实/数据/现状 | `I01-info-query` |
| I02 概念解释 | 要理解原理/为什么 | `I02-concept-explain` |
| I03 建议咨询 | 开放问题求做法/方案 | `I03-advice` |
| I04 决策辅助 | 已知选项间做取舍 | `I04-decision` |
| I05 推理计算 | 需多步推导/计算出正解 | `I05-reasoning` |

## 消歧口诀

- 要**事实**→I01；要**懂**→I02；要**怎么做**→I03；要**选哪个**→I04；要**算/推**→I05
- 信息不足或过于模糊 → 先激活 `../clarify-gate`

## Asking 交付模板（咨询求解专属 · 识别结果结构化呈现）

> 咨询类核心审计点：**问对了没有、答案要多深、可信度要求**。填充后交付用户确认。

```yaml
# ===== Asking 意图确认卡 | 回复「确认」开答，或「修改：…」=====
你的问题: <复述用户的问题，如「你想知道 RAG 和微调怎么选」>

intent:
  L2_核心意图: <I01 信息查询|I02 概念解释|I03 建议咨询|I04 决策辅助|I05 推理计算>

问题解析:
  已知条件: <用户已提供的前提/约束，无则填 无>
  求解目标: <用户到底想得到什么答案>
  选项集合: <仅 I04 填：待取舍的候选项列表；其余填 不适用>

回答规格:
  深度: <速览要点 | 详解原理 | 深度论证>
  D1_领域: <编程|学习|商业|科研|生活|…>
  可信度要求: <需权威来源核实 | 常识即可 | 需展示推导过程>
  篇幅: <一句话 | 短段落 | 长文>

待确认项: <问题里模糊/歧义处，全清晰填 无>
交付预期: <如：给出对比表 + 场景化选型建议>
# ===== 填入快照 snapshot.md §三，作为下游 skill 的交接输入。可选向用户轻量复述一次，原则上无需再次确认 =====
```

- 命中 `待确认项` 或 D5 模糊 → 先走 `../clarify-gate`
