| 场景 | 规则 | 示例 |

### F. Flow 三态判定

| Flow | 适用意图 | 行为 |
|---|---|---|
| 落盘快照 | I01-I16, M01-M04 | 产出 `.tribro/snapshots/<命名>.md`，交接下游 skill |
| 不落盘 | I17-I20, M05 | 直接自然回应，不生成快照 |
| 先澄清 | clarify-gate 命中（Expressing 例外） | 先反问补齐再识别产出快照 |

### G. Expressing 例外

I17-I20 即使 Gate=是，也仅在对话内对齐设定，Flow 仍为「不落盘」。

### H. 多意图消歧

一句含多意图时，取「最终期望产出」为主意图，其余降为辅助标签。

### I. 边缘兜底

无法归入任一 I/M 项的输入 → 落 I19 闲聊娱乐，保证 MECE 完全穷尽。

### J. 快照产出机制

| 能力点 | 规范 |
|---|---|
| 命名 | `<问题类型>_<YYYYMMDD>_<HHMMSS>_<会话ID前8位>.md` |
| 目录 | `.tribro/snapshots/`（不存在则先创建） |
| 唯一交付 | 禁止产出 requirements.md/design.md/tasks.md/implements.md/reports.md |
| 内容三段式 | ① 用户原始提问 ② 意图分析过程 ③ 结构化结论（含下游路由建议） |

### K. intent-gate 轻量复述

| 能力点 | 规范 |
|---|---|
| 可选调用 | 不调用也能直接交接下游 skill |
| 不设审批门 | 复述仅供发现明显误识别，非执行前置审批 |
| 修正机制 | 用户指出误识别 → 追加「修正」段落，不覆盖原快照 |
| 可跳过 | 当 clarify-gate 已完成澄清时连复述都可跳过 |

## 一、判定字段说明

| 字段 | 含义 | 判定标准 |
|---|---|---|
| **L1** | 第一层大类 | 必须完全一致（A/B/C/Meta） |
| **L2** | 二级意图编码 | 必须一致（如 I08）；边界用例允许「主意图一致，辅助意图不计分」 |
| **Gate** | 是否触发 clarify-gate | 一致（是/否） |
| **Flow** | 落盘去向 | 一致（**落盘快照** / **不落盘** / **先澄清**），与 `hooks/intent-gate.py` 保持单一事实源。Gate=是的用例 Flow 记为「先澄清」，Expressing 例外记为「不落盘」 |
| **D1-D5** | 正交维度标注 | 维度专项用例须逐维度比对；其余用例不强制比对 |
| **Route** | 下游路由建议 | 产出物专项须比对；其余用例不强制比对 |

## 二、评分规则

- 每条用例核心字段（L1/L2/Gate/Flow）全部命中记 **PASS**，任一不符记 **FAIL**
- 维度标注专项额外比对 D1-D5，降级/产出物/复述专项比对对应附加字段
- 通过率 = PASS 数 / 总用例数
- **质量门槛**：正常场景 ≥95%、消歧场景 ≥90%、异常场景 ≥90%、边界场景 ≥80%，整体 ≥90% 视为达标
