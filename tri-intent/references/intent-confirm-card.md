# 意图确认卡（通用主模板 · 完整参考）

> **用法**：意图识别完成后，用识别结果填充下方模板，作为快照 §三 结构化结论区的内容。
> - 对**用户**：用「一句话复述」+「待确认项」让用户 3 秒看懂自己的需求
> - 对 **LLM**：`intent` / `dimensions` 等结构化字段可被下游 skill 直接读取执行，**无需再次意图识别**
> - 各分类目录下有该组的**专属细化模板**（`asking/` `doing/` `expressing/` `meta/`），字段更贴合场景，**优先使用专属模板**
>
> 📖 本文件为 `SKILL.md` §意图确认卡 的展开参考，两者冲突时以本文件为准。

## 一、完整 YAML 模板

```yaml
# ===== 意图确认卡 v2 | 填入快照 §三，可选向用户轻量复述一次 =====
一句话复述: <用第一人称复述用户真实需求，如「你想让我把这份 PDF 报告翻译成英文」>

intent:                       # 机器执行区（下游 skill 直接据此执行，不再重新识别）
  L1_交互类型: <A.Asking | B.Doing | C.Expressing | Meta>
  L2_核心意图: <如 I08 翻译转换；代码审查填「代码审查(CR)」>
  L3_子意图: <仅子类路由时填：sdlc | workflow | loop | music | article；无子类填 无>
  辅助意图: [<可选，其余降级意图编号>]
  置信度: <0–1 两位小数，如 0.92>
  主次分差: <与最高辅助意图的差值，无辅助意图填 1.00>
  置信度档位: <高(≥0.85) | 中(0.60–0.85) | 低(<0.60)>

dimensions:                   # 第三层正交标签（缺失填 未指定）
  D1_任务领域: <办公|学习|编程|生活|创作|商业|情感|科研|未指定>
  D2_输入形态: <文本|代码|图片|文档|表格|音视频|链接|无>
  D3_交互轮次: <单轮|多轮|长程Agent>
  D4_输出期望: <简答|长文|结构化数据|可执行代码|文件产物|分步指引>
  D4_格式约束: <表格/分点/字数限制，无则填 无>
  D5_确定性: <明确|模糊|开放>

任务要点:                     # 用户可读 + LLM 可执行的具体化需求
  - <拆解出的关键要求 1>
  - <关键要求 2>

澄清门状态: <已跳过(需求清晰) | 已澄清(附结论) | 待澄清(附反问)>
待确认项:                     # 仅列不确定处，让用户补齐；全清晰则填 无
  - <如：目标读者是谁？输出多长？>
交付预期: <一句话说明用户期望的最终交付物>
下游路由建议: <基于 L2 意图给出下游 skill 路由建议，须与 §路由映射表 一致>
下游 slug: <实际 skill 目录名，如 tri-fix，供下游依赖检测直接消费>
# ===== 填入快照 snapshot.md §三，作为下游 skill 的交接输入。可选向用户轻量复述一次，原则上无需再次确认 =====
```

## 二、填充规则

1. **必填不留空**：所有字段必须有值，无信息填「未指定/无」，禁止 `<...>` 占位残留
2. **复述先行**：`一句话复述` 必须用用户能秒懂的自然语言，是审计的第一入口
3. **机器区自洽**：`intent` + `dimensions` 组合须能让下游 skill 无歧义执行，不依赖上下文重新判定
4. **澄清优先**：`D5=模糊/开放` 或有 `待确认项` 时，`澄清门状态` 必须为「待澄清」并先反问

## 三、字段与下游消费对照

| 字段 | 消费方 | 说明 |
|---|---|---|
| `一句话复述` | 用户 | 轻量复述的主体内容，供发现明显误识别 |
| `intent.L2_核心意图` | 下游 skill | 认领范围校验主键，越界即回退重路由 |
| `intent.L3_子意图` | 下游 skill | 子类路由标记（sdlc / workflow / loop / music / article） |
| `intent.置信度档位` | 下游 skill | 低档不得执行，详见 `references/confidence-mechanism.md` |
| `dimensions.D1–D5` | 下游 skill | 执行策略与格式约束依据 |
| `任务要点` / `交付预期` | 下游 skill | 产出范围与验收基线 |
| `下游路由建议` / `下游 slug` | tri-intent 下游检测 | 依赖检测与安装引导的目标 |
