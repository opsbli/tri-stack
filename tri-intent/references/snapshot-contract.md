# 快照定位契约与异常处置（下游 skill 必读 · 完整参考）

> 快照「永不覆盖」会导致目录持续堆积，且文件名含会话 ID——下游 skill 无法凭空推算该读哪个文件。
> 故 tri-intent MUST 在落盘快照的**同时**维护指针文件，下游 skill 按下列**优先级顺序**定位快照。
> 📖 本文件为 `SKILL.md` §快照定位契约 的展开参考，两者冲突时以本文件为准。

## 一、定位优先级（四级，自上而下）

1. **指针优先**：读取 `.tribro/LATEST.md`，取其中 `snapshot_path` 字段指向的文件（推荐路径）。
2. **会话内最新**：若指针缺失，取 `.tribro/snapshots/` 下**文件名会话 ID 段匹配当前会话**且
   `<日期>_<时间>` 最大的文件。
3. **全局最新**：若无法获知当前会话 ID，取 `.tribro/snapshots/` 下 `<日期>_<时间>` 最大的文件，
   且其修改时间距今 **≤ 30 分钟**；超时视为过期快照，不得使用。
4. **意图校验**：读到快照后 MUST 校验 §三 `intent.L2_核心意图` 是否属于本 skill 认领范围；
   越界则停止执行并回退 tri-intent 重新路由，NEVER 强行按越界快照执行。

## 二、LATEST.md 最小格式

> tri-intent 每次落盘快照后**覆盖写**该文件。

```yaml
snapshot_path: .tribro/snapshots/I11_20250211_143022_6a5c037d.md
intent: I11
route_slug: tri-coding
confidence: 0.92
generated_at: 2025-02-11 14:30:22
session_id: 6a5c037d
```

## 三、快照异常处置（下游 skill 统一约定）

| 异常情形 | 判定条件 | 处置动作 |
|---|---|---|
| **快照缺失** | 指针与目录均无可用快照 | 转入自身「引导安装 / 降级模式」，NEVER 静默按空上下文执行 |
| **快照过期** | 全局最新快照修改时间距今 > 30 分钟 | 视同缺失，提示用户重新发起意图识别 |
| **快照损坏** | 无 §三 区块，或 YAML 无法解析 | 报告损坏文件路径，回退 tri-intent 重新产出，不做猜测性修补 |
| **字段不全** | `L2_核心意图` / `任务要点` / `下游路由建议` 任一缺失或残留 `<...>` 占位 | 缺 `L2` → 回退重新识别；缺其余字段 → 就该字段走一次澄清补齐后继续 |
| **意图越界** | `L2` 不属于本 skill 认领范围 | 停止执行，回退 tri-intent 重新路由 |
| **低置信度** | `置信度档位` = 低 | 不执行，提示先经 clarify-gate 澄清 |

## 四、模式判定速查（下游 skill 上游依赖检测）

> 各下游 skill 的「上游依赖检测」三态（A / A0 / B / C）与本契约的对应关系：

| 模式 | 本契约中的对应情形 | 下游行为 |
|---|---|---|
| **A · 快照模式** | 一~三级定位命中可用快照 | 读取 §三，按标准工作流推进 |
| **A0 · 待识别** | 存在 `tri-intent/` 但快照缺失/过期/损坏 | 提示「本次请求尚未经意图识别」，引导先经 tri-intent |
| **B · 引导安装** | 未检测到 `tri-intent/` | 提示 `skillhub install tri-intent` |
| **C · 降级模式** | 用户明确拒绝安装 tri-intent | 自构造等价输入并显式声明降级 |
