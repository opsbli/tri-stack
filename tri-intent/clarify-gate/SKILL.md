# 澄清对齐门（Clarify Gate · AI 主动反问）

> **方向**：AI→用户（主动反问）。与 M01 澄清追问（用户→AI 求解释）方向相反，勿混。
> **定位**：横切所有意图的前置门，命中则先澄清后执行。

## 两种反问模式

### G1 苏格拉底式反问（引导澄清）

- **触发**：命中 D5 模糊探索/开放发散，或缺关键输入（目标、约束、边界不清）
- **做法**：连续、递进地追问，引导用户说清**目标 / 约束 / 边界 / 期望产出**
- **语气**：启发式、协作式，不预设答案
- **典型场景**：「帮我做个方案」（没说什么方案、给谁、要多细）

### G2 批判式反问（挑刺质疑）

- **触发**：需求存在**矛盾 / 冲突 / 不合理 / 关键要素缺失 / 不可行项**
- **做法**：站在批判者视角，质疑假设与逻辑、指出冲突、找出遗漏项与潜在错误
- **语气**：直接但建设性，帮用户明确并修正任务
- **典型场景**：需求内部自相矛盾、技术上不可行、关键前提缺失

## 门控规则

1. **判定**：路由前先扫描是否命中 G1/G2 触发条件
2. **命中→反问**：抛出聚焦问题（一次一个焦点，避免连环轰炸）
3. **等补充**：用户补齐信息
4. **达标→继续**：信息充分后回到原意图执行
5. **充分→跳过**：需求本身清晰完整则不反问，直接进入意图识别

## 语义拷问（自然语言词 → 可判定断言 · G2 子规则）

> **来源**：tri-stack-train M4b 实证——FR 用「内嵌」一词，clarify-gate 只问了 UI 位置 / User-Agent / 存储
> 三个**参数**，从未问「内嵌 = 主窗口内嵌还是独立窗口」；agent 按「独立窗口」交付，门④ 标
> 「⚠️ 部分通过」仍判交付完成。失败模式不是「问得少」，而是**问的层次错：只拷问参数，从不拷问语义**。

- **触发**：需求 / 验收标准中出现**无法机器判定的定性词**（内嵌 / 可交互 / 优雅降级 / 自动 / 实时 / 轻量 / 无缝 / 直观 / 友好 / 快速 …）
- **做法**：逐词产出「**词 → 可判定断言**」映射，作为 G2 反问的**必答项**交用户确认：
  - 每个定性词 MUST 落为一句可观测陈述——DOM 选择器+断言 / IPC 事件名+期望 payload / 进程退出码 / 面板挂载位置 / 可测阈值，**至少其一**
  - 映射表随澄清反问卡一并呈现，用户逐词确认后才算语义达标
- **禁止**：NEVER 用「参数已澄清」代替「语义已澄清」——只问 UI 位置 / 依赖选型 / 存储位置，不构成对定性词的拷问
- **判定顺序**：语义拷问**先于**参数澄清；定性词未译出可判定断言时，NEVER 进入下游交付

**与 G1/G2 的关系**：语义拷问是 G2 的子规则——当模糊项不是「缺信息」而是「用词歧义」时走 G2 而非 G1。

## 与 M01 的正交说明

| 维度 | clarify-gate | M01 澄清追问 |
|------|--------------|--------------|
| 发起方 | AI 主动 | 用户主动 |
| 方向 | AI→用户 | 用户→AI |
| 目的 | 对齐任务再执行 | 用户求解上一轮回复含义 |

## 澄清反问模板（对齐门专属 · AI→用户 交付）

> 与其他模板方向相反：这是 **AI 抛给用户** 的反问卡，用于收集缺失信息。特点：**聚焦、少而精、带建议默认值**，降低用户回答成本；用户补齐后回填意图确认卡再执行。

```yaml
# ===== 澄清对齐卡 | 请补齐下列信息，或回复「按默认」=====
反问模式: <G1 苏格拉底式(引导) | G2 批判式(挑刺)>
初步理解: <复述当前对需求的理解，如「你想做数据看板，但没说给谁看、看哪些指标」>

需澄清项:                     # 一次只列真正阻塞执行的关键项，≤3 条
  - 问题: <如：目标用户是谁？>
    为何要问: <缺它会导致什么偏差>
    建议默认: <给一个合理默认值，用户可直接采纳>
  - 问题: <…>
    为何要问: <…>
    建议默认: <…>

发现的问题: <仅 G2：矛盾/不可行/遗漏项，如「你要求实时且零成本，二者冲突」>

回复方式: <逐条补充 | 回「按默认」全采纳建议值 | 「继续」表示无需澄清>
# ===== 用户补齐后：回填对应意图确认卡字段 → 填入快照 snapshot.md §三 → 交接下游 skill =====
```

### 门控使用规则

1. **少打扰**：`需澄清项` ≤3 条，只问阻塞执行的关键信息，非关键的用 `建议默认` 兜住
2. **给默认值**：每项都提供合理默认，让用户可「一键按默认」，最小化交互成本
3. **G1 vs G2**：信息不足用 G1 引导补全；需求有矛盾/风险用 G2 直接点破
4. **回填闭环**：用户补齐后，将答案回填到 asking/doing/… 对应意图确认卡，再交付执行
5. **达标即停**：信息一旦充分立即结束反问，不为澄清而澄清
