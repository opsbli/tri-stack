# 需求文档审核判据（八维 · D1–D8）

> **本文件是 tri-req-audit 本地校验与兜底审核的判据单一事实源。**
> 判定 MUST 逐维执行，不得跳维；每维 MUST 给出证据位置（章节号 / 表格行 / 原文片段）或明确「本维通过」的理由。
> 分级判据（P0/P1/P2）唯一真源见 §四，SKILL.md 内的同名表为速查。

---

## 一、审核对象结构基线（tri-prototype 的 `requirements.md`）

| 序 | 章节 | 关键字段（非空校验） |
|---|---|---|
| 一 | 项目概述 | 项目名称 / 项目背景 / 目标用户 / 核心价值 / 原型来源 / PRD 来源 / 解析保真度 |
| 二 | 功能需求 | 每条：功能名称 / 描述 / 优先级 / **出处** / **验收标准** |
| 三 | 页面清单与交互规则 | 每页：页面名称 / 路由 / 组件列表 / 交互规则；含「全局交互」 |
| 四 | 业务规则 | 每条：规则描述 / **出处**；冲突项标注「PRD 优先」 |
| 五 | 非功能需求 | 性能 / 安全 / 兼容性 / 可访问性 |
| 六 | 技术约束 | 前端框架 / 后端 / 数据库 / 部署环境 |
| 七 | 数据需求 | 数据实体 / 字段 / **来源** |
| 八 | 验收标准 | 每条：功能 / 验收标准 / **判定方式** |
| 九 | 待补充项 | 每条：缺失信息 / 建议补充方式 / 影响 |
| — | 解析元数据 | 解析时间 / 原型平台 / 保真度 / PRD 是否提供 / 冲突项数 / 待补充项数 |

> 若审核对象不是上述结构（自由格式需求文档 / 第三方 PRD），D1 判 **N-A（附理由）**，其余维度照常，
> 并在报告首部标注 `structure=non-standard`。

## 二、八维判定要点

### D1 完整性

| 检查 | 判据 | 典型 P0 |
|---|---|---|
| 章节齐备 | 九章 + 解析元数据块均在 | 整章缺失 |
| 字段非空 | 关键字段非模板占位（如未替换的 `{{...}}`） | 技术约束整章空 / 验收标准整章空 |
| 表头与行一致 | 表头列数与数据行列数一致 | 表被截断 |

### D2 无歧义性

| 检查 | 判据 | 例 |
|---|---|---|
| 术语唯一 | 同一概念全文用同一个词 | 「入库」既指物理入库又指系统录入 |
| 口径唯一 | 数值 / 单位 / 时间口径有定义 | 「最近 30 天」是自然日还是工作日 |
| 指代明确 | 「该模块」「上述字段」有唯一先行词 | 跨三页后出现的「该系统」指向不明 |
| 优先级唯一 | 同一条目只有一个 P 级 | 功能表与验收表对同一功能给了不同优先级 |

### D3 可测性（**本维为本 skill 的核心差异点**）

| 检查 | 判据 | 反例 |
|---|---|---|
| 可判定 | 存在明确**通过 / 不通过**条件 | 「界面友好」「性能良好」 |
| 可观测 | 条件对应可观测结果（界面元素 / 数据 / 日志 / 接口返回） | 「用户满意」 |
| 无复合断言 | 一条验收标准只验证一件事 | 「支持导出且不丢数据且速度快」 |
| 有判定方式 | 「判定方式」列非空且具体 | 空白 / 仅写「人工」 |

> 判定辅助：验收标准含 Given-When-Then、或含可观测动词（显示 / 跳转 / 返回 / 写入 / 拦截 / 提示）与量化阈值者，视为**可判定**。

### D4 边界与异常

| 检查 | 判据 |
|---|---|
| 空态 | 列表 / 详情无数据时的表现已交代 |
| 极值 | 数量为 0 / 达上限 / 超长输入已交代 |
| 并发 | 同一实体被多人同时操作的规则已交代 |
| 失败与超时 | 接口失败、超时、部分成功、重试策略已交代 |

### D5 状态与流程闭环

| 检查 | 判据 |
|---|---|
| 状态穷尽 | 状态集合列出且互斥 |
| 迁移完整 | 每个状态的入边与出边均有触发条件 |
| 逆向与中断 | 取消 / 回退 / 中断 / 回滚路径已交代 |
| 无悬空 | 不存在「只能进不能出」或未定义终态的状态 |

### D6 权限与角色

| 检查 | 判据 |
|---|---|
| 角色定义 | 角色集合明确 |
| 可见范围 | 每角色可见的数据范围明确 |
| 可操作范围 | 每角色可执行的动作明确 |
| 无越权路径 | 不存在绕过权限的路径（如直接改 URL 可进） |

### D7 数据与字段口径

| 检查 | 判据 |
|---|---|
| 字段齐备 | 类型 / 必填性 / 唯一性 / 默认值 / 长度限制 |
| 口径一致 | 同一字段在数据需求与业务规则中定义一致 |
| 脱敏规则 | 含个人信息 / 敏感数据的字段有脱敏或权限约束 |
| 来源明确 | 每个实体 / 字段标出来源（原型 / PRD 章节） |

### D8 证据溯源

| 检查 | 判据 | 归属标记 |
|---|---|---|
| 业务规则有出处 | 每条业务规则标 `PRD:<章节号>` | 无出处 → 需追问 |
| 交互规则有出处 | 每条交互规则标 `原型:<页面名>` | 无出处 → 需追问 |
| 功能有出处 | 每条功能标出处 | 无出处 → 需追问 |
| 冲突已标注 | 原型与 PRD 冲突项标「PRD 优先」 | 未标注 → 属实质缺陷 |
| 保真度如实 | 解析元数据的保真度等级与实际情况相符（低保真却声称完整解析 = 失真） | 虚高 → P0 |

## 三、门② 前置三重校验（家族专有，必做）

| # | 校验 | 输入 | 判据 | 输出 |
|---|---|---|---|---|
| 1 | **结构完整性** | `requirements.md` | 见 §一 结构基线 | 缺失章节 / 空字段清单 |
| 2 | **证据溯源** | 同上 | D8 全部检查项 | 无出处条目清单 + 未标注冲突清单 |
| 3 | **下游可消费性** | 同上 + tri-coding 门② 期望 | ① 验收标准可判定（D3）② 技术约束齐备（D1 六章）③ 待补充项已定级并说明影响（D1 九章） | 阻塞门② 的缺口清单 |

> 三者的可机器判定部分由 `scripts/audit_precheck.py` 承担；语义判断（如「这条断言是否真的可判」）由 Agent 复核并给出证据。

## 四、分级判据（P0 / P1 / P2）

| 级别 | 定义（判据） | 典型条目 | 处置 |
|---|---|---|---|
| **P0 · 阻断开工** | **缺该信息则 tri-coding 门② 必然返工或必然做错** | 验收标准不可判定；核心业务规则无出处；九章中任一整章缺失；技术约束整章空；状态机存在悬空/未定义终态；保真度虚高 | 回炉 tri-prototype；判定「阻断开工」 |
| **P1 · 需澄清** | 不影响是否开工，但影响实现细节，须在门② 前澄清 | 术语歧义；边界场景未覆盖；权限矩阵不完整；字段口径缺失；复合断言 | 列入修订清单；建议 tri-grill 对齐 |
| **P2 · 建议改进** | 表达 / 结构 / 可读性层面 | 字段命名不统一；示例缺失；表格格式不一致；章节内顺序混乱 | 记入报告，不阻断 |

**判定总则**：

- 判定「阻断开工」当且仅当**存在至少一条 P0**。
- 无 P0 但有 P1 → 「**有条件开工**」（P1 须在门② 前销账）。
- 仅 P2 → 「**可开工**」。
- **反规避**：NEVER 因用户催促、时间紧或「先开工再说」而下调级别。

## 五、结论可信度声明（报告必填）

| 模式 | 声明内容 |
|---|---|
| **委派审核** | 本地三重校验 + `<候选 slug>` 的通用产品视角；就绪度来自市面 skill，可消费性来自本地判据 |
| **兜底审核** | 仅本地八维判据；**未获得**市面 skill 的岗位就绪度与决策清单视角；建议后续安装 `<首个可用候选>` |
| **降级模式 C** | 属兜底 + 上游降级：审核范围与交付预期由用户描述推断，可能遗漏未言明维度 |
