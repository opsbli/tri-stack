# STAR 与行为描述框架（star-framework）· 共享资源层

> 由 ResumeSkills-main 的 resume-bullet-writer / interview-prep-generator 蒸馏，供
> tri-resume-core / tri-interview 复用（写 bullet 与讲故事共用同一套骨架）。
> grep 模式：`STAR` / `XYZ` / `CAR` / `故事库`

## 一、三种行为描述框架

| 框架 | 结构 | 适用 |
|---|---|---|
| **X-Y-Z（Google 法）** | `Accomplished X as measured by Y by doing Z` | 一句式 bullet |
| **STAR** | S 情境(1-2 句) → T 任务(1 句) → A 行动(2-3 句) → R 结果(1-2 句带指标) | 面试详细故事 |
| **CAR** | Challenge → Action → Result | 简洁替代 STAR |

## 二、文字长度约束

- 面试故事：Full **2min** / Short **60s** / One-liner **15s** 三版本。
- Interview 详述：90s–2min，含 S/T/A/R 且带指标。
- 简历 bullet：**≤2 行**，impact 而非 duty，至少 1 数字。

## 三、STAR 故事库五类（目标 8-10 个 STAR）

1. **Leadership** 领导力
2. **Problem-Solving** 问题解决
3. **Collaboration** 协作
4. **Achievement** 成就
5. **Failure-Growth** 失败与成长

> 每个 STAR 归档为本人真实经历，覆写时只调长度与侧重，不虚构。

## 四、常见面试难题解答公式

- **弱点**：`Real（真实）+ Self-awareness（自知）+ Improvement（在改进）`。
- **为何离职**：积极 + 向前看 + 简短（NEVER 说前雇主坏话）。
- **失败**：真实失败 + 学到了什么 + 如何应用下次。

## 五、简历 bullet 结构复核

被动语态 / 无量 / 职责而非成就 / 过泛 / 过长（>2 行）五大失误 MUST 修复。
转行 / 应届 / 空窗场景需在讲法上做差异化处理（转行强调迁移技能，空窗短且正向解释）。
