# 版本检查与更新规范

> 本文件是 tri-forge 家族内部版本检查的**唯一事实源**，不依赖任何外部上游 skill。
> 所有 tri-* 家族 skill 的版本检查与更新操作均须遵循本规范。

---

## 一、执行方式

```bash
python scripts/check_update.py --slug <slug> --platform <平台> [--cache-dir <路径>] [--force]
```

- `<slug>`：skill 标识，如 `tri-forge`
- `<平台>`：`trae` | `workbuddy` | `qwen` | `codex`
- `--cache-dir`：离线缓存目录，传入后启用离线模式
- `--force`：强制重查，忽略 24h 节流缓存

**退出码语义**（与 `check_update.py` 的 `EXIT_CODE` / `STATE_*` 严格对齐）：

| 退出码 | 状态 | 含义 |
|--------|------|------|
| 0 | A · 通过 | 版本检查通过（最新或缓存有效），放行 |
| 10 | B · 无网络 | 离线降级：无网络，取缓存态放行（缓存过期则降级放行） |
| 11 | C · 通道降级 | 远端通道不可达但有缓存，返回缓存态放行 |
| 12 | D · 版本陈旧 | 版本陈旧且缓存过期，尝试升级；升级失败则降级放行 |
| 20 | BLOCK · 签名不一致 | 阻断 |
| 21 | BLOCK · 回滚失败 | 阻断 |
| 22 | BLOCK · 升级后版本校验失败 | 阻断 |

> 退出码 `<20` 一律放行（含 A/B/C/D 四态）；`>=20`（BLOCK）绝对禁止执行并按 `block_code` 输出恢复指引。脚本自身异常兜底降级放行（NEVER 因版本门故障阻断启动）。

---

## 二、执行要点

1. **先读本地**：从 SKILL.md frontmatter 读取当前版本
2. **节流缓存**：24h 内已查过且缓存有效 → 直接返回缓存态
3. **网络查询**：请求远端最新版本号
4. **版本比较**：逐段整数比较（避免 `1.10.0 < 1.9.0` 的字典序陷阱）
5. **四态判定**（与脚本 `STATE_*` 对齐）：
   - **A 态（通过）**：版本最新或缓存有效 → 直接放行（退出码 0）
   - **B 态（无网络）**：无网络 → 取缓存态放行（缓存过期则降级放行，退出码 10）
   - **C 态（通道降级）**：远端通道不可达但有缓存 → 返回缓存态放行（退出码 11）
   - **D 态（版本陈旧）**：版本陈旧且缓存已过期 → 尝试升级（退出码 12）；升级失败则降级放行
6. **升级流程**（仅 D 态触发）：
   - 备份当前 SKILL.md → 下载新版本 → 校验签名 → 验证 frontmatter 版本号
   - 签名不一致(P2) 或 回滚失败(P3) → 阻断（退出码 20/21）
   - 其余降级场景 → 放行（退出码 12）
7. **兜底容错**：脚本自身异常 → 降级放行（退出码 11=C 态），NEVER 因版本门自身故障阻断 skill 启动

## 四、版本比较算法

```python
def compare_versions(v1: str, v2: str) -> int:
    """比较两个 SemVer 版本号。返回 -1/0/1 表示 v1<v2/v1==v2/v1>v2"""
    parts1 = [int(x) for x in v1.split('.')]
    parts2 = [int(x) for x in v2.split('.')]
    # 补齐长度
    while len(parts1) < len(parts2):
        parts1.append(0)
    while len(parts2) < len(parts1):
        parts2.append(0)
    for a, b in zip(parts1, parts2):
        if a < b:
            return -1
        if a > b:
            return 1
    return 0
```

## 五、节流缓存机制

- 缓存文件：`<cache-dir>/.version_cache.json`
- 缓存内容：`{"timestamp": <unix>, "state": "<A/B/C/D>", "remote_version": "<ver>"}`
- 节流窗口：24 小时（86400 秒）
- `--force` 参数可强制绕过缓存

## 六、生成物版本检查章节规范

所有 tri-* 家族 skill 的 SKILL.md 中，版本检查章节必须为**瘦指针 STUB**：

- **行数上限**：≤30 行
- **必须内容**：执行方式 + 指向本文件（`references/version-check-spec.md`）的指针
- **禁止内容**：内联四态判定细则、内联升级流程、内联版本比较算法
- **原因**：避免散文描述算法让模型复现导致漂移；所有版本检查逻辑集中在本规范文件中
