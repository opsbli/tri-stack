# 语义审查手册（tri-guard）

> 单一事实源。grep 模式：维度名（如 `外部传输`）、三族名（`SSD`）、或「报告模板」。
> 主用途：对确定性引擎（skillspector）认定的每个 HIGH/CRITICAL finding 做**语义/意图复核**，判断是「恶意、疏忽还是良性但敏感」，并结合声明目的判定最终 `APPROVE / CAUTION / REJECT`。
> 铁律：**不信任纯分数**——高分不一定恶意（敏感但必要且文档化），低分也可能漏掉语义风险。数值仅是风险姿态参考。

---

## 一、语义十一维复核框架（skill-inspector 来源）

> 对每个高信号发现逐一应用；维度不适用则可跳过，但主标题区须显式标注。

| # | 维度 | 复核问题 | 恶意图信号 |
|---|------|----------|------------|
| 1 | 目的匹配（Purpose fit） | 代码是否只做技能描述承诺的事？ | 声明 vs 行为脱节、隐藏附加行为 |
| 2 | 权限匹配（Permission fit） | 请求的工具/权限是否与实际行为一致？ | 声明权限 < 实际所需能力（LP 类） |
| 3 | 敏感访问（Sensitive access） | 是否读取 token/凭据/主目录/配置/已装技能/记忆？ | 读密钥/SSH/AWS/其它 agent 配置（E2/PE3/AS1-3） |
| 4 | 外部传输（External transmission） | 什么数据离开本机？发往哪？是否文档化？ | 未文档目的地的外发（E1/E4） |
| 5 | 执行风险（Execution risk） | 是否用 shell/subprocess/动态导入/eval/exec/解码负载/下载代码？ | 组合危险调用（AST/TT） |
| 6 | 持久化（Persistence） | 是否建 cron/launch agent/shell hook/启动钩子/自写文件/隐藏状态？ | src 改动、跨会话残留（RA2/MP3） |
| 7 | 提示词风险（Prompt risk） | 是否弱化安全边界/隐藏行为/泄露内部指令/引导未来对话？ | P6-8、弱化护栏词（P1/AR1-3） |
| 8 | 触发风险（Trigger risk） | 触发器是否过宽可能劫持无关请求？ | 泛触发词/shadow 命令（TR1-3） |
| 9 | 供应链（Supply chain） | 依赖是否 pin？包是否可疑？是否下载并执行远程脚本？ | 未 pin/仿冒/远程执行（SC1/SC2/SC6） |
| 10 | 用户控制（User control） | 敏感/破坏性行为是否有清晰用户同意？ | 无确认自动执行（EA2） |
| 11 | 语义-声明一致性 | 声明、权限、实现、用户可见行为四者是否一致？ | 四者任一不匹配 |

> **复核结论三分类**：`malicious（明确恶意）` / `negligent（疏忽/无意图但风险真实）` / `benign-but-sensitive（良性但敏感，需文档化与边界）`。`benign-but-sensitive` 可接受，但 MUST 出现在报告的 Guardrails 段并要求触发用户控制。

## 二、LLM 语义三族问题集（src/skillspector 来源）

> 用于引擎不可用或需二次语义核验时。grep 模式：`SSD` / `SDI` / `SQP`。

### 2.1 SSD —— 语义安全发现（Semantic Security Discovery）

| ID | 检测面 | 代表提问 |
|----|--------|----------|
| SSD-1 | 语义级提示注入 | 技能自然语言是否在诱导越权/绕过安全？ |
| SSD-2 | 变体攻击措辞 | 是否存在伪装/变体的攻击表达（非字面关键字）？ |
| SSD-3 | 自然语言外泄 | 是否用自然语言教唆向外部泄漏上下文？ |
| SSD-4 | 叙事欺骗 | 是否用渐进叙事逐步建立越权/恶意行为的合理性？ |

### 2.2 SDI —— 语义开发者意图（Semantic Developer Intent）

| ID | 检测面 | 代表提问 |
|----|--------|----------|
| SDI-1 | 描述-行为不匹配 | manifest/文档声明与实际代码行为是否一致？ |
| SDI-2 | 上下文不当能力 | 是否具备与用途不匹配的危险能力？ |
| SDI-3 | 范围蔓延 | 权限/能力是否超出声明用途？ |
| SDI-4 | 意图-代码分歧 | 注释/陈述意图与代码实际动作是否矛盾？ |

### 2.3 SQP —— 语义质量策略（Semantic Quality Policy）

| ID | 检测面 | 代表提问 |
|----|--------|----------|
| SQP-1 | 模糊触发器 | 触发词/描述是否模糊、过宽或分散？ |
| SQP-2 | 缺用户警告 | 涉及敏感/破坏行为是否缺显式 user warning？ |
| SQP-3 | 自然语言策略违规 | 是否违反自然语言安全/行为策略？ |

## 三、裁决标准（rubric）

综合「严重级别 + 语义复核结论 + 源码可解释性」给出最终裁决：

| 裁决 | 判据 |
|------|------|
| **APPROVE** | 无 HIGH/CRITICAL，或全部 HIGH/CRITICAL 均被源码明确 + 可解释 + 必要 + 有边界 |
| **CAUTION** | 存在 MEDIUM 或部分 HIGH 敏感但良性，需用户在知悉风险下审慎安装 |
| **REJECT** | 存在不可解释的 HIGH/CRITICAL，或 51+ 且源码不可信，或存在恶意意图发现 |

### 分数姿态参考（非唯一依据）

| 分数 | 默认姿态 |
|------|----------|
| 0–20 | 通常可接受，快速源码复核后 APPROVE |
| 21–35 | 仅当发现可清楚解释时可接受 |
| 36–50 | 必须人工审查；默认 CAUTION 除非每处担忧都被解释 |
| 51–80 | 默认 REJECT，除非源码可信且所有敏感行为必要 |
| 81–100 | 默认 REJECT |

## 四、报告模板（用户语言正文 + 英文术语）

> 正文/章节标题用用户语言（中文用户→中文）；英文术语、命令、路径、规则 ID、严重级别、裁决标签保持英文。语言策略同源 skill-inspector。

```markdown
# 技能安全审查：<skill 名>

**风险行**：`<severity>` · 风险分数 <N>/100 · 裁决 **<APPROVE|CAUTION|REJECT>**
**Bottom Line**：<一句话结论 + 是否可安装>

## Signal Overview
<高危/严重信号总览，简明表格>

## Key Evidence
<每条关键证据：规则 ID + 文件路径:行号 + 证据片段 + 原件位置>

## Diagnosis
<综合判定：恶意 / 疏忽 / 良性但敏感 + 目的匹配分析>

## Guardrails
<若 APPROVE/CAUTION：必须的边界、用户控制、文档化承诺>
```

> 禁止粘贴完整扫描器原始 dump；仅使用必要表格与具体证据。禁用「解释不了的高危发现被信誉/分数/包名降级」。

## 五、降级态诚实性

- 引擎可用 → 报告标注 `scan_mode=static+llm / static-only`（是否真实跑了语义分析）。
- 引擎不可用 → 报告 MUST 明示「未运行确定性引擎，本次为纯语义降级审查」，置信度整体下调，并将所有结论标注 `unconfirmed`。
- 未经确认的高危发现 NEVER 被默认 APPROVE；降级态下默认偏 REJECT 以安全为先。
