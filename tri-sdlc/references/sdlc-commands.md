# SDLC 自然语言指令表与状态机（references）

> 本文件是 `tri-sdlc` 的自然语言指令集与阶段状态机单一事实源。SKILL.md 保留摘要与指针，全集在此。
> grep 检索：按指令名或状态名检索，如 `grep -n "ROLLBACK" references/sdlc-commands.md`。

## 自然语言指令表

| 指令 | 用户典型说法 | 动作 |
|---|---|---|
| `START` | 启动 SDLC / 开始做个 XX / 按完整流程走一遍 / 从立项开始 | 初始化 `manifest.md`，确认剖面，进入首个启用阶段 |
| `STATUS` | 进度 / 到哪了 / 现在什么状态 / 看下 manifest | 渲染进度摘要（阶段状态表 + 当前门禁 + 下一步动作），**不改变任何状态** |
| `APPROVE` | 通过 / 确认 / OK / 可以 / 下一步 / 继续 | 闸门② 放行，当前阶段置 `已通过`，进入下一启用阶段 |
| `REJECT` | 打回 / 不行 / 重做 / 这里要改：<意见> | 当前阶段置 `进行中`，轮次 +1，携用户意见回炉子SKILL |
| `ROLLBACK` | 回退到 P2 / 退回需求阶段 / 重来一遍设计 | 级联回退（见状态机级联回退规则），说明将失效哪些阶段后再执行 |
| `SKIP` | 跳过 P3 / 这段不用做 | 登记理由 + 风险 + 用户确认，置 `已跳过`，进入下一阶段 |
| `PROFILE` | 用轻量流程 / 切到标准剖面 / 不用做运维那段 | 切换剖面并重算启用阶段，登记切换记录 |
| `REGATE` | 再审一次 / 重跑门禁 | 对当前阶段重新执行闸门①，轮次不变，报告追加新章节 |
| `FASTMODE` | 快速模式 / 不用每步都问我 / 自动往下走 | 闸门② 自动放行（闸门① FAIL 仍硬阻断），登记模式变更 |
| `PAUSE` | 暂停 / 先停一下 / 明天再说 | 当前阶段置 `已暂停`，落盘 manifest，输出恢复指引 |
| `RESUME` | 继续 / 接着做 | 从 manifest 恢复上下文，回到暂停前状态 |
| `ABORT` | 终止 / 不做了 / 取消项目 | 登记终止原因，manifest 标记 `已终止`，保留全部已产出交付物 |

**指令消歧**：`继续` 在「待确认」状态下解析为 `APPROVE`，在「已暂停」状态下解析为 `RESUME`；歧义无法消除时 MUST 反问确认，NEVER 猜测执行。

## 阶段状态机

| 状态 | 含义 | 可迁移至 |
|---|---|---|
| `未启用` | 不在当前剖面内 | `未开始`（切换剖面时） |
| `未开始` | 尚未进入 | `进行中` |
| `进行中` | 子SKILL 正在产出交付物 | `待审计`、`已暂停` |
| `待审计` | 交付物已产出，等待闸门① | `审计未过`、`待确认` |
| `审计未过` | 闸门① FAIL，已输出修订意见 | `进行中`（回炉，轮次+1） |
| `待确认` | 闸门① PASS，等待闸门② | `已通过`、`进行中`（用户打回） |
| `已通过` | 双闸门均过 | `失效`（被级联回退时） |
| `已跳过` | 用户显式跳过，已登记理由与风险 | `进行中`（补做时） |
| `失效` | 因上游阶段回退而失效，需重做 | `进行中` |
| `已暂停` | 用户暂停 | `进行中` |

**级联回退规则**：执行 `回退到 Pn` → Pn 状态置 `进行中`（轮次 +1），P(n+1)…P8 中所有 `已通过`/`待确认`/`待审计` 阶段一律置 `失效`，其交付物文件保留在盘但在 manifest 标记 `stale`，重做时覆盖更新。

## 维护

- 新增指令：在本表追加一行（指令名 + 典型说法 + 动作），处理流程的指令识别自动覆盖。
- 新增状态：在状态机表追加行（状态 + 含义 + 可迁移至），级联回退规则同步更新。
