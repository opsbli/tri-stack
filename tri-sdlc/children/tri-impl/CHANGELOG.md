# Changelog

本文件记录 tri-impl（tri-sdlc P4 编码实现子SKILL）的版本变更历史。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [1.1.1] - 2026-08-05

### 修复

- **版本门自动升级死命令**（P0）：`skillhub install <slug> --upgrade` 实测报 `unrecognized arguments: --upgrade`，改为正确命令 `skillhub upgrade <slug>`，并补 CLI 回退路径 `python ~/.skillhub/skills_store_cli.py upgrade <slug>`

### 变更

- **版本检查三态判定 → 四态判定**：新增 D 态（升级通道不可用降级），升级失败时标注降级继续而非死锁
- 版本检查节命令细则收敛为指向唯一真源 `tri-intent/references/version-gate.md`，消除各 skill 内的重复表述
- frontmatter version `1.1.0` → `1.1.1`

## [1.1.0] - 2026-08-03

### 新增

- **版本检查与更新机制**：新增「版本检查与更新机制」独立章节，作为 skill 任一执行入口启动后的第零步。包含：
  - 设计原则与触发时机：版本检查 → 上游依赖检测 → 读取快照 → 核心执行 的执行顺序固化
  - 版本检查技术实现标准：校验端点、请求载荷、响应契约、SemVer 比较、超时控制（≤5s）、幂等性
  - 更新流程安全验证要求：来源校验（官方通道 ONLY）、SHA-256 完整性校验、签名校验、回滚保障、权限最小化、版本一致性联动
  - 六类禁止执行判定条件（P1–P6）及结构化阻断提示
  - mermaid 流程图展示完整决策链路
- **强制执行契约第 0 条（版本检查前置硬门）**：优先级高于所有其他强制前置条目，明确版本检查为执行流程第零步，更新完成前 NEVER 进入后续步骤

### 变更

- frontmatter version `1.0.0` → `1.1.0`

## [1.0.0] - 2026-08-02

### 新增

- 初始版本：tri-sdlc 九阶段编排的 P4 编码实现子SKILL
- 12 条强制执行契约：强制前置（校验 P3 看板已通过）、面向门禁产出、任务驱动、看板回写、不改上游规格、源码落工作区、测试必跑、合规五条、无占位交付（含代码内 TODO）、回炉逐条闭环、不越权、自检句
- 七维实现方法论：任务闭环 / 分层产出 / 单元测试 / 边界与异常 / 注释与说明 / 合规红线 / 源码落盘，逐维对应 `P4-M1`–`P4-M7`
- 任务状态四态表（未开始 / 进行中 / 完成 / 已转移），明确 P4 结束时允许存在的状态
- 分层产出映射表（数据层 / 业务逻辑层 / 接口层 / 前端）及不适用时的显式声明答法
- 单元测试五要素（用例数 / 通过数 / 覆盖率 / 执行证据 / 用例来源），覆盖率读 manifest 阈值覆写，缺省 ≥60%，禁止伪造数值
- 边界与异常五类清单（空与极值 / 非法输入 / 并发与重入 / 外部失败 / 权限与状态），要求 ≥3 条含「场景→策略→用例」
- 合规红线五条自检表（原创不照搬 / 许可证兼容 / 依赖已授权 / 披露到位 / LICENSE 已声明），复用 `tri-coding` §代码版权与许可证合规
- 源码清单登记规范（路径 + 职责 + 关联任务/需求 ID + 变更类型），源码禁止落 `.tribro/`
- 设计偏差回报机制：实现中发现设计缺陷记入「设计偏差」区并回报 tri-sdlc 决策
- 建议项落地方式（提交规范 `P4-R1`、圈复杂度与函数长度 `P4-R2`）
- 与 P3 / P5 / P6 的三条职责边界说明（工程骨架 vs 业务代码、自检 vs 评审、单测 vs 集成验收）
- 上游依赖检测两态（编排模式 / 引导安装，含改用 `tri-coding` 的建议与「仅出实现文档」降级）
- 落盘 `.tribro/sdlc/<命名>/P4-implementation/`，任务状态回写 P3 看板仅改状态列
- 配套 README.md 与 tests/tri-impl-full-testcases.md
