# tri-ops（tri-sdlc P8 运维与监控子SKILL）

tri-sdlc 九阶段编排中的 **P8 运维与监控专家子 SKILL**。接收 tri-sdlc 派发的阶段任务，把发布后的系统交到「能长期看住」的状态，产出 `ops-runbook.md` 与 `monitoring.md`，交 tri-sdlc 门禁审计。

## 特性

- **日志四要素**：采集范围（含脱敏）+ 格式 + 保留期 + 聚合方式，单机项目给等价答法
- **指标三类**：可用性 / 性能 / 业务各 ≥1，每项带采集方式与频率
- **告警必须有人收**：阈值 + 级别 + 渠道 + 接收角色，只记录不通知的规则视为无效
- **阈值有据**：性能阈值引用 P2 目标或实测基线，无依据须标「待校准」
- **只备份不演练不算过**：备份频率 + 保留策略 + 演练周期 + RTO/RPO
- **手册可照做**：≥3 条故障条目，含现象 / 定位 / 处置 / 验证恢复 / 升级路径

## 交付物

| 产物 | 位置 |
|---|---|
| `ops-runbook.md` | `.tribro/sdlc/<命名>/P8-operations/` |
| `monitoring.md` | 同上 |
| 监控/告警配置（可选） | 用户工作区，须确认并登记路径 |

## 安装

随 tri-sdlc 包分发，置于 `tri-sdlc/children/tri-ops/`。独立安装需先装 tri-sdlc：

```
python ops/install-skills.py --target <目标目录>
```

## 使用

```
tri-sdlc 派发 P8 阶段任务（附 P7 发布报告 + P2 容量性能目标 + P6 缺陷台账）
      → 六维编制（日志 → 指标 → 告警 → 健康检查 → 备份容灾 → 故障手册）
      → 两份交付物落盘
      → 门禁自查（7 必检 / 2 建议）
      → 交回 tri-sdlc 审计 → tri-sdlc 出全流程总结并结项
```

> 剖面为 `standard` / `lite` 时本阶段未启用，tri-sdlc 不会派发。

## 设计原则

- **面向验收标准产出**：六维运维与 P8 门禁条目一一对应
- **监控 ≠ 巡检**：P7 是发布窗口内一次性核对，P8 建立长期自动且有人接收的体系
- **目标与阈值分离**：P2 定目标值，P8 定监测方式与告警阈值，不反向改 P2
- **不越权**：不判门禁、不改业务代码、不重新发布、不宣布结项、不静默改生产
