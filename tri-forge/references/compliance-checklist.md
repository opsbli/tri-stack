# 家族合规核对清单（22 条）

> **本文件是门④「合规自检」的判据单一事实源。** 编号即判定序号，逐条执行，不得跳条。
> 构成：**12 条家族硬约束（1–12）+ 8 条增强约束（13–20）+ 1 条安装约束（21）+ 1 条版本检查去重（22）**。
> 判定由 `scripts/compliance_check.py` 承担可机器判定部分；标注 `[需人工]` 的条目 MUST 由 Agent 逐条给出证据位置，NEVER 臆断。
>
> **判定口径**：`PASS` / `FAIL` / `N-A`（**MUST 附不适用理由，无理由的 N-A 视为 FAIL**）。
> **必检项** FAIL → 门④ 判 FAIL → 回炉门②；**建议项**（下表标注）FAIL 不阻断，计入「建议改进项」——
> 与家族既有的「必检项 + 建议项」惯例一致。
> 任一门④ FAIL 连续 3 轮 → 停止自动回炉，报告卡点请求人工介入。

## 〇、条目来源可信度（务必先读）

## 一、家族硬约束（1–12）

| # | 约束 | 判定方法 | 适用 |
|---|---|---|---|

| 2 | **独立安装声明** | `description` 含「支持独立安装，含上游依赖检测**N**态逻辑」字样（N 为态数） | 全部（根路由除外） |

| 4 | **frontmatter 完整** | 含 `name` / `slug` / `version` / `displayName` / `description` / `summary` / `tags` / `license` 八字段，`version` 形如 `\d+(\.\d+)*` | 全部 |
| 5 | **强制执行契约存在且含自检句** | §强制执行契约 含编号条目 ≥5 条，且**含一条自检句条目**（声明格式见第 15 条） | 全部 |
| 6 | **上游检测态数与类型匹配** | 咨询/表达/元操作型 = **两态**（快照/引导安装）；编码/内容/调试/loop/编排型 = **三态**（快照/引导安装/降级），三态 MUST 含降级声明文本 | 全部（根路由除外） |
| 7 | **职责边界明确** | §职责边界 含「本 skill 负责」+「不负责」+ 一张「不由本 skill 处理」或相邻边界表 | 全部 |
| 8 | **意图认领 MECE 不重叠** `[需人工]` | 生成物认领的 L2/L3 编码 **MUST 与 `tri-intent/SKILL.md` §路由映射表 逐项交叉比对**（**该表是路由真源**，不是 `family-spec.md` 内的副本），无一编码被两个 skill 认领 | 路由型下游 |
| 9 | **核心能力方法论含可扩展性** | §核心能力方法论 除方法论本身外，含「可扩展性」小节（说明新增维度/条目的零改动路径） | 全部 |
| 10 | **交付产物含落盘规则** | §交付产物 明确各产物的**落盘位置**（`.tribro/` vs 用户工作区）与命名规则 | 全部 |
| 11 | **CHANGELOG 规范** | 首行格式遵循 Keep a Changelog 链接；首条为 `## [x.y.z]` 且**等于 frontmatter version**、且为**全文件最大版本** | 全部 |
| 12 | **tests 全场景用例** | `tests/` 下存在 `*-full-testcases.md`，含能力清单表 + 用例（≥10 条） | 全部 |

## 二、增强约束（13–20）

| # | 约束 | 判定方法 | 适用 |
|---|---|---|---|
| 13 | **门禁/审批门明确** | 若有产物落盘，MUST 定义审批门（编号 + 通过/不通过规则 + 回炉方向）；纯只读 skill 可 N-A（须附理由） | 产出落盘者 |
| 14 | **兜底处理覆盖** | 至少覆盖四类：版本检查异常 / 门禁不过 / 上游缺失 / 异常场景；且明确「NEVER 静默失败」 | 全部 |
| 15 | **自检句格式与家族一致** | 声明格式取自家族三种之一——`本次意图=`（路由型下游）/ `本次模式=`（内部工具型）/ `本次操作=`（横向型）；MUST 含当前阶段或状态字段 | 全部（有例外者见第 20 条） |
| 16 | **反规避规则**〔建议项〕 | 含「NEVER 因用户着急/时间紧下调标准」类表述，且标准只以判据文件为准 | 有门禁者 |
| 17 | **禁止硬编码家族计数** | 正文 NEVER 出现「N 个下游」「N 个 skill」「N 个目录」等硬编码计数（正则 `\d+\s*个(下游\|skill\|目录\|顶层)` 命中即 FAIL）——计数会随家族演进失真，须改为「全部路由型下游」等表述 | 全部 |

| 19 | **与相邻 skill 边界表**〔建议项〕 | §职责边界 或独立小节给出「相邻 skill / 边界判据」对照表 | 有相邻竞争者 |
| 20 | **横向层自检句例外登记** `[需人工]` | 横向型 skill 若自检句格式与家族不同，MUST 在 `family-spec.md` 登记该例外 | 横向型 |

## 五、判定记录格式

门④ 的产出（`gate-report` 段落）MUST 按此格式逐条记录，便于审计回溯：

```
## 门④ 合规自检 · 第 <轮次> 轮

| # | 约束 | 判定 | 证据位置 / FAIL 原因 |
|---|---|---|---|
| 1 | 目录结构完整 | PASS | SKILL.md / README.md / CHANGELOG.md / tests/ 均在 |
| 8 | 意图认领 MECE 不重叠 | PASS | 交叉比对 tri-intent/SKILL.md §路由映射表：认领 I13 默认落点，无冲突 |
| 17 | 禁止硬编码家族计数 | N-A | 本 skill 为内部工具，不描述下游集合（理由：不涉及家族计数表述） |
...

**汇总**：必检项 22/22 PASS（N-A x 项，均附理由）→ **门④ PASS**
```

- **每条 MUST 给出证据位置**（文件名 + 章节/行范围）或 FAIL 原因
- `N-A` MUST 附不适用理由
- 汇总 MUST 给出 `x/y PASS` 与门④ 总判定
