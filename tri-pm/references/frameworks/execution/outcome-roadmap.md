# 结果导向路线图改写（outcome-roadmap）

> 蒸馏自 `outcome-roadmap`｜域：执行｜源词数：≈520

## 必含章节清单（MUST-SECTIONS）

- [ ] Original Initiatives — 原举措（按季度/阶段列出）
- [ ] Outcome Statements — 结果陈述（每条举措：Enable [segment] to [outcome] so that [business impact]）
- [ ] Key Metrics — 成功指标
- [ ] Dependencies / Sequencing — 依赖或排序说明
- [ ] Strategic Context — 战略对齐、客户假设、灵活发布窗口

### 可选补充段（OPTIONAL，不参与 BLOCK 判定）

- [ ] （无）

## 逐段引导问题

- **每举措**：我们在试图达成什么结果？解决什么客户问题？哪个业务指标会改善？
- **改写**：用「Enable [segment] to [outcome] so that [business impact]」格式。
- **指标**：哪些指标能指示成功？
- **韧性**：多个输出可服务同一结果——聚焦结果而非功能清单。

## 输出模板

```markdown
## Outcome-Focused Roadmap: [Product] — [Period]
**Original Initiatives**（by quarter）:
- Q2: [feature] → Outcome: [Enable ... to ... so that ...]

**Key Metrics**: [indicator]
**Dependencies**: [notes]
**Strategic Context**: [alignment, assumptions, flexible windows]
```

## 输出命名规则

`Outcome-Roadmap-[year].md`（内容充实时保存）

## 关键规则

- 结果须可测、可证伪；多输出可达一结果，拥抱灵活性。
- 结果路线图更抗变更；若不确定某功能驱动什么结果，反复问「So what?」直到触达真实价值。
- 避免精确日期，用相对窗口（季度）。
