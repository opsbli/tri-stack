# tri-content

内容处理下游执行 skill。读取 tri-intent 快照 §三 结构化结论，处理 I06–I10（内容生成 / 内容改写 / 翻译转换 / 总结提炼 / 分析处理）委托执行类文本产出意图，产出可直接使用的文本成果物。当 tri-intent 快照下游路由建议指向本 skill 时激活。

本 skill **仅负责依据快照执行文本产出**，不重新识别意图（由 tri-intent）、不产出咨询作答类知识回答（由 tri-ask）、不产出编码/调试结果（由 tri-coding）、不产出多媒体产物（由 tri-mm）。核心理念：**没有满足输入依赖的素材，就没有内容产出——改写/翻译/总结/分析缺原文时产出必失真。**

## 特性

- **5 子意图差异化执行策略**：I06 从零生成 / I07 基于原文改写 / I08 跨语言翻译 / I09 长输入总结 / I10 材料分析，按 L2 路由到对应策略，互不混用
- **输入依赖校验门**：I07–I10 MUST 校验 `D2_输入形态` 是否包含必需的原文/素材，I06 校验主题/体裁/规格是否明确；缺失则回退 tri-intent 的 clarify-gate，NEVER 凭空生成
- **原文对照机制**：I07 改写 / I08 翻译类产出 MUST 保留与原文的段落级对照关系，便于用户校验保真度
- **最小化原则门禁**：进入执行阶段前校验内容范围是否最小化，只生成 `任务要点` 范围内的内容，扩大范围须用户确认
- **格式约束贯穿**：据 `D4_格式约束`（字数/结构/风格）组织产物，格式约束贯穿产出全程
- **独立安装三态依赖检测**：支持快照模式 / 引导安装 / 降级模式，无 tri-intent 时可降级自构造等价输入

## 目录结构

```
tri-content/
├── SKILL.md                          主入口：内容处理工作流 + 子意图差异化策略 + 输入依赖校验
├── templates/                        模板
│   ├── deliverable.md                文本成果物模板（区分 I06–I10）
│   └── 对照表.md                      原文对照表模板（I07/I08）
└── tests/                            测试
    └── tri-content-full-testcases.md 全场景测试用例
```

## 安装

将 `tri-content/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-content/ /path/to/your/skills/
```

本 skill 可独立安装。激活时检测上游 tri-intent skill 是否可用，据检测结果选择执行模式：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| A · 快照模式 | `.tribro/snapshots/` 有快照 或 skills 目录有 `tri-intent/` | 读取快照 §三，按工作流推进（标准模式） |
| B · 引导安装 | 以上均不满足 | 向用户提示依赖并引导安装 `skillhub install tri-intent` |
| C · 降级模式 | 用户明确拒绝安装 | 从用户请求自构造等价输入，声明降级模式 |

## 使用

### 核心流程

收到 tri-intent 快照且 `下游路由建议` 指向本 skill 后，按以下链路推进：

```
读取快照 §三 (L2 ∈ I06–I10)
        │
        ▼
  子意图路由（按 L2 选择策略）
        │
        ▼
  输入依赖校验门
  · I06：校验主题/体裁/规格是否明确
  · I07–I10：校验原文/素材是否齐备
        │
     缺失 ──→ 回退 tri-intent clarify-gate 补充
        │满足
        ▼
  按子意图策略产出文本
  · 格式约束贯穿全程（D4_格式约束）
  · I07/I08 保留原文对照关系
        │
        ▼
  质量自检（准确性/格式合规/原文保真）
        │
        ▼
  交付（文本成果物）
```

### 子意图策略表

| 子意图 | 执行策略 | 输入依赖 | 产出要求 |
|---|---|---|---|
| I06 内容生成 | 从零写文本成稿 | 主题/体裁/规格（明确） | 完整文稿 |
| I07 内容改写 | 基于原文润色/扩缩/改风格 | 必须有原文 | 改写稿 + 原文对照 |
| I08 翻译转换 | 跨语言/跨格式等价转换 | 必须有原文 + 目标语言/格式 | 译文 + 原文对照 |
| I09 总结提炼 | 长输入压缩成要点 | 必须有长输入 | 结构化要点/摘要 |
| I10 分析处理 | 材料中挖洞察/评估/诊断 | 必须有分析对象 | 分析报告 |

### 产物落盘

成果物落盘于 `.tribro/content/<命名>/`，命名沿用 tri-intent 快照命名规范：

```
.tribro/
└── content/
    └── <命名>/
        ├── deliverable.md    # 文本成果物（最终交付物）
        └── (对照表.md)       # I07/I08 原文对照表（如有）
```

示例：`I07_20250211_143022_6a5c037d/deliverable.md`

## 测试

完整测试用例见 `tests/tri-content-full-testcases.md`，覆盖 5 子意图差异化策略、输入依赖校验门（缺失回退）、原文对照机制、最小化原则门禁、格式约束贯穿等全部能力点。

## 设计原则

- **输入依赖前置**：改写/翻译/总结/分析缺原文时产出必失真，输入依赖校验门为硬性前置
- **子意图差异化**：5 个子意图各有独立执行策略与产出要求，NEVER 用统一模板套用
- **最小化原则**：只生成 `任务要点` 范围内的内容，扩大范围须用户确认，NEVER 默默扩范围
- **职责边界**：仅依据快照执行文本产出，不越界识别意图或产出非文本类成果物
