## 一、判定字段说明

| 字段 | 含义 | 判定标准 |
|---|---|---|
| **激活条件** | skill 是否被正确激活 | 触发源命中（委派/显式/查询/管理） |
| **模式判定** | 工作模式 | TRANSLATE_EXECUTE / TRANSLATE_QUERY / TRANSLATE_ADMIN |
| **自检声明** | 操作前一句话声明 | 含 操作/触发源/已读取/段数或键 4 要素 |
| **占位符残留** | 译后占位符扫描 | MUST = 0 |
| **MQM 状态** | 质量门槛通过判定 | pass=通过 / fail=未通过 |

## 二、评分规则

- 每条用例核心断言全部命中记 **PASS**，任一不符记 **FAIL**
- 通过率 = PASS 数 / 总用例数
- **质量门槛**：元数据/输入契约/职责边界场景 ≥95%，执行契约/自检声明/交付产物/质量标准场景 ≥90%，整体 ≥90% 视为达标

> 验证三策略分层、19 类不译规则、隔离区占位法、三层术语表、MQM 自检、策略矩阵、可扩展性、三模式接口。

### TC-04-01：三策略分层——意译传达意义
- **前置条件**：原文为一般解释性段落
- **测试步骤**：1. 翻译；2. 校验译文
- **预期结果**：意译传达原文意义而非逐字映射，但 NEVER 偏离原文核心语义
- **通过标准**：PASS——意译达旨；FAIL——逐字或偏离

### TC-04-02：三策略分层——直译符合中文习惯
- **前置条件**：术语密集场景
- **测试步骤**：1. 翻译；2. 校验直译风格
- **预期结果**：按字面直译但符合中文表达习惯，强制术语表，NEVER 欧化生硬
- **通过标准**：PASS——直译且通顺；FAIL——欧化或生硬

### TC-04-03：19 类不译规则——路径与代码块
- **前置条件**：原文含 `/usr/local/bin` 和 ```code block```
- **测试步骤**：1. 扫描；2. 校验占位符
- **预期结果**：路径 → `__PATH_1__`；代码块 → `__CODEBLOCK_1__`
- **通过标准**：PASS——占位符正确；FAIL——漏占位

### TC-04-04：19 类不译规则——URL 与邮箱
- **前置条件**：原文含 `https://example.com` 和 `user@example.com`
- **测试步骤**：1. 扫描；2. 校验占位符
- **预期结果**：URL → `__URL_1__`；邮箱 → `__EMAIL_1__`
- **通过标准**：PASS——占位符正确；FAIL——漏占位

### TC-04-05：19 类不译规则——版本号与 SHA
- **前置条件**：原文含 `v18.0.0` 和 `a1b2c3d4e5f6`
- **测试步骤**：1. 扫描；2. 校验保留
- **预期结果**：版本号与 SHA 哈希保留原文不译
- **通过标准**：PASS——保留；FAIL——误译

### TC-04-06：三层术语表——Priority C 上下文调整
- **前置条件**：原文含 "deployment"（Priority C 推荐"部署"/"上线"）
- **测试步骤**：1. 翻译上下文为发布场景；2. 校验术语选择
- **预期结果**：Priority C 可上下文调整，选"上线"
- **通过标准**：PASS——上下文调整；FAIL——固定译法

### TC-04-07：MQM 5 维质量自检——Hallucination 检测
- **前置条件**：译文含 AI 编造的原文没有的内容
- **测试步骤**：1. 触发 MQM 自检；2. 校验 Hallucination 维度
- **预期结果**：检测到 Hallucination Critical 错误，触发重译或退守直译
- **通过标准**：PASS——检测到并重译；FAIL——漏检

### TC-04-08：MQM 质量门槛——重译最多 2 次
- **前置条件**：译文未达门槛
- **测试步骤**：1. 触发重译；2. 校验次数
- **预期结果**：最多重试 2 次；超过则退守直译
- **通过标准**：PASS——最多 2 次；FAIL——无限重试

### TC-04-09：翻译策略矩阵——6 场景路由
- **前置条件**：6 种场景原文（技术文档/营销/UI/学术/对话/法律）
- **测试步骤**：1. 翻译各场景；2. 校验策略选择
- **预期结果**：技术文档主策略=直译；营销=意译；法律=直译；对话=意译
- **通过标准**：PASS——按场景路由；FAIL——策略错乱

### TC-04-10：退守条件——数字版本号触发退守
- **前置条件**：原文含数字版本号
- **测试步骤**：1. 翻译；2. 校验策略退守
- **预期结果**：数字版本号触发意译退守直译
- **通过标准**：PASS——退守正确；FAIL——意译版本号

### TC-04-11：可扩展性——5 种扩展方式
- **前置条件**：检查可扩展性章节
- **测试步骤**：1. 校验 5 种扩展声明
- **预期结果**：①新增不译规则 ②术语条目 ③风格示例 ④质量维度 ⑤翻译场景
- **通过标准**：PASS——5 种均声明；FAIL——缺失

### TC-04-12：三模式接口——TRANSLATE_ADMIN 命令集
