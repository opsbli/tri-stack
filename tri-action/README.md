# tri-action

操作执行下游执行 skill。读取 tri-intent 快照 §三 结构化结论，处理 I14（操作执行）意图，调用工具真实执行动作（下单/设提醒/发消息/调用 API 等）并返回操作结果。当 tri-intent 快照下游路由建议指向本 skill 时激活。

本 skill **仅负责依据快照真实执行操作**，不重新识别意图（由 tri-intent）、不出方案不执行（由 tri-plan）、不产出编码开发结果（由 tri-coding）、不产出内容文本（本分支未包含）。核心理念：**没有分级判定的操作不执行——不可逆操作跳过确认门即失控。** 本 skill「真实执行产生副作用」，是 tri 体系内唯一会调用工具产生真实世界影响的下游 skill。

## 特性

- **4 级操作安全分级**：L0 只读 / L1 可逆 / L2 不可逆 / L3 高风险，每个操作映射到对应确认要求，高风险有确认、低风险不阻塞
- **L2/L3 确认门**：等级为「不可逆」或「高风险」的操作 MUST 先向用户列出操作清单 + 影响范围 + 不可逆说明（L3 附风险评估），待用户明确确认后方可执行，NEVER 默默执行高风险操作
- **失败不擅重试机制**：L2/L3 操作失败后 NEVER 自动重试（避免重复副作用如重复扣款、重复发送），L1 可逆操作可有限重试（≤3 次）
- **confirm-log.md SHA-256 防篡改**：高风险操作确认记录落盘时附加 SHA-256 内容哈希，任何正文修改都会导致哈希不匹配，确保审计完整性
- **最小化原则门禁**：进入执行阶段前校验操作范围是否最小化，只执行 `任务要点` 范围内的操作，扩大范围须用户确认
- **独立安装两态依赖检测**：支持快照模式 / 引导安装，不支持降级模式（模式 B 为硬性阻断）

## 安装

将 `tri-action/` 目录放入你的 skills 目录即可：

```bash
cp -r tri-action/ /path/to/your/skills/
```

本 skill 可独立安装。激活时检测上游 tri-intent skill 是否可用，据检测结果选择执行模式：

| 模式 | 触发条件 | 行为 |
|---|---|---|
| A · 快照模式 | `.tribro/snapshots/` 有快照 或 skills 目录有 `tri-intent/` | 读取快照 §三，按工作流推进（标准模式） |
| B · 引导安装 | 以上均不满足 | 向用户提示依赖并引导安装 `python ops/install-skills.py --target <目标目录>` |

> 本 skill 不支持降级模式——模式 B 为硬性阻断，MUST 安装 tri-intent 后方可使用。

## 使用

### 核心流程

收到 tri-intent 快照且 `下游路由建议` 指向本 skill 后，按「解析 → 校验 → 分级 → 确认门 → 执行 → 返回」安全执行链路推进：

```
读取快照 §三 (L2 = I14)
        │
        ▼
  操作解析（操作对象/参数/目标工具 → 操作清单）
        │
        ▼
  参数校验（完整性 + 合法性）
  · 缺失 → 回退 clarify / 不合法 → 中止并报告
        │
        ▼
  操作分级（L0 只读 / L1 可逆 / L2 不可逆 / L3 高风险）
        │
        ├── L0/L1 ──→ 直接执行
        │
        └── L2/L3 ──→ 确认门（操作清单+影响范围+不可逆说明）
                          │
                     拒绝/修改 ──→ 据反馈调整或中止
                          │确认通过
                          ▼
                    执行（调用工具）
        │
        ▼
  结果返回（状态 + 工具原始回执 + 确认记录）
  · L2/L3 失败不擅自重试
        │
        ▼
  交付（操作结果）
```

### 操作安全分级表

| 操作等级 | 风险特征 | 确认要求 | 失败处理 | 示例 |
|---|---|---|---|---|
| L0 只读 | 不产生副作用 | 无需确认 | 可重试 | 查询数据、搜索、读取文件 |
| L1 可逆 | 产生副作用但可撤销 | 无需确认 | 可有限重试（≤3 次） | 创建草稿、设置提醒 |
| L2 不可逆 | 不可撤销但影响有限 | 必须确认（操作清单+影响范围） | 不擅自重试 | 删除文件、提交表单 |
| L3 高风险 | 不可逆且影响重大 | 必须确认（+不可逆说明+风险评估） | 不擅自重试，须用户确认 | 资金交易、生产变更、批量删除 |

### 产物落盘

操作结果落盘于 `.tribro/actions/<命名>/`，命名沿用 tri-intent 快照命名规范：

```
.tribro/
└── actions/
    └── <命名>/
        ├── result.md         # 操作结果（最终交付物）
        └── (confirm-log.md)  # 高风险操作确认记录（L2/L3 时）
```

示例：`I14_20250211_143022_6a5c037d/result.md`

> **防篡改机制**：confirm-log.md 落盘时对文件全部内容（不含哈希行本身）计算 SHA-256 内容哈希，以 `<!-- HASH:sha256:<hash_value> -->` 作为文件最后一行附加。审计时重新计算哈希与记录值比对，一致则未被篡改。实现见 `scripts/hash_confirm.py`，用法：`python scripts/hash_confirm.py <file> [--verify <hash>]`。

完整测试用例见 `tests/tri-action-full-testcases.md`，覆盖 4 级操作安全分级、L2/L3 确认门（通过/拒绝/修改）、失败不擅重试机制、confirm-log.md SHA-256 防篡改、最小化原则门禁、参数校验（缺失回退/不合法中止）、上游依赖检测两态逻辑等全部能力点。

## 设计原则

- **分级判定前置**：每个操作 MUST 先判定等级再决定确认要求，不可逆操作跳过确认门即失控
- **高风险有确认**：L2/L3 操作 MUST 经用户明确确认后方可执行，NEVER 默默执行高风险操作
- **失败不擅重**：L2/L3 操作失败后 NEVER 自动重试，避免重复副作用；确认记录一经落盘不得修改（审计完整性）
- **职责边界**：仅依据快照真实执行操作并返回结果，不越界出方案或产出非操作类成果物
