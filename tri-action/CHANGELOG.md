## [1.1.0] - 2026-07-26

### 新增

- **最小化原则门禁规则**：进入执行阶段前 MUST 校验操作范围是否最小化，只执行 `任务要点` 范围内的操作；执行中需扩大操作范围 MUST 向用户说明并确认，NEVER 默默扩大范围
- **上游依赖检测两态逻辑**：支持快照模式 / 引导安装两种执行模式
  - A · 快照模式：检测到 `.tribro/snapshots/` 快照或 `tri-intent/` 目录时，按标准工作流推进
  - B · 引导安装：未检测到上游依赖时，向用户提示并引导安装 `skillhub install tri-intent`
- **confirm-log.md SHA-256 防篡改机制**：高风险操作确认记录落盘时附加 SHA-256 内容哈希
  - 哈希附加：对文件全部内容（不含哈希行本身）计算 SHA-256，以 `<!-- HASH:sha256:<hash_value> -->` 作为文件最后一行
  - 审计验证：重新计算文件内容（去掉最后一行哈希行）的 SHA-256 哈希，与文件末尾记录值比对——一致则未被篡改
  - 不可篡改性：任何对 confirm-log.md 正文的修改都会导致重新计算的哈希与记录值不匹配，从而被审计发现

### 变更

- 强制执行契约新增「最小化原则」门禁规则条款，明确扩大操作范围须用户确认
- 上游依赖检测从隐式依赖改为显式两态判定，独立安装场景下未检测到依赖时硬性阻断
- 明确本 skill 不支持降级模式——模式 B 为硬性阻断，MUST 安装 tri-intent 后方可使用
- 落盘规则明确确认记录一经落盘不得修改（审计完整性），与 SHA-256 防篡改机制配合

## [1.0.0] - 2026-07-24

### 新增

- 初始版本：操作执行下游执行 skill，处理 I14（操作执行）意图，调用工具真实执行动作并返回结果
- 4 级操作安全分级：L0 只读 / L1 可逆 / L2 不可逆 / L3 高风险，每个操作映射到对应确认要求
- L2/L3 确认门：不可逆/高风险操作 MUST 先列出操作清单 + 影响范围 + 不可逆说明（L3 附风险评估），待用户确认后方可执行
- 失败不擅重试机制：L2/L3 操作失败后 NEVER 自动重试（避免重复副作用），L1 可逆操作可有限重试（≤3 次）
- 安全执行链路：解析 → 校验 → 分级 → 确认门（L2/L3）→ 执行 → 返回结果
- 2 个模板：`result.md`（操作结果）+ `confirm-log.md`（高风险操作确认记录）
- 质量标准五维：操作可追溯 / 高风险有确认 / 回执保真 / 失败不擅重 / 参数合法
- 产物落盘至 `.tribro/actions/<命名>/`，L2/L3 操作确认记录与操作结果一同落盘便于审计
