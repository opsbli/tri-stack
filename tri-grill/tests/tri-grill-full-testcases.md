# tri-grill 全场景测试用例

## 测试用例

| # | 场景 | 预期结果 |
|---|---|---|
| T01 | 质询含歧义的需求文档 | 逐条过，每条至少一个挑战；歧义被标注 |
| T02 | 质询清晰的文档 | 逐条过但认可「没问题」；不强行发明问题 |
| T03 | 用户拒绝回答某个问题 | 标注「用户选择不回答」；继续其他条目 |
| T04 | 同一条目连续 3 轮未解决 | 标注「需升级讨论」；继续其他条目 |
| T05 | 质询中产生新决策 | 调用 tri-domain 记录 ADR |
| T06 | 质询中发现新术语 | 调用 tri-domain 写入 CONTEXT.md |
| T07 | 就地更新文档 | 更新处标注 [已对齐 YYYY-MM-DD] |
| T08 | 文档不存在 | 澄清路径；NEVER 凭想象创建 |
| T09 | tri-domain 不可用 | 降级：自行维护简单 Markdown 术语表 |
| T10 | 文档无任何可质询条目 | 告知用户文档已足够清晰 |
| T11 | 结束条件不满足（仍有待定） | NEVER 宣布对齐完成；继续质询 |
| T12 | 结束条件满足（全解决 + 用户确认） | 宣布对齐完成；产出质询记录 |
