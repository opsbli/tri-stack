# tri-grill 全场景测试用例

## 测试用例

| # | 场景 | 预期结果 |
|---|---|---|
| T01 | 质询含歧义的需求文档 | 逐条过，每条至少一个挑战；歧义被标注 |
| T02 | 质询清晰的文档 | 逐条过但认可「没问题」；不强行发明问题 |
| T03 | 用户拒绝回答某个问题 | 标注「用户选择不回答」；继续其他条目 |
| T04 | 同一条目连续 3 轮未解决 | 标注「需升级讨论」；继续其他条目 |
| T05 | 质询中产生新决策 | 调用 tri-domain 记录 ADR |
| T06 | 质询中发现新术语 | 调用 tri-domain 写入 CONTEXT.md |
| T07 | 就地更新文档 | 更新处标注 [已对齐 YYYY-MM-DD] |
| T08 | 文档不存在 | 澄清路径；NEVER 凭想象创建 |
| T09 | tri-domain 不可用 | 降级：自行维护简单 Markdown 术语表 |
| T10 | 文档无任何可质询条目 | 告知用户文档已足够清晰 |
| T11 | 结束条件不满足（仍有待定） | NEVER 宣布对齐完成；继续质询 |
| T12 | 结束条件满足（全解决 + 用户确认） | 宣布对齐完成；产出质询记录 |

## 三、质询维度测试

| # | 场景 | 预期结果 |
|---|---|---|
| T13 | 歧义挑战：「提交」有两种理解 | 提出澄清；获得用户回答后精化文档 |
| T14 | 边界场景：数量为 0 | 发明边界场景；写入 CONTEXT.md |
| T15 | 反例：找到不满足规则的例子 | 提出反例；用户确认或修正规则 |
| T16 | 术语挑战：「入库」含义模糊 | 挑战术语；调用 tri-domain 登记 |
| T17 | 依赖挑战：发现隐含依赖 | 标注依赖；写入文档 |
| T18 | 优先级挑战：质疑 P0 标注 | 用户确认或调整优先级 |

## 四、tri-domain 集成测试

| # | 场景 | 预期结果 |
|---|---|---|
| T19 | 质询中产生新决策 | 调用 tri-domain 记录 ADR |
| T20 | 质询中发现新术语 | 调用 tri-domain 写入 CONTEXT.md |
| T21 | tri-domain 不可用 | 降级：自行维护简单 Markdown 术语表和决策列表 |

## 五、结束条件测试

| # | 场景 | 预期结果 |
|---|---|---|
| T22 | 所有条目已质询 + 无歧义 + 用户确认 | 宣布对齐完成；交付精化文档 |
| T23 | 有一个条目仍有「待定」 | NEVER 宣布完成；继续质询该条目 |
| T24 | 连续 3 轮同一条目未解决 | 标注「需升级讨论」；跳过继续其他条目 |

## 六、兜底测试

| # | 场景 | 预期结果 |
|---|---|---|
| T25 | 文档路径为文件（非目录） | 澄清；NEVER 继续 |
| T26 | 文档内容为空 | 告知用户文档为空，无可质询 |
| T27 | 版本检查报 D 态 | 放行但告警 |
