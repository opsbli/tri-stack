# 质询技巧参考

## 六维质询法

### 1. 歧义挑战
一个词、一句话有两种以上合理解读 → MUST 澄清。
- 「提交」= 提交表单？提交审批？提交到数据库？
- 「用户」= 登录用户？管理员？访客？

### 2. 边界场景
每个规则 MUST 至少发明一个极端情况。
- 数量为 0？负数？超大？
- 两个人同时操作？
- 网络中断时提交？

### 3. 反例
找一个不满足规则的例子。
- 「所有资产必须有序列号」——租赁资产呢？

### 4. 术语挑战
检查术语是否有歧义或多重含义。
- 「入库」是物理入库还是系统录入？
- 「审核」是谁审？审什么？通过标准是什么？

### 5. 依赖挑战
这条功能依赖什么？谁先做？外部接口在哪？
- 需要物资分类先配置好？
- 依赖微信小程序的开放接口？

### 6. 优先级挑战
这个功能没有它系统能跑吗？能跑 → P2 而不是 P0。
- 「导出 Excel」没有它系统照跑 → P2
- 「登录鉴权」没有它任何人都能操作 → P0
