## 一、质疑的成立性判定

**结论：成立。** 质疑不是修辞，它指向 5 处可实测的缺口（G1–G5）。逐条证据见 §二。

但同时须澄清**边界**：本 skill 已具备的 3 项防作弊条款（委派诚实铁律 / 反规避 / 结论可信度声明）**确实存在且有效**，
只是它们的防区是「**单轮内的诚实**」，而质疑指向的是「**执行者的独立性**」与「**跨轮的单调性**」——
两者不重叠，所以不是「已有条款没做好」，而是「**没有这类条款**」。

## 三、缺口枚举

| # | 缺口 | 归类 | 后果 |
|---|---|---|---|
| **G1** | 「外部借力」在当前环境是**名义的**（E1+E2） | 独立性 | 实际唯一执行者 = 与 tri-prototype 同源的同一 agent ⇒ 实质自审 |
| **G2** | 报告无**独立性声明**（E2）；`audit-dimensions.md:136` 的「结论可信度声明」只写「就绪度来自市面 skill」，**隐含**了并不存在的外部性 | 诚实性 | 读者会误判结论的独立性等级 |
| **G3** | 八维是**清单式**判据，与强制公理 A38/D45「禁止自证式检查」**直接冲突**（E3+E6） | 方法学 | 通过 = 确认在场；无人负责「攻击这份文档」 |
| **G4** | 跨轮**无单调性守卫**、无轮次账本（E4+E5） | 收敛性 | **正是「多轮后自己掩饰问题自己通过」的机制本体**：P0 可在零新证据下逐轮降级，而每轮单看都「守规矩」 |
| **G5** | 结论无**可复算证据**强制要求（报告不强制 `file:line` + 引文） | 可验证性 | 用户无法抽查复算，只能整体采信 |

> **G4 是最危险的一条**：G1–G3 是「单轮就不独立」，用户看得见；G4 是「每轮都合规、合起来失真」——
> 隐蔽且不可归因，与补丁层「坑 4 / 坑 5」同类（单步无异常、整体错）。

## 四、设计（五件套 H1–H5）

### H1 · 新增 **D9 对抗维**（判据入 `references/audit-dimensions.md`）

不改 D1–D8 的口径（它们服务「可消费性」），**新增一维**：

| 检查 | 判据 | 通过条件 |
|---|---|---|
| 错误场景构造 | 主动回答「**这份文档最可能让下游做错的三件事是什么**」 | MUST 产出 **≥3 条具体错误场景**，每条为「若按此文档开工 → 下游会做出 X → 证据位置」 |
| 反例优先 | 先找反例，再找支持 | 至少 1 条场景 MUST 相 **D1–D8 全绿** 的条目（即「看起来没问题」处） |
| 诚实缺席 | 无法构造错误场景时 | MUST 写「本维无发现」**并附尝试过的 3 个攻击入口**；NEVER 留空或写「无问题」 |

> **判据**：报告**无「对抗式审查结论」小节 = 违规**（对齐 `metago-adversarial-review` 的 A38/D45）。
> **与 D4 的 MECE 区分**：D4 问「边界/异常**是否交代**」；D9 攻击「**交代了也照样会错**」——主键不同（在场 vs 可被证伪）。

### H2 · 报告必填 **`independence=` 声明**（扩 `audit-dimensions.md` §五）

| 取值 | 含义 | 附加要求 |
|---|---|---|
| `same-agent` | 审核方与被审文档同源（**当前唯一可达态**） | MUST 写明「本次审核**非独立第三方**」；**报告全文禁用「独立审核 / 第三方视角」字样** |
| `cross-context` | 审核在**独立子会话**执行（生成方 context 未参与） | 记录子会话标识 |
| `cross-model` | 含真实异构模型交叉验证 | 记录供应商/模型清单与调用回执 |

> 与既有 `delegation=` 并列，不替代它。`delegation=unavailable` 时 **MUST** `independence=same-agent`。

### H3 · **轮次账本 + 单调性守卫**（新增落盘产物）

`.tribro/req-audit/<命名>/round-ledger.jsonl`，每轮一行：

```json
{"round":2,"p0":0,"p1":5,"p2":3,"new_evidence":0,"changes":"tri-prototype 回炉重出","verdict":"有条件开工"}
```

**守卫规则（门④ 执行，硬）**：

| 信号 | 判定 | 处置 |
|---|---|---|
| P0 或 P1 数量**下降** 且 `new_evidence == 0` | **收敛造假嫌疑** | **强制升级人审**，本轮判定降为「待复核」，NEVER 直接放行 |
| 任一 P 级**降级**（P0→P1/P2 等） | 需证据 | MUST 附新证据并在账本 `downgrades[]` 留痕；无证据则**驳回降级** |
| P0 数量**上升** | 正常（回炉引入新问题） | 记录，不拦截 |

> 这条把 E4 的「单轮反规避」补成「**跨轮反收敛**」。它是 G4 的唯一解药。

### H4 · **对抗委派**（二跳扩展 · 可选增强）

在既有「中介 → 市面 PRD 审核 skill」之外，增第二条二跳链：

| 优先级 | 候选 | 形态 | 可用性（实测） |
|---|---|---|---|
| 1 | `metago-adversarial-review` | 本机已装 v1.0.6，家族外（MetaGO） | ✅ 已装 |
| — | 不可用 | 降级为 **H1 内置 D9** | 标注 `delegation.adversarial=unavailable` |

> **需登记**：family-spec §五「待登记项」新增一行（对抗委派二跳，被执行方为**家族外** skill）。

### H5 · **可复算证据**（判据入 `audit-dimensions.md` §四）

每条 P0 / P1 **MUST** 附 `文件:行号` + **原文引文**（≥1 行原样），使结论可被第三方独立复算。
无引文的条目降为 P2 并标注 `evidence=unverifiable`。

## 九、验收标准

1. 报告**必含**「对抗式审查结论」小节，≥3 条可证伪错误场景，每条带证据位置；缺则判违规
2. 报告**必含** `independence=`；为 `same-agent` 时全文不出现「独立审核 / 第三方」字样
3. **构造用例**：第 2 轮把某 P0 改为 P2 且 `new_evidence=0` ⇒ 守卫 MUST 拦截并升级人审（不得放行）
4. 每条 P0 / P1 附 `file:line` + 引文，第三方可按引用复算；无引文条目自动降 P2
5. `metago-adversarial-review` 未装时，降级为内置 D9，报告标注 `delegation.adversarial=unavailable`
6. 五处版本线一致（1.1.0）+ `version-lint.py` exit 0 + `apply.py` 第二次「写入 0」
7. **反例守卫**：把 D9 小节整段删除后重跑门④，MUST 判不通过（证明 D9 不是装饰）
