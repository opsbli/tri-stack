# token 成本模型（节点 / 评估 / 建议速查）

> 本文件是 tri-cost 的参考表单一事实源。SKILL.md 正文引用此处，检索用 grep 模式：`节点 N`、`评估维度`、`建议类型`。

## 一、关键节点划分（标准链路八节点）

> tri-cost 默认把「用户提问 → 最终答案」拆为 8 个关键节点。新节点可扩展追加（N9+），分账逻辑自动适配。

| 节点 | 名称 | 输入锚点 | 输出锚点 | 典型消耗来源 |
|------|------|----------|----------|--------------|
| N1 | 用户提问输入 | 用户 prompt | 意图识别入口 | 用户 prompt 编码 token |
| N2 | 意图识别 | N1 输出 | 快照 §一/§三 | tri-intent 识别 + 维度标注 |
| N3 | 快照落盘 | N2 输出 | snapshot.md | 快照生成 |
| N4 | 下游读取快照 | snapshot.md | 下游 skill 上下文 | 下游读取快照 §三 |
| N5 | 核心执行 / 工具调用 | 下游 skill 上下文 | 中间结果 | 多轮推理 + 工具调用结果注入 |
| N6 | 推理思考 | N5 中间结果 | 决策 | CoT / 反思 token |
| N7 | 最终答案生成 | N6 决策 | 答案草稿 | 回答输出 token |
| N8 | 输出 | N7 草稿 | 用户可见答案 | 交付渲染 token |

**扩展规则**：新增节点时，在节点表追加一行（节点/名称/输入锚点/输出锚点/典型消耗来源），COST_TRACK 按新节点取样，COST_AUDIT 自动分账。

## 二、评估维度（逐节点三问）

> COST_AUDIT 对每个节点输出三要素，判定档位定义如下。

### 2.1 是否必要（necessity）

| 档位 | 定义 | 典型节点 |
|------|------|----------|
| 高 | 产生最终答案不可替代的输入 | N5 核心执行、N7 答案生成 |
| 中 | 产生可复用/可裁剪的辅助价值 | N2 意图识别、N3 快照落盘 |
| 低 | 价值可被其它节点替代或可省略 | 冗余推理、重复上下文注入 |

### 2.2 是否可优化（optimizability）

| 档位 | 定义 | 典型信号 |
|------|------|----------|
| 高 | 有明显省 token 空间 | 长上下文反复注入、冗余工具重试、CoT 过长 |
| 中 | 有部分优化空间 | 可改用摘要/缓存、可裁剪背景 |
| 低 | 已较精简，空间有限 | 单轮短问答 |

### 2.3 改进建议（suggestion）

MUST 给出可执行动作，NEVER 空话。动作来自下方建议类型速查。

## 三、建议类型速查

> 触发条件供 COST_AUDIT 结合节点档位命中；grep 模式：`建议类型`。
> **方法底座扩展**：下表末两行（输出风格压缩、载荷类型感知摘要）蒸馏自开源项目 caveman，完整架构/分类法/边界见 `caveman-distill.md`（其方法为 MIT，引擎为 BSL-1.1，本 skill 只引用方法、不打包运行时）。

| 建议类型 | 动作示例 | 适用节点 | 触发条件 |
|----------|----------|----------|----------|
| 精简提问 | 收敛问题范围、去掉多余背景、一次一问 | N1 | N1 消耗高 或 提问含冗余背景 |
| 裁剪上下文 | 只注入近 2 轮摘要而非全文、按需注入文件片段 | N4/N5 | 上下文注入长 或 重复注入 |
| 复用缓存 | 命中 tri-cache 历史作答、参考注入摘要 | N4/N5 | 同类问题重复出现 |
| 收敛工具调用 | 合并重复检索、减少无效调用、限制重试次数 | N5 | 工具调用次数多 或 重试频繁 |
| 缩短推理 | 简单任务关闭 CoT、限步数、用快速模型 | N6 | 推理 token 占比高 或 任务确定性强 |
| 摘要输出 | 交付用摘要替代全文、分级输出 | N7/N8 | 输出超长 或 用户仅需结论 |
| 快照剪枝 | 快照只保留下游必需字段、去除冗余章节 | N3/N4 | 快照体积大 或 下游只读部分字段 |
| 降本模型 | 简单任务切低价模型、输入复用缓存前缀 | N5/N7 | 模型单价高 或 任务复杂度低 |
| 输出风格压缩 | 用 concise/terse 风格生成、删填充客套、保代码与错误串、Auto-Clarity 回退 | N7/N8 | 输出冗长 或 口语化严重 |
| 载荷类型感知摘要 | 对 json/log/code/diff/search-result/text/html/terminal/tabular/config 按类型摘要，保留错误/结构/变更行 | N4/N5 | 工具输出/日志体量大 |

## 四、成本估算与高消耗判定

- **成本估算**：`cost = Σ input_tokens × input_price + Σ output_tokens × output_price`（单价见 `_meta.json` price 表）。
- **高消耗标记**：`high_cost = (node_total_tokens ≥ total_tokens × high_cost_ratio) OR (node_total_tokens ≥ high_cost_tokens)`。
- **ROI 评分**：`roi = value_injection / normalized_cost`，`value_injection ∈ [0,1]` 由审计时按节点价值注入度打分，`normalized_cost = node_cost / max(node_cost)`。
- 实现见 `scripts/cost_eval.py`。
