# 蒸馏专业技能方法论（distill-skill）

> 被 tri-god 在识别对象类型=专业技能（skill/手艺/专家能力）后加载。
> **核心信条**：捕捉的是「专家的决策规则与启发式（heuristics）」，而非「教科书知识」——把隐性专家经验（tacit knowledge）**显性化**为可被 Agent 执行的行为规则。教科书讲 WHAT，本方法论追 HOW & WHEN experts decide。

## 引用合规（MUST）

- 引用他人教程/课程/文档单条 ≤150 字，MUST 保留出处；主体以「自述重写」承载技能逻辑。
- NEVER 照搬受版权保护的培训材料或认证体系原文；蒸馏产出须标注素材来源与专家署名，尊重许可证。

## Phase 1 · 技能边界界定

MUST 先框定这项技能的边界，缺口不补齐 NEVER 进入采集：

| 界定项 | 内容 |
|--------|------|
| 解决什么问题 | 这项技能针对哪类问题、在什么场景被调用 |
| 输入 | 施展技能所需的前提、素材、信息 |
| 输出 | 技能产出的成果形态与交付物 |
| 成功标准 | 如何判定这次施展是否成功（可度量） |
| 施展者画像 | 谁在用、专家 vs 新手的差距在哪 |

## Phase 2 · 专家行为采集

MUST 基于**真实专家行为**（案例/访谈/复盘），采集隐性经验的四类载体：

| 采集项 | 内容 |
|--------|------|
| ① 案例复盘 | 专家处理真实问题的完整过程回放 |
| ② 关键决策点 | 专家在哪些岔路口做了判断、当时看到了什么信号 |
| ③ 经验法则 | 专家挂在嘴边的「一般来说…」「除非…」土规则 |
| ④ 常见陷阱 | 专家会主动规避、但新手常踩的坑 |

> MUST 追问「你当时为什么这么判断」——决策背后的信号识别，才是隐性知识的核心。

## Phase 3 · 启发式提炼

将采集素材提炼为可执行的决策结构（这是蒸馏的核心产物）：

1. **IF-THEN 决策规则（MUST）**：形如「IF 观察到 X THEN 采取 Y，因为 Z」，每条规则可回溯到具体决策点。
2. **优先级排序**：多规则冲突时的先后次序（先看什么、后看什么）。
3. **权衡取舍（Trade-offs）**：在对立目标间如何取舍（如「速度 vs 稳妥」），及取舍的判据。

> MUST 每条 IF-THEN 可回溯到 Phase 2 真实决策点，NEVER 虚构专家未展示过的规则。

## Phase 4 · 执行步骤形式化

将启发式落为可操作规格：

| 规格项 | 内容 |
|--------|------|
| 1-2-3 步骤 | 施展技能的有序、可核对操作步骤 |
| 检查清单 | 每个关键节点的自检项（防遗漏） |
| 决策嵌入 | 把 Phase 3 的 IF-THEN 规则挂到对应步骤上 |

> MUST 可执行、不空泛——步骤须具体到「做什么动作、看什么指标」，NEVER 停留在「要注意…」的口号。

## Phase 5 · 反模式与边界

MUST 显式标出技能的**失效区**：

- **反模式（Anti-patterns）**：什么情况下这套技能不该用、会适得其反。
- **新手常犯错误**：新手施展时最容易出错的点（对应 Phase 2 常见陷阱）。
- **专家盲区**：连专家也易犯的系统性偏差、或本技能覆盖不到的领域。
- **适用边界**：技能在什么条件下成立、超出边界即失效。

## Phase 6 · 生成技能 skill + 诱饵压力测试

将上述封装为可独立调用的技能 skill：

- **SKILL.md**：定位（解决什么问题）+ IF-THEN 决策规则 + 1-2-3 步骤与检查清单 + 反模式清单 + 适用边界，用 MUST/NEVER 约束行为。
- **description MUST 明确 trigger**：让 Agent 知道「遇到什么问题该加载本技能」。
- **压力测试（MUST）**：
  - **正例测试**：真实应施展场景能否正确激活并给出专家级判断。
  - **诱饵测试（关键）**：构造「看似该用实则不适用」的诱饵场景，验证 skill NEVER 越界误用。
- **配套**：素材来源清单、专家署名、示例走查（体现决策规则如何运作）。

## 阶段化对接 tri-god 审批门

| tri-god 门 | 本方法论阶段 |
|---|---|
| 门① requirements.md | Phase 1 的技能边界（问题/输入输出/成功标准/用途） |
| 门② design.md | 「加载 distill-skill + 六阶段规划 + 启发式提炼与形式化计划」 |
| 门③ tasks.md | 拆解为行为采集 → 启发式提炼 → 步骤形式化 → 反模式梳理 → skill 构造 + 压力测试任务（含复选框） |
| 执行 → implements.md | Phase 2~6 执行记录 + 决策规则可追溯性核对 + 压力测试结果 |

## 质量红线（全过方可交付）

- [ ] 含 IF-THEN 决策规则，且每条可回溯到真实决策点。
- [ ] 含反模式清单（反模式 / 新手错误 / 专家盲区）。
- [ ] 执行步骤可操作、不空泛，具体到动作与指标。
- [ ] 明确标注适用边界与失效条件。
- [ ] 含诱饵压力测试，诱饵场景不误触发/误用。
- [ ] 引用限长、保留出处、标注专家署名，不照搬受版权材料。
