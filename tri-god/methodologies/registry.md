# 蒸馏方法论注册清单（Registry）

> 本文件是 tri-god 方法论加载机制的**唯一注册入口**。
> 新增蒸馏对象类型只需：① 在本目录创建 `distill-<type>.md` → ② 在本文件追加一条注册记录。
> tri-god 在识别蒸馏对象类型后读取本文件，按识别特征匹配并加载对应方法论文件。

## 加载机制

```
tri-god · 识别蒸馏对象类型
        │
        ▼
  读取本 registry.md
        │
        ▼
  按注册表「识别特征」逐条匹配用户素材与快照结论
        │
        ├── 命中某一类型 → 加载对应 distill-<type>.md
        └── 全部未命中 / 跨类型混合 → 加载 distill-general.md（兜底）
```

**加载规则**：
1. 每次蒸馏**只加载一个**方法论文件（对象类型互斥，不叠加）。
2. 识别顺序：优先精确匹配（human/workflow/skill/thing），无法归类或混合时兜底到 `general`。
3. 加载后严格按该方法论的阶段化流程串行执行，方法论各阶段在 tri-god 的 design.md「方法论各阶段规划」环节展开。
4. 对象类型判定结论 MUST 写入 design.md 并经门②审批，禁止执行阶段擅自更换方法论。

## 注册表

| 对象类型 | type_id | 识别特征（满足任一即命中） | 方法论文件 | 一句话说明 |
|---|---|---|---|---|
| 人类 | human | 蒸馏某个人的思维/表达/决策方式；对象是人物、专家、作者、KOL；素材含其著作/访谈/演讲/社媒 | `distill-human.md` | 捕捉「HOW they think」而非「WHAT they said」，产出人物思维 skill |
| 工作流 | workflow | 蒸馏一套可复用流程；对象是操作步骤序列、协作机制、SOP、审批链路；素材含流程实例/记录 | `distill-workflow.md` | 从流程实例抽象出阶段+状态机+审批门，形式化为可执行 workflow skill |
| 专业技能 | skill | 蒸馏一门可操作的专业技能/手艺/方法；对象是技术、工艺、方法论；素材含教程/操作文档/示范 | `distill-skill.md` | 提炼技能的操作步骤+判断准则+边界，产出可复用技能 skill |
| 事物 | thing | 蒸馏书/视频/课程/文档等长内容中的知识框架；素材是可通读的长文本/内容 | `distill-thing.md` | 五阶段 RIA-TV++ 流水线 + 三重验证 + RIA++ 六段，产出知识框架 skill |
| 其它/不确定 | general | 无法归入上述类型，或跨类型混合 | `distill-general.md` | 通用兜底：需求澄清 → 提取 → 验证 → 构造 → 交付 |

## 对象类型判定辅助（结合快照维度）

| 快照信号 | 倾向类型 |
|---|---|
| D1_任务领域=人物/传记，素材为某人语料 | human |
| D1_任务领域=流程/运营，素材为步骤/SOP | workflow |
| D1_任务领域=技术/工艺，素材为教程/操作说明 | skill |
| D2_输入形态=长文本/书/课程/视频转录 | thing |
| 混合信号或无法归类 | general |

## 扩展指南

新增蒸馏对象类型步骤：

1. **创建方法论文件**：在本目录创建 `distill-<type>.md`，顶部带 frontmatter（`name` / `description`），正文含阶段化流程与质量红线。
2. **注册**：在本文件「注册表」表格追加一行，填写对象类型 / type_id / 识别特征 / 方法论文件 / 一句话说明。
3. **补充判定辅助**（可选）：在「对象类型判定辅助」表追加快照信号 → 类型的映射。
4. **无需修改 tri-god/SKILL.md**——加载机制通过本 registry.md 驱动，天然可扩展。

## 引用合规提示（全类型通用）

所有方法论在蒸馏涉及原文时 MUST 遵守：
- 原文直接引用限长（建议单条 ≤150 字），保留出处。
- 以「自述重写」为主，避免整段照搬原文。
- 蒸馏产出的 skill 中标注素材来源，尊重原作者署名与许可证。
