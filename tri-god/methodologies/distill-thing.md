# 蒸馏事物方法论（distill-thing）

> 被 tri-god 在识别对象类型=事物（thing，书/视频/课程/文档等长内容）后加载。
> **目标**：把一段可通读的长内容提炼成一个承载其知识框架、可被 Agent 独立调用的 skill，而非内容摘要。

## 引用合规（MUST）

- 原文直接引用单条 ≤150 字，保留章节出处；主体以「自述重写」承载知识。
- NEVER 整段搬运原文；蒸馏产出须标注内容来源与作者署名，尊重许可证。
- 素材含敏感信息（商业机密/专有流程细节/个人隐私等）时，MUST 先与用户确认脱敏范围，蒸馏产物 NEVER 保留可识别的敏感细节。

## 断点续跑机制

MUST 在工作区维护 `PIPELINE_STATE.md`，记录当前阶段与各阶段产物状态；中断后据此续跑，NEVER 从头重来。

## 五阶段 RIA-TV++ 流水线

### 阶段 0 · 整书理解

通读长内容，建立全局地图：主题、结构骨架、核心论点、章节脉络。产出「全局理解笔记」作为后续提取的锚点。

### 阶段 1 · 并行五提取器

MUST 并行运行五个提取器（可派子任务），分别产出结构化清单：

| 提取器 | 提取内容 |
|--------|----------|
| ① 框架提取器 | 核心概念框架、模型、分类体系 |
| ② 原则提取器 | 可迁移的原则、规律、启发式 |
| ③ 案例提取器 | 正面案例、示范、成功实践 |
| ④ 反例提取器 | 反面案例、失败教训、常见误区 |
| ⑤ 术语提取器 | 关键术语、定义、专有名词 |

### 阶段 1.5 · 三重验证

对提取结果 MUST 逐条过三重验证，未通过者剔除或修正：

| 验证 | 检验点 |
|------|--------|
| V1 · 跨域验证 | 该知识点是否在原内容领域之外仍成立/可迁移 |
| V2 · 预测力验证 | 该原则能否预测新情境的结果（有预测力才是真知识） |
| V3 · 独特性验证 | 该知识点是否非平庸、非常识、具备独特价值 |

### 阶段 2 · RIA++ 构造 skill（六段）

将验证后的知识封装为 skill 的六段结构：

| 段 | 代号 | 内容 |
|----|------|------|
| 原文引用 | R | 关键原文引用（≤150 字/条，保留出处） |
| 自述重写 | I | 用自己的话重写知识框架（主体） |
| 过去案例 | A1 | 该知识曾适用的历史案例 |
| 未来触发 | A2 | 何时该调用本 skill → 写入 description 的 trigger |
| 执行步骤 | E | 应用该知识的可操作步骤 |
| 边界 | B | 适用边界与失效条件 |

> **description MUST 明确 trigger**：由 A2（未来触发）导出，让 Agent 知道「遇到什么情境该加载本 skill」。

### 阶段 3 · Zettelkasten 链接

为知识点建立卡片式双向链接，标注知识点间的关联（支撑/对立/递进/前置），形成可导航的知识网络。

### 阶段 4 · 压力测试（含诱饵测试）

MUST 对产出 skill 做压力测试：

- **正例测试**：真实应触发场景能否正确激活并给出正确知识。
- **诱饵测试（关键）**：构造「看似相关实则不该触发」的诱饵场景，验证 skill NEVER 误触发/误用。

### 阶段 5 · 交付 DIGEST.md

产出 `DIGEST.md` 交摘要：蒸馏概览、六段结构索引、三重验证通过记录、压力测试结果、素材来源清单。

## 质量红线（全过方可交付）

- [ ] 全部知识点通过三重验证（V1 跨域 / V2 预测力 / V3 独特性）。
- [ ] RIA++ 六段完整（R/I/A1/A2/E/B）。
- [ ] 原文引用限长（≤150 字/条）、保留出处。
- [ ] 含诱饵测试，且诱饵场景不误触发。
- [ ] description 明确 trigger（由未来触发 A2 导出）。
- [ ] 交付 DIGEST.md，素材来源可追溯。
