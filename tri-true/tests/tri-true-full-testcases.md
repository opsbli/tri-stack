## 四、TC-02 强制执行契约验证（12 用例）

> 验证强制执行契约章节定义的强制前置、四道防线铁律、最小化、幻觉类型分流、IDK 阈值、人审兜底、隐私过滤、成本控制、自检句等最高优先级规则。

### TC-02-01：触发源激活——下游 skill 委派触发 VERIFY_EXECUTE
- **前置条件**：调用方（如 tri-coding）判定高风险结论需幻觉消除，调用本 skill 执行接口
- **测试步骤**：1. 模拟委派触发；2. 校验 skill 是否激活
- **预期结果**：触发源命中即激活，MUST 不当参考文档；进入 VERIFY_EXECUTE 流程
- **通过标准**：PASS——委派触发激活；FAIL——未激活或当参考文档

### TC-02-02：触发源激活——用户直接调用触发 VERIFY_EXECUTE
- **前置条件**：用户发起验证请求"验证这个回答"
- **测试步骤**：1. 模拟用户直接调用；2. 校验 skill 是否激活
- **预期结果**：进入 VERIFY_EXECUTE 流程
- **通过标准**：PASS——显式触发激活；FAIL——未激活

### TC-02-03：VERIFY_EXECUTE 前置——先上下文收集再防线一
- **前置条件**：VERIFY_EXECUTE 模式激活
- **测试步骤**：1. 检查是否先执行上下文收集（风险等级/领域/段落切分）；2. 校验是否走防线一置信度评估
- **预期结果**：MUST 先收集上下文，再走防线一，NEVER 跳过任何防线直接交付
- **通过标准**：PASS——先收集再防线一；FAIL——跳过防线

### TC-02-04：四道防线铁律——高置信+知识类型放行防线一
- **前置条件**：原文为一般信息查询，risk_level=low，知识类型=common/known
- **测试步骤**：1. 模拟低风险内容；2. 计算三层置信度；3. 校验综合置信度 ≥ 0.7；4. 校验知识类型 ∈ {common, known}
- **预期结果**：综合置信度 ≥ 阈值（low=0.7）**且**知识类型允许放行（common/known），防线一放行，标记 verified（附置信度+知识类型），不触发防线二
- **通过标准**：PASS——高置信+允许放行的知识类型方可防线一放行；FAIL——高置信但知识类型为 inferred/iframe/guess/computed 仍防线一放行

### TC-02-05：四道防线铁律——中低置信触发防线二
- **前置条件**：原文含事实性主张，综合置信度 < 阈值
- **测试步骤**：1. 计算三层置信度；2. 校验综合置信度 < 阈值；3. 校验是否触发防线二

### TC-02-06：四道防线铁律——T1/T2 支撑防线二放行
