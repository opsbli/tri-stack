# Changelog

本文件记录 tri-fix skill 的版本变更历史。

格式基于 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。


## [1.5.0] - 2026-09-26

### 新增

- **交付前风险预筛自动门（tri-true 自动委派）**：解决「何时触发幻觉核查」靠人工判断的缺口——本 skill 在最终交付前自动执行确定性风险预筛（R1 YMYL 领域 / R2 破坏性或高风险操作 / R3 无法本地自证的外部断言 / R4 低置信 / R5 单点依据或对外发布），命中即自动委派 tri-true 开 `VERIFY_EXECUTE`，跑 `confidence_calc.py` 三层置信度门 + 人审盖章，落盘 `.tribro/true/<命名>/`。诚实边界：自动层落地置信度门 + 事实源自检 + 人审标记；多模型交叉验证（UAF/T1-T4）需 key 与 RAG 基础设施，仅留方法论占位，NEVER 假装调用。版本号 1.4.1 → 1.5.0（新功能）。

## [1.4.1] - 2026-09-24

### 变更

- **分支收窄为编程工作流专线（22 skill）**：清理对已移除 skill 的交叉引用——职责边界表 / 不由本 skill 处理表的对应行改为「本分支未包含（原 tri-xxx）」或删除；已删的委派关系与相邻边界说明同步失效。非功能性变更（文档）。

## [1.4.0] - 2026-09-20

### 新增

- **阶段 3 前置「证据增强三式」**（蒸馏自系统化调试方法论的根因调查与模式分析增量）：近期变更扫描（git diff/新依赖/配置变更）、多组件断裂点埋点（先定位断裂层再猜具体原因）、正常示例对比（模式分析，逐项列差异不预判）。阶段编号体系不变（1-6 唯一编号），三式作为阶段 3 的前置小节。
- **阶段 4 架构质疑语义**：「最多 3 轮」升级求助从单纯求助扩为「停止并质疑架构」——每次修复暴露新耦合/别处新症状 = 架构缺陷信号，NEVER 未做架构讨论盲试第 4 次。

## [1.3.2] - 2026-09-18

### 新增

- **职责边界补「不触发场景（Not-Trigger）」**（对齐全家族 skill 写作规范）：明确本 skill 不接手既有目标代码不存在的新功能开发（tri-coding）、只审查不改码（tri-review）、只求解释不求修复的咨询（tri-ask）与意图识别（tri-intent），强化「先诊断后修复」边界。

## [1.3.0] - 2026-08-03

### 新增
