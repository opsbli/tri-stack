## 一、判定字段说明

| 字段 | 含义 | 判定标准 |
|---|---|---|
| **激活条件** | skill 是否被正确激活 | 收到 tri-intent 快照且 L2=I12 |
| **链路顺序** | 各阶段/审批门串行顺序 | 严格按门①→门②→门③，不可跳门 |
| **复选框状态** | 任务/测试条目状态标记 | 默认 `- [ ]`；完成 `- [x]`；回炉重置 `- [ ]` |
| **方法论阶段** | 6 阶段调试方法论执行 | 每阶段完成标准满足 |
| **产物完整性** | 链路文档结构与落盘 | 4 个文档结构完整且落盘正确 |

## 二、评分规则

- 每条用例核心断言全部命中记 **PASS**，任一不符记 **FAIL**
- 通过率 = PASS 数 / 总用例数
- **质量门槛**：元数据/输入契约/职责边界场景 ≥95%，执行契约/审批门/链路文档场景 ≥90%，整体 ≥90% 视为达标

- **前置条件**：阶段 6 清理执行中
- **测试步骤**：1. 用前缀 grep 检查 `[DEBUG-...]` 标签；2. 校验清理结果
- **预期结果**：所有 `[DEBUG-xxx]` 插桩已移除；一次性原型已删除（或移到明确标注的调试位置）
- **通过标准**：PASS——DEBUG 标签全部清除；FAIL——残留标签

### TC-08-06：最小化修复原则
- **前置条件**：阶段 5/7 修复执行中
- **测试步骤**：1. 检查修复策略；2. 校验修复范围
- **预期结果**：最小化修复——只改根因处，不越界，不顺便重构、不顺便优化；记录修复内容，保持改动最小化
- **通过标准**：PASS——仅改根因处；FAIL——越界重构

### TC-08-07：事后复盘含架构改进建议
- **前置条件**：阶段 6 事后复盘执行中
- **测试步骤**：1. 检查事后复盘内容；2. 校验是否含架构改进建议
- **预期结果**：问「什么本可以避免这个 bug？」；若答案涉及架构改动（无好测试接缝/调用方纠缠/隐藏耦合），把具体情况交接给 tri-review 或建议架构改进；在修复落地之后再给建议
- **通过标准**：PASS——复盘含架构改进建议且在落地后给出；FAIL——无复盘或无建议
