# 判据印章模板

> `tri-verify` 产物之一。文件名固定 `verdict.md`，存放于 `.tribro/verify/<命名>/`。
> **每轮执行 MUST 产出本文件** —— 包括「未触发」与「未执行」两种结局，
> 否则调用方无法区分「判定后跳过了」和「忘了验证」。

---

## 一、判据印章（四态封闭判据 · 五选一）

> MUST 从下表**恰好选一个**盖章，NEVER 自造态名。盖章行放在本文件首行（便于机器读取）。

| 盖章 | 含义 | 是否阻断交付 |
|---|---|---|
| `功能验证: 通过（engine=<id>，用例 n/n）` | 冒烟层全过 | 否 |
| `功能验证: 修复后通过（轮次 n，归因 A/B/C）` | 有界循环内收敛 | 否 |
| `功能验证: 已升级人审（连续 2 轮同类失败，归因 <X>）` | 未收敛 | **是**（停止自动交付） |
| `功能验证: 未执行（<原因>）` | 降级矩阵命中 | 否；但 **V5 命中时转人审** |
| `功能验证: 未触发（可交付）` | V1–V5 全未命中 | 否 |

```
功能验证: <盖章原文>
```

---

## 二、判定依据

| 项 | 值 |
|---|---|
| 委派来源 | 来源 A / B / C |
| 触发规则判定 | V1 <命中/未命中> · V2 <…> · V3 <…> · V4 <…> · V5 <…> |
| 判定结论 | 执行 / 跳过 / 强制 |
| 使用引擎 | `local` / `testsprite` / 两者（**逐条标注哪条走了哪个**） |
| 降级发生 | 是（原因：<…>）/ 否 |

---

## 三、运行台账

| 轮次 | 引擎 | testId | runId | 状态 | 退出码 | 归因 | 备注 |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | |
| 2 | | | | | | | |

> 归因列填 A / B / C / `uncertain` / `—`（通过）。
> **契约变更（B）与重试（C）不计入轮次**，但 MUST 在备注中记账。

---

## 四、复验对比（来源 B 或有修复时必填）

| 项 | 值 |
|---|---|
| 修复前 runId | `<run-a>` |
| 修复后 runId | `<run-b>` |
| 运行对比结果 | `verdictMatch=true`（无回归） / `false`（**有回归**） |
| 回归详情 | `<per-step 状态翻转 / codeVersion drift>` |

> `verdictMatch=false` 时 MUST 继续归因**新出现的失败**，NEVER 直接判「修复完成」。

---

## 五、未执行 / 未触发时的强制说明

> 若盖章为「未执行」或「未触发」，本节 MUST 填写完整，否则调用方无法评估残余风险。

| 项 | 值 |
|---|---|
| 具体原因 | <无可用引擎 / 目标不可达 / 凭证缺失 / 额度不足 / V1–V5 未命中 / 判 V3> |
| **判 V3 的依据** | <交付物无运行时入口的证据：纯库 / 纯类型 / 纯静态资源> |
| 残余风险 | <未验证的部分可能存在的风险> |
| 建议的后续动作 | <何时/如何补验> |

> ⚠️ **反规避**：`未执行` 与 `未触发` MUST NOT 被调用方当作 `通过` 消费。
> 调用方消费本文件时 MUST 按 §一 五态区分，NEVER 只判断「有没有红」。

---

## 六、升级说明（盖章为「已升级人审」时必填）

| 项 | 值 |
|---|---|
| 轮次记录 | <第 1 轮归因 X，第 2 轮归因 X> |
