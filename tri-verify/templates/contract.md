# 验证契约模板

> `tri-verify` 产物之一。文件名固定 `contract.md`，存放于 `.tribro/verify/<问题类型_日期_时间_会话ID>/`。
> 本契约是**行为契约**，不是选择器脚本：只描述「用户做什么、应看到什么」，元素定位交给执行引擎。
> 派发执行前 MUST 先通过本地契约校验（零成本）。

---

| 验证层级 | 冒烟层 / 回归层 |

## 二、用例清单

### C01 · <一句可断言的行为陈述>

> **命名要求**：用例名 MUST 是一句**可以断言的行为陈述**，不能只写「登录测试」这类名词短语。
> 反例：`登录测试` · `测试注册功能`

| 项 | 值 |
|---|---|
| 用例 ID | C01 |
| 优先级 | p0 / p1 / p2 / p3 |
| 关联需求 | `requirements.md` 的哪条验收标准（**无对应条目则 MUST 先回炉补需求**） |
| 目标区域 | `<页面 / 接口>` |

**步骤**（一步只做一个动作；「搜索并打开第一个结果」必须拆成两步）：

| # | 类型 | 描述 |
|---|---|---|
| 1 | `action` | <导航到 X> |
| 2 | `action` | <在 Y 中输入 Z> |
| 3 | `action` | <点击 W> |
| 4 | `assertion` | <验证功能真的可用：描述可见结果 + 所在区域> |

> **断言质量门（硬要求）**：
> - 断言 MUST 验证功能**真的可用**，NEVER 只验证「元素存在」。
> - 反例：`src` 返回 404 的图片，`img` 元素依然存在；丢了 CSS 的卡片，文字依然可见。
> - 布局敏感项 MUST 断言**几何关系**（并排 / 网格 / 上下层级 / 卡片边界）。
> - 断言 MUST 明确**可见结果 + 所在区域**，例如「提交后进入 Secure Area，页面顶部显示绿色成功提示」。
>   反例：`确认页面正常`（无可判定标准）。

**不适用声明**（命中引擎官方排除路径时 MUST 填写）：

| 排除项 | 是否命中 | 说明 |
|---|---|---|
| 第三方 OAuth / SSO / 2FA | 是 / 否 | |
| 原生文件对话框 | 是 / 否 | |
| iframe 内交互 | 是 / 否 | |
| 多标签页跨上下文 | 是 / 否 | |

## 三、依赖关系（存在数据依赖时填写）

| 用例 | 角色 | 产出 / 消费 |
|---|---|---|
| C01 | `producer` | 产出 `<凭证 / 数据>` |
| C02 | `consumer` | 消费 `<凭证 / 数据>` |
| C03 | `cleanup` | 清理 `<数据>` |

> 有依赖时执行顺序由引擎调度，**NEVER 硬编码顺序**。失败归因时先查**最早失败的生产者**。

## 四、契约变更记录（B 类归因时填写）

> **硬规则**：契约变更 MUST 单独标记，**NEVER 混入「产品修复」计数** ——
> 否则轮次上限会被契约调整稀释成无限。

| 轮次 | 变更内容 | 归因 | 依据（为什么是契约错而非产品错） |
|---|---|---|---|
| <n> | <把断言从 X 改为 Y> | B | <回查 requirements.md 的证据> |

> 同一用例的契约变更 ≥2 次 ⇒ 视为**契约设计缺陷**，MUST 升级人审，NEVER 继续调。
