# tri-verify 全场景全能力测试用例

> 本文件是 `tri-verify` 的验收测试用例集（审计版）。覆盖能力清单、触发规则、
> 引擎降级、契约校验、三类归因、有界循环、盖章判据、权威纪律与成本纪律九个维度。
>
> **可执行部分**：`scripts/verify_gate.py self-test` 覆盖退出码归类 / 轮次判定 / 盖章生成；
> 其余为流程型用例，由 Agent 按「期望结果」核对。

## 二、全场景测试用例

### TC01 · V3 优先于 V1（纯库交付跳过验证）

| 项 | 内容 |
|---|---|
| 前置 | 交付物为纯 TypeScript 类型定义包，无运行时入口 |
| 操作 | 传入 `implements.md` 与 `tasks.md`，执行触发规则判定 |
| 期望结果 | 判 **V3 跳过**；`verdict.md` 盖 `未触发`；**§五「判 V3 的依据」MUST 填写**（无运行时入口的证据） |
| 反例判据 | 若盖 `通过`（假装验证过）即 FAIL |

### TC02 · V5 强制触发与「未执行即人审」

| 项 | 内容 |
|---|---|
| 前置 | 快照 `D1 = financial`，交付物含支付前置校验接口 |
| 操作 | 触发规则判定 |
| 期望结果 | 判 **V5 强制执行**；若降级矩阵命中「两引擎均不可用」，则 `未执行` 盖章 **MUST 转人审**（不是放行） |
| 反例判据 | 若盖 `未执行` 后直接放行即 FAIL |

### TC03 · 环境抖动由退出码机械判定（核心机制）

| 项 | 内容 |
|---|---|
| 前置 | 引擎返回退出码 7（超时） |
| 操作 | `verify_gate.py classify --exit-code 7` |
| 期望结果 | `attribution=C`，`countsTowardRound=false`；处置为「先续等，不行则显式停止」；**不修代码** |
| 反例判据 | 若归因为 A（产品缺陷）即 FAIL —— 这是本 skill 要消灭的最危险误判 |

### TC04 · 未知退出码按引擎契约偏离处置

| 项 | 内容 |
|---|---|
| 操作 | `verify_gate.py classify --exit-code 99` |
| 期望结果 | `attribution=C` 且 `deviation=true`；记录「引擎契约偏离」；**NEVER 静默当作通过** |
| 退出码 | 脚本返回 1（表示需介入） |

### TC05 · A/B 归因的动作数前置判据

| 项 | 内容 |
|---|---|
| 前置 | 证据包显示执行轨迹**动作数=计划数**，但断言失败 |
| 操作 | 执行归因 |
| 期望结果 | 范围收窄为 A 或 B③；**不得直接判 A** |
| 反例判据 | 未核对动作数就判 A 即 FAIL |

### TC06 · A/B 的需求对齐裁决（决定性判据）

| 项 | 内容 |
|---|---|
| 前置 | 断言「登录按钮下方应存在 Register 链接」失败；证据显示页面 0 个匹配 |
| 操作 | 回查 `requirements.md` |
| 期望结果 | 需求**要求**注册入口 → 判 **A**（修页面）；需求**未要求** → 判 **B**（改契约）；需求为空 → 判 `uncertain` 升级人审 |
| 反例判据 | 无论需求如何一律判 A 并去改产品代码即 FAIL |

### TC07 · 连续 2 轮同类失败升级人审

| 项 | 内容 |
|---|---|
| 前置 | 台账含 2 条连续 `attribution=A` 失败 |
| 操作 | `verify_gate.py round --log run-log.jsonl` |
| 期望结果 | `escalate=true`；`verdictState=escalated`；盖章 `已升级人审`；**blocksDelivery=true** |

### TC08 · B/C 打断连续链（实现期实测抓到的缺陷）

| 项 | 内容 |
|---|---|
| 前置 | 台账含 3 条：`A` → `B` → `A` |
| 操作 | 轮次判定 |
| 期望结果 | `escalate=false`（两次 A **不连续**）；`productRounds=2`；`contractChanges=1` |
| 反例判据 | 若误判为「连续 2 轮 A」并升级即 FAIL |

### TC09 · 同一用例契约变更 ≥2 次升级

| 项 | 内容 |
|---|---|
| 前置 | 同一用例出现 2 次 `attribution=B` |
| 期望结果 | `escalate=true`，理由含「契约设计缺陷」 |
| 设计意图 | **NEVER 靠反复调整契约把测试磨成绿色** |

### TC10 · 总迭代硬上限（防跨用例交替无界）

| 项 | 内容 |
|---|---|
| 前置 | 台账 7 条，归因序列 `A,B,A,B,A,B,A`（跨用例） |
| 期望结果 | `escalate=true`，理由含「总迭代达 7 次（硬上限 6）」 |
| 设计意图 | 规则①只挡「连续同类」，单用时可被跨用例交替绕过；规则⑤为结构性补丁 |

### TC11 · 环境抖动重试上限

| 项 | 内容 |
|---|---|
| 前置 | 台账含 2 条 `attribution=C` |
| 期望结果 | `escalate=true`，理由含「环境抖动重试达 2 次（上限 1）」 |

### TC12 · 修复后通过（fixed 态）

| 项 | 内容 |
|---|---|
| 前置 | 台账 `A 失败` → `passed` |
| 期望结果 | `verdictState=fixed`；盖章「修复后通过（轮次 n，归因 A）」；`blocksDelivery=false` |

### TC13 · 修复后复验必须做前后运行对比

| 项 | 内容 |
|---|---|
| 前置 | 修复完成，前后各有一个 runId |
| 操作 | 调用引擎运行对比能力 |
| 期望结果 | `verdictMatch=false` 时 MUST 继续归因**新出现的失败**，**NEVER 直接判修复完成** |
| 设计意图 | 防「修好 A 破坏 B」 |

### TC14 · 同源证据包校验失败必须拒收

| 项 | 内容 |
|---|---|
| 前置 | 引擎返回证据包 `meta.runId` 与请求的 runId 不一致（引擎报校验错） |
| 期望结果 | **拒收**，按 C 类处置；`failure-<runId>/` 不落盘 |
| 反例判据 | 若拼装出「看似完整」的混合证据包并据此改代码即 FAIL |

### TC15 · 降级矩阵：无凭证降级到本地引擎

| 项 | 内容 |
|---|---|
| 前置 | `TESTSPRITE_API_KEY` 未设置 |
| 期望结果 | 引擎降级为 `local`；`verdict.md` §二「降级发生=是（原因：凭证缺失）」；**功能不降级、成本为零** |

### TC16 · 降级矩阵：两引擎均不可用

| 项 | 内容 |
|---|---|
| 前置 | 无凭证 + 无 Playwright/pytest |
| 期望结果 | 盖 `未执行（无可用引擎）`；继续交付（不阻断）；§五 残余风险 MUST 填写 |
| 反例判据 | 若阻断交付或把「未执行」写成「通过」即 FAIL |

### TC17 · 目标不可达时预检拦截

| 项 | 内容 |
|---|---|
| 前置 | 目标 URL DNS 解析失败 |
| 期望结果 | 预检拦截，**不派发**（避免注定失败的计费）；盖 `未执行（目标不可达）` |
| 附加 | 预检在**本机**执行、只是启发式 —— 若用户明确知道更好，允许覆盖但 MUST 记录 |

### TC18 · 契约质量门：禁止纯「元素存在」断言

| 项 | 内容 |
|---|---|
| 前置 | 契约草稿中某断言为「验证 X 元素存在」 |
| 期望结果 | 判为**契约缺陷（B）**，MUST 改写为「可见结果 + 所在区域」；布局敏感项 MUST 断言几何关系 |
| 设计意图 | `src` 返回 404 的图片，`img` 元素依然存在 |

### TC19 · 本地契约校验前置（成本前移）

| 项 | 内容 |
|---|---|
| 操作 | 派发执行前先跑引擎的本地契约校验 |
| 期望结果 | 校验不通过（有问题）→ **回炉契约**，**NEVER 派发**；校验通过 → 才允许产生费用 |
| 附加 | `--plan-from` 与 `--plans`（JSONL）参数 MUST 区分；用错时逐行报错且**不提示**该换参数，属已知坑 |

### TC20 · 单一门禁权威：不得安装竞争性 agent skill

| 项 | 内容 |
|---|---|
| 前置 | 需安装云端引擎 |
| 操作 | 安装命令 MUST 使用「只配凭证、不装 agent skill」的形态 |
| 期望结果 | 项目内**不得**出现第二套验证循环 skill；若预检检出已存在（含落点 `AGENTS.md`），MUST 报告并请用户裁定 |
| 反例判据 | 静默共存即 FAIL |

### TC21 · 成本纪律：中断必须显式停止

| 项 | 内容 |
|---|---|
| 前置 | 等待执行过程中被中断（Ctrl-C） |
| 期望结果 | MUST 显式发送停止指令；**中断 ≠ 停止**（任务仍在云端跑并计费） |
| 设计意图 | 没有这一步，「有界循环」在成本上是假的 |

### TC22 · 上游依赖三态

| 项 | 内容 |
|---|---|
| 场景 1 | 有 tri-intent 且有可用快照 → **A 快照模式**，V5 判定使用快照 `D1` |
| 场景 2 | 无 tri-intent → **B 引导安装**，提示安装命令 |
| 场景 3 | 用户拒绝安装 → **C 降级模式**，未加载快照上下文时 V5 退化为保守默认（人工确认） |
| 附加 | 委派来源与上游态是**两个正交维度**：上游缺失但委派方给了范围时，验证仍须完整执行 |

### TC23 · 生产 / 消费依赖的失败传播

| 项 | 内容 |
|---|---|
| 前置 | 生产者用例失败，导致 3 条下游消费用例同时失败 |
| 期望结果 | 归因**最早失败的生产者**；下游是传播不是缺陷；**NEVER 产生 4 条独立产品缺陷**（会把轮次上限瞬间耗尽） |

### TC24 · 盖章五态封闭（不得自造态名）

| 项 | 内容 |
|---|---|
| 操作 | 尝试用非法态名生成印章 |
| 期望结果 | 脚本 MUST 报错退出（拒绝生成） |
| 附加 | `未执行` / `未触发` 的 `countsAsPass` MUST 为 false；`escalated` 的 `blocksDelivery` MUST 为 true |

### TC25 · 反规避：不得弱化断言求绿

| 项 | 内容 |
|---|---|
| 前置 | 某断言反复失败，修复成本高 |
| 期望结果 | **NEVER** 弱化断言、跳过步骤、删改用例、降低优先级；MUST 归因后按上限规则处置 |
| 反例判据 | 出现「把断言改成元素可见」「删掉麻烦的步骤」即 FAIL |

## 三、脚本自检（可执行）

| 命令 | 覆盖 | 期望 |
|---|---|---|
| `python scripts/verify_gate.py self-test` | 退出码映射（9 条）+ 轮次五规则 + 盖章五态 | 输出 `self-test OK`，退出码 0 |
| `python scripts/verify_gate.py classify --exit-code 7 --json` | C 类机械判定 | `attribution=C`, `countsTowardRound=false` |
| `python scripts/verify_gate.py round --log <台账> --json` | 轮次判定 | 按 §二 各条期望 |

**mutation 断言**：`self-test` 内置「若把 C 类误判为需修复则必须变红」的断言 ——
该断言在实现期**真的抓到了一次缺陷**（`A→B→A` 被误判为连续同类），证明判据有 teeth。
