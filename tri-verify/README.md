# 验证执行（tri-verify）

> 横向验证型 skill。补上 tri-xxx 家族唯一缺失的一环：**没有任何环节真的驱动运行中的应用**。

## 这是什么

写完了 ≠ 能用。

三层测试证明局部逻辑、静态审查证明代码质量、事实核查证明结论没编造 —— 但**只有真的把应用打开、
按用户路径点一遍**，才能回答那个最难的问题：*这次修改真的没有破坏原来的功能吗？*

`tri-verify` 就是这一环：把交付物跑起来 → 按行为契约驱动用户路径 → 取同源失败证据 →
失败时驱动「三类归因 → 修复 → 复验」的有界循环，直到功能真正可用，或明确升级人审。

## 特征

| 特征 | 说明 |
|---|---|
| **确定性触发** | 触发规则 V1–V5 逐条判定，结果只有「执行 / 跳过 / 强制」——不靠 Agent 自由裁量 |
| **三类归因前置** | 产品缺陷 / 契约缺陷 / 环境抖动。**改任何代码之前 MUST 先归因** |
| **C 类由退出码机械判定** | `{3,6,7,10,11}` 一律归环境抖动且**不修代码**，从机制上排除「环境问题被误判成产品缺陷 → 自动修复制造缺陷」 |
| **有界循环** | 连续 2 轮同类失败即停并升级人审。**NEVER 为让测试变绿而弱化断言** |
| **引擎可插拔** | 默认本地引擎（Playwright/pytest，零外部依赖、可离线、零成本）；可选云端引擎（TestSprite CLI，语义定位 + 同源失败证据包） |
| **降级不阻断** | 引擎不可用 / 目标不可达 / 无凭证 → 显式盖章「未执行（原因）」后继续交付，但 NEVER 把「未执行」说成「通过」 |
| **单一门禁权威** | 门禁判据不外包。安装云端引擎时只配凭证，**不装它自带的验证 skill**（否则会与 `tri-init` 争抢 `AGENTS.md`） |

## 安装

本 skill 随 tri-stack 仓库分发（junction 安装，单源不复制）：

```bash
python ops/install-skills.py --target <目标目录>
```

安装后 MUST 重放补丁层（内容修正与安装是两件事）：

```bash
python ops/patches/apply.py
```

## 用法

### 由上游自动委派（推荐）

| 委派方 | 时机 | 验证范围 |
|---|---|---|
| `tri-coding` | `implements.md` 产出后、交付前 | 冒烟层（≤5 条高价值用户路径） |
| `tri-fix` | 修复完成后 | 定点复验 + 修复前后运行对比（防「修好 A 破坏 B」） |
| `tri-sdlc` | P6 / P7 阶段 | 按阶段给定范围 |

### 用户直接调用

```
帮我验证一下这次改动是不是真的能用
```

无 tri-intent 快照时走降级模式（未加载快照上下文），验证仍可完整执行。

### 启用云端引擎（可选）

```bash
# 只配凭证，不装它自带的 agent skill（单一门禁权威纪律）
testsprite setup --api-key <KEY> --no-agent
```

未配置 `TESTSPRITE_API_KEY` 时自动使用本地引擎，**功能不降级、成本为零**。

## 落盘产物

```
.tribro/verify/<命名>/
├── contract.md         验证契约（行为陈述 + 步骤 + 断言）
├── run-log.jsonl       每轮运行台账（轮次 / 引擎 / 归因 / 退出码）
├── failure-<runId>/    失败证据包（原样归档，仅校验同源）
├── escalation.md       升级人审说明（仅触发时）
└── verdict.md          判据印章（四态封闭判据）
```

`verdict.md` 的四态：`通过` / `修复后通过` / `已升级人审` / `未执行（原因）`（另有 `未触发`）。
**「未执行」与「未触发」MUST NOT 被调用方当作「通过」消费。**

## 与相邻 skill 的分工

| skill | 层次 | 核心动作 |
|---|---|---|
| `tri-review` | 静态 | 读码审查，不执行 |
| `tri-test` | 计划层（SDLC P6） | 编计划 / 映射验收标准 / 缺陷台账 |
| **`tri-verify`** | **执行引擎层（横向）** | **驱动运行中的应用，取同源证据，驱动有界修复循环** |
| `tri-true` | 事实层 | 核查断言真假（本 skill 的证据包可作其 T1 信源） |

`tri-test` 与本 skill 是**依赖而非竞争**：前者出计划，后者出执行证据。

## 设计原则

1. **确定性优先**：能机械判定的（退出码、字段存在性、轨迹步数比对）绝不交给语义判断。
2. **成本前移**：契约本地校验（零成本）→ 可达性预检（零成本）→ 才派发计费执行。
3. **失败面向 Agent 组织**：证据包必须同源、可判定；异源包拒收。
4. **机制管理不确定性**：不承诺 AI 永远正确，而是认真设计「AI 判断错误时系统该怎么办」——
   轮次上限、归因前置、降级不阻断、盖章四态，都是这一原则的产物。
5. **门禁规则本身仍需人负责**：自动验证可以成为门禁，但 `已升级人审` 这一态 MUST 真的停下来等人。
