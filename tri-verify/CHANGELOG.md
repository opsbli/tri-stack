## [1.0.0] - 2026-09-25

### 新增

- **首版发布**：横向验证型 skill——为 tri-xxx 家族补齐「驱动运行中应用的真实功能验证」能力
- **触发规则 V1–V5**：确定性判定表（含可运行入口 / AT 清单存在 / 纯库跳过 / 用户显式要求 / 高风险与 YMYL 强制），结果只有执行-跳过-强制三种
- **三类归因**：产品缺陷（A）/ 契约缺陷（B）/ 环境抖动（C）；**改任何代码之前 MUST 先归因**；只有 A 类计入修复轮次
- **C 类机械判据**：失败归因的 C 类由引擎**退出码**判定（`{3,6,7,10,11}` 归 C 且不修代码；`{4,5}` 归 B），无需语义判断
- **有界循环**：连续 2 轮同类失败即停止并升级人审；契约变更单独标记、不消耗轮次；契约类同用例 ≥2 次视为契约设计缺陷并升级
- **复验机制**：修复前后取运行 id 做引擎级对比，机械判定有无回归（含代码版本漂移检测）
- **引擎抽象**：七方法契约（可达性预检 / 创建 / 执行 / 快速分流 / 取失败证据 / 运行对比 / 停止）
- **引擎可插拔**：默认本地引擎（Playwright/pytest，零依赖、可离线、零成本）；可选云端引擎（TestSprite CLI）
- **降级矩阵**：无凭证 / 无效凭证 / 额度不足 / 缺本地依赖 / 两引擎均不可用 / 目标不可达 / 官方排除路径，逐条处置且 NEVER 阻断交付
- **单一门禁权威纪律**：安装云端引擎 MUST 只配凭证不装其自带 agent skill；预检探测竞争性 skill 并报告落点冲突
- **成本前移链**：本地契约校验（零成本）→ 可达性预检（零成本）→ 才派发计费执行；中断时 MUST 显式停止避免持续计费
- **判据印章四态**：通过 / 修复后通过 / 已升级人审 / 未执行（另含未触发），MUST NOT 混同
- **可执行实现**：`scripts/verify_gate.py`（退出码归类 / 轮次判定 / 盖章生成的确定性判定）
- 上游依赖检测三态（快照模式 / 引导安装 / 降级模式）
- 版本门节采用家族 `version-stub v1` 瘦指针形态

### 设计边界

- **不改交付物**：只出验证结论；需修复时回炉 `tri-coding` / `tri-fix`
- **不做计划层**：测试计划、覆盖率映射、缺陷台账归 `tri-test`
- **不注册 downstream**：横向型，不认领 tri-intent 路由表落点，由委派或显式调用激活
- **不实现同源校验**：证据包一致性由引擎自身保证，本 skill 只做拒收判定
